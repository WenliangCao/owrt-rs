# 个人设备 Rust 核心控制面开发计划

日期：2026-09-06。状态：待执行。顺序：ubusd → netifd → procd。

## 1. 项目目标与本轮边界

这是用户个人的极客项目，只有一位用户、一台 AX3000T，不是待发布的路由器产品。
目标是在这台设备上实际用 Rust 接管三个核心 daemon，获得理解、修改和优化系统的自由。
不以支持其他机型、任意 OpenWrt 包、企业功能或购买第二台设备为前提。
功能先兼容，随后按实测优化；更快不是语言保证，也不要求每项微基准都胜出才允许接管。

本轮重写 ubusd、netifd 和 procd 的本机必要职责。保留 Linux 内核、驱动、nftables 执行面、
hostapd/wpad、dnsmasq、odhcpd/odhcp6c，以及现有协议 helper、启动 shell 和成熟执行工具。
netifd 调用保留的协议 helper、procd 调用保留的 ujail 等工具，不等于未完成 daemon 替换。
但不能留下原版 netifd/procd 在后台代做核心状态管理，再宣称已替换。

procd 本轮终点是正常启动后的 PID 1 由 Rust 实现承担；原 `/sbin/init` early-init、
preinit 和独立升级/隔离工具可以保留，必须列明边界，不声称 procd 整个源码仓库全部 Rust 化。

用户本次要求的是开发计划。本轮计划编写不连接或修改路由器。
将本计划交给执行者后，可以先完成源码核查、代码、离线验证、打包和切换方案。
真实设备的安装、接管、网络重启、重启等变更，遵守 AGENTS.md：需要对应的明确用户请求和
经验证的恢复路径。已有授权按原范围沿用，不逐条命令反复询问；没有授权时，先把可执行产物和
具体操作窗口准备完整，再一次说明将做什么、会中断什么及如何恢复。
不把历史的一次重启授权解释成任意未来重启或刷机授权。

工程约束：

- 每个 daemon 独立 crate：`components/ubusd`、`components/netifd`、`components/procd`。
- 复用 ubus/uci；netlink 写侧按需求增加。不要因为这轮开发重构全仓库或新建通用框架。
- 根 Makefile 当前明确采用独立 crate，不强制改成 Cargo workspace。
- 单事件循环、显式状态、清楚的资源所有权优先；不预设异步运行时、插件系统或数据库。
- 默认复刻本机所需的接口与状态语义，不顺手改成自创配置协议。
- 配置里暂时没出现，不代表本机不需要：包含启动、重连、LuCI 操作、脚本调用和失败恢复可达路径。
- 无需覆盖未使用协议，但遇到不支持的配置应明确报错，不能静默忽略或先拆掉正在工作的网络。
- 候选已知的安全缺陷不机械复刻；任何有意行为差异单独记录并验证调用方影响。
- 原始配置、报文、镜像和源码副本仍留在 Git 外；报告只保留脱敏结果。

## 4. P1：ubusd-rs

### P1.1 协议合同与实现

阅读精确 ubusd/libubus 源码和补丁，按依赖实现：

1. Unix socket、握手、client/object/type ID、报文拆装、长度/对齐校验、部分读写。
2. 对象注册/移除/查找，方法调用转发，返回状态、序号、异步回复和断连后的在途请求清理。
3. 订阅、通知、事件、客户端离开后的对象与订阅回收；本机需要的 monitor 行为。
4. `SCM_RIGHTS` FD 生命周期和转发、socket peer 凭据、ACL 加载/更新与非 root 授权。
5. 慢读客户端、发送队列限制、恶意长度与截断消息处理；限制若偏离原版，说明差异。

可复用 `components/ubus` 的编解码，不把仅适用于客户端的信任假设直接搬进 daemon。
优先保持公共库 API 稳定；修改共享库时回归当前 logd/rpcd/httpd 使用路径。

### P1.2 离线验证

建立同一组客户端分别访问 C/Rust daemon 的差分 harness；两边用独立 socket、目录和同样的 ACL 所有权。
使用原版 libubus/CLI 客户端与本项目 Rust 客户端交叉测试，不能只让候选客户端验证候选服务端。

覆盖 lookup/invoke、对象增删、通知/事件、FD 传递、非 root allow/deny、请求中断、重连重注册、
慢客户端和畸形报文。动态 ID 可做一致映射，但不能把错误路由、消息遗漏或因果顺序差异归一化掉。
重跑并扩展 `tools/r22_ubus_clients_reconnect.sh`：区别“原版已有缺陷”和“候选新增缺陷”。
不要求候选自动修复 odhcpd；必须给出这类客户端需要重启的准确名单和顺序。

基准：相同客户端/消息/权限下，lookup、invoke、事件投递、并发客户端与慢客户端干扰；
记录延迟、CPU、RSS、FD/队列是否增长，不预设加速倍数。

### P1.3 打包与实际接管

新增 `packaging/openwrt/owrt-ubusd`，安装默认不抢占原总线；包升级也不隐式杀总线。
候选必须先以替代 socket 跑通；这只能算隔离验证，不算系统接管。

正式切换前写出两条路径并选实际可恢复的一条：

- 在线受控切换：由原 procd 启动候选，并按已验证依赖顺序重启不能自行恢复的客户端。
  接受本窗口内网络/无线中断；控制脚本不能依赖正在被替换的 ubus 继续存活或回退。
- 启动时选择候选：按精确启动链在 `STATE_UBUS` 之前生效。
  普通 Sxx 脚本太晚，不能冒充启动接管。选择机制先在精确启动环境演练，失败可选择原版。

不预先强制修改 preinit，不承诺 bind mount 一定适用；根据精确源码和恢复路径确定最小改动。
保留 C ubusd，切回时同样恢复全部客户端。自动回退计时器若采用，须独立于 ubus/网络/SSH 会话，
并先证明退出会话后仍能执行；计时器不等于早期启动失败救援。

完成标准：实际系统总线由 Rust 提供，原 C ubusd 不运行；现有六个 Rust 组件和保留 daemon
均能完成必要调用；切回验证通过；至少一次真实启动后重新确认接管和对象恢复。
启动验证未执行时只能标记“在线接管完成”，不能标记阶段全部完成。

## 5. P2：netifd-rs

开始条件：P1 已完成本机验证。开发和上线时保持原 procd 不变。

### P2.1 设备与接口状态机

按实际拓扑实现设备、接口、协议三部分，状态与依赖关系显式表达：

- UCI 读取/校验，设备发现、link/carrier、bridge/VLAN 和接口依赖。
- 本机使用的地址、路由、规则、MTU/MAC 等配置；netlink ACK、dump、中途错误和事件处理。
- `network`、`network.device`、`network.interface.*` 的必要 ubus 方法、状态和事件。
- ifup/ifdown/reload 与配置变更，不重复创建资源，不误删其他进程拥有的资源。

先在 namespace 验证，再扩展协议 handler。保留现有 DHCP/IPv6/PPPoE 等实际需要的 helper，
复刻 proto-shell 协议、notify_proto、更新/失败/超时和退出语义，不同时重写这些客户端。
实际使用的 IPv6 PD、地址生命周期、DNS 更新和 WAN 重连不能推给“以后支持”。

### P2.2 无线编排与生命周期

重写属于 netifd 的无线设备/接口状态、脚本调用、异步 setup/teardown、重试与进程登记行为。
继续使用现有 wireless 脚本及 hostapd/wpad，不重写认证协议。
将 `network.wireless` 的注册/恢复、无线接口加入 bridge、radio 重载后的状态更新列为必测。
已有 rpcd 的只读 nl80211 代码不能替代这些写侧与生命周期职责。

### P2.3 差分与故障验证

C/Rust 分别在独立网络 namespace 上执行同样的配置与事件序列，比较最终拓扑、地址、路由、
规则、DNS 产物和有因果约束的事件；忽略 ifindex/时间戳等动态值，不忽略中间错误状态。

必测：启动、无变更 reload、合法变更、非法配置、WAN 失联/恢复、helper 退出、重复/乱序事件、
netlink 失败、接口删除重建、ubus 重连，以及本机实际使用的 IPv4/IPv6 路径。
先做几百轮离线事件循环检查资源增长；真实无线与本机网络故障不在未授权时模拟。

### P2.4 本机切换

新增包和独立开关，正常启动仍由 C procd 监管。任何时刻只允许一个 netifd 管理真实接口；
不能让 C/Rust 并排写同一个 bridge 或接口。“影子运行”必须真正没有网络写入/helper 副作用。

切换脚本先保存必要的原状态和切回方式，独立回退任务预先就绪，再停止 C、启动 Rust。
不能假设已有 SSH 连接会一直活着。恢复脚本须能直接启动原 netifd/所需 helper，不依赖候选的 ubus 方法。
地址或默认路由存在不算成功：检查有线管理、无线关联、LAN/WAN、DNS、DHCP、实际使用的 IPv6、
LuCI 网络页及防火墙联动；需要用户侧观测的无线/端到端项目明确标注。

完成标准：C netifd 停止，Rust 管理本机全部必要接口；切回、重新启用、一次真实重启验证通过。
之后以正常个人使用观察至少一个日常使用周期，建议 24 小时；无需自动持续占用 agent，
可用本地日志/计数和下一次汇总，未观察的时长不虚报。

## 6. P3：procd-rs

开始条件：P2 已完成本机验证。本阶段不再次改变 ubusd/netifd 的协议或网络策略。

### P3.1 服务监管

先完成可在隔离环境运行的监管核心：

- 本机 service/system ubus 接口、服务/实例配置更新和触发器。
- spawn/exec、环境、工作目录、uid/gid、limits、信号与子进程回收。
- respawn 限制/延迟、正常退出与崩溃区别、stop 超时、日志 FD。
- 实际声明的 jail/capability/seccomp 参数与现有 ujail 工具契约。
- 配置触发器与 reload_config、rc.common/procd.sh 的配合。

复用原 init 脚本声明作为输入；不新建服务描述语言。
在私有 PID/mount/net namespace 验证进程树、退出码、信号、僵尸回收和故障循环。
此阶段只证明监管核心，不能宣称 PID 1 已替换。

### P3.2 PID 1、启动与停止

依照精确源码实现正常 procd 的状态机、ubusd 早期启动、inittab、rcS、hotplug/coldplug、
watchdog 接管/喂狗、shutdown/reboot。列明与原 `/sbin/init` 交接的环境和继承 FD。
测试旧 init → Rust procd 的真正 exec 交接，特别检查 watchdog FD 继承、关闭及失败行为。

已知需要保留的语义：`/etc/init.d/rcS` 在镜像中不存在；它由 procd 内建 rcS 处理；
启动脚本按顺序串行执行，普通非零退出不阻断后续脚本。不要套用通用 init 的想象实现。
内存不足、exec 失败等原版缺陷若有意改进，记录小范围差异，不扩展成启动框架重设计。

隔离 PID 1 测试之外，能用虚拟机就补完整启动/关机演练；虚拟硬件与目标硬件差异明确记录。
不因没有第二台物理设备而停掉开发，也不把容器通过当作本机启动通过。

### P3.3 本机 PID 1 接管与恢复

只在启动边界选择 Rust PID 1。禁止用杀死/重启当前 PID 1 的普通服务方式切换。
保留原 `/sbin/init`、原 procd 和救援所需工具，选择器不依赖尚未启动的 ubus/netifd。
先验证切换位置：它必须早于原 init exec procd，并明确 overlay 挂载及 failsafe 分支的先后关系。

特别注意：旧救援报告“failsafe 不加载 overlay 改动”的结论，不能直接外推到替换 procd。
必须逐步追踪新的选择机制在 failsafe 下是否仍会误选 Rust PID 1；救援应进入原路径，且能撤销选择。
PID 1 崩溃/panic/挂死时普通回退脚本不一定能运行；自动回退不能作为唯一恢复保证。
若本机不刷机且现有恢复机制下找不到可验证的启动选择方案，完成其余离线工作，
明确指出具体技术缺口和最小新增操作，不擅自刷机、不要求先购买第二台机器。

包安装/升级不能自动启用新 PID 1。准备好下一次启动的选择和撤销操作后，再进入对应设备窗口。
核对 `/proc/1/exe`、构建身份、服务实例、watchdog、启动日志，以及 ubusd/netifd/现有六件的状态。
验证一次完整启动和后续正常重启路径；强制掉电/故障启动实验只在具体授权范围内执行。

完成标准：正常系统的 PID 1 为 Rust，原 procd 不代管服务；本机服务、网络和管理功能正常；
实际启动与正常重启通过，回到原版的路径得到验证。长期运行观察同 P2。

## 7. 验证、交付和执行节奏

每个 daemon 只维护一份合同、一份结果报告；机器数据直接由 harness 产出，别为同一状态再建多套门禁文档。
建议文件：`docs/contracts/{ubusd,netifd,procd}.md` 与目标 reports 目录内的对应报告。
打包遵循当前工具链与 SDK 配方，把新增 crate 接入根 Makefile 的必要检查。
每个可独立审阅的实现/修复做小提交，提交前确认没有原始设备资料或秘密。

检查随工作范围走：改哪个组件就跑其单测和差分；改共享 ubus 则回归使用者；
最终打包后二进制再跑关键差分，进入设备前做现有六件回归。不要无变化反复重跑全部检查。
性能只记录同负载、同功能、同配置的对照，显著回退先找根因；结果允许持平，不捏造优势。

阶段状态只用：开发中 / 离线通过 / 在线接管通过 / 启动验证通过 / 日常观察完成。
没有设备授权时继续可独立完成的开发、离线测试和打包，准备好一个具体设备窗口再交接；
尚未本机验证的前置阶段，不在本机叠加下一项候选。P1 → P2 → P3 的实际上线顺序保持不变。

最终验收清单：

- ubusd、netifd、正常运行 PID 1 都是本项目 Rust 实现，构建身份可核对。
- 当前个人配置与实际使用功能保留，现有六个 Rust 组件没有回归。
- 原版保留可恢复，清楚列出未重写的 helper、early-init 和不支持功能。
- 每项实机操作和观察有真实结果；无第二台设备要求，无企业测试矩阵，无虚假的“全 OpenWrt 兼容”。
