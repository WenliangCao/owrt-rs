## 2. P11 time-source coverage
All time-based sources (instance stop/respawn/watchdog deadlines, trigger debounce, rc/rcS queues and stop timeouts, inittab respawn, hotplug queue/button/coldplug, dispatch 50 ms cadence, hardware watchdog ping) are represented in `pending`/next_tick_ms but acted on only when poll() returns 0 (F1). Descriptor-driven sources (trigger/inittab/instance child exit via SIGCHLD self-pipe, rc job output, uevents, inotify IN_NONBLOCK, instance pipes, shutdown signals via wake_loop) wake `other` correctly. Read-only classification (service list/get_data/validate, system info/board) verified: none spawns or arms anything (no Command/fork in sysobj.rs). SubscribeState/Other return false correctly.

## 3. Hot-path overhead (service list)
1. wait_activity rebuilds the pollfd Vec and poll()s 2 + hotplug + inotify + 2×instances-with-pipes + rc fds per wake (kernel O(N) vs epoll O(ready)) — R/main.rs:483-505.
2. next_tick_ms scans every instance's two deadlines per wake (R/main.rs:454-457).
3. dump_list rebuilds the reply and reset_bounded(16 KiB) shrinks afterwards → realloc chain per request over 16 KiB (R/main.rs:1121-1124; R/service.rs:19-37).
4. Request storage recycled (spare_request), two frames per reply as in C.
5. On mutating wakes: pump_instance_logs format!("{arg0}[{pid}]") per instance before checking readability (R/main.rs:544-557); log_instance_line openlog/syslog/closelog per line (R/sys.rs:475-492).
Leaks: none on the steady path; the one unbounded growth is F2's hotplug.queue once child is stuck.
