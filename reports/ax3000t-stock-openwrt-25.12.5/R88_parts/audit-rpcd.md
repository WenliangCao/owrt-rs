## 2. Hot-path overhead
1. session access: one pass over fields, BTreeMap lookup + Instant::now touch, linear Vec<Acl> scan with literal/* fast path, 'static reply; no heap allocation on hit path. C: two AVL lookups + two fnmatch per candidate.
2. uci get: Context::new + savedir String per call (uciobj.rs:23-25,139-144); load_cached opens+flocks, reads ≤32 KiB, byte-compares with retained copy, clones Package on hit (uci/src/read_cache.rs:119-126); load_delta opens per-session delta (uci/src/file.rs:107-108). C re-parses every time. Device: -13% latency, -21% CPU uci_get_network.
3. Loop fixed cost per iteration (main.rs:346-354): delayed.reap() (waitpid WNOHANG per tracked pid), sessions.expire() hint compare, apply-deadline check, rx.try_recv(); up to 31 buffered frames per poll (main.rs:373-389, 406).
4. file list/stat/lstat skip the JSON tree (file.rs:118-136); IdentityNames caches uid/gid names per request (file.rs:250).
5. luci only: Ctx::ubus_call opens a fresh ubus connection per call (main.rs:60-69); getOdhcp6cStats does 1+N (luci.rs:958-966). Not core.
Leaks: none on core paths. timeout<=0 sessions never expire (same as C); uci-<sid> dirs purged on destroy/expire; worker threads end after Deferrer::finish; fds CLOEXEC; all children waited by exact pid. Residual same as C: file exec children in flight at HUP become unreaped children of the re-exec'd process.
