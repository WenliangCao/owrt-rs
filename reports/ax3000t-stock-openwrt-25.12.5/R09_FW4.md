# R09：firewall4 生成器 Rust 化（fw4-rs）

> 状态：offline_verified — 等待设备窗口授权
> 合同：C4（`docs/contracts/fw4.md`）；决策：0010

## 范围

把 `/sbin/fw4` 背后的 ucode 生成器（fw4.uc 3376 行 + 模板 800 行）逐函数移植为 Rust `fw4-rs`
（`components/fw4`，约 3900 行，零第三方 crate，复用 `components/ubus` 的 ubus 客户端与 JSON）。
子命令面与原实现一致：`start|reload|stop|flush|restart|check|print|reload-sets|network|device|zone`。

## 离线验证

| 项 | 结果 |
|---|---|
| 上游 firewall4 测试（31 个用例文件，stdout 与 stderr 逐字节比较，含 `[call]` 调用轨迹） | 31/31 通过（`tools/r09_fw4_check.py`） |
| 单元测试（IP 解析、ucode 语义、UCI 解析、选项解析、格式化） | 11/11 |
| 设备配置离线差分：2026-09-02 只读采集（`/etc/config/firewall`、helpers、`network.interface dump`、`service get_data`、`network.device status`、`/proc/version`、`/sys/class/net/*/flags`、`nft --json list flowtables`）→ `fw4-rs print` 对比设备 `fw4 print` | 逐字节相同（203 行，含 `delete flowtable inet fw4 ft`） |
| 参考运行器：ucode 在 oracle 上从源码构建，原实现跑上游测试 | 31/31（确认 oracle 与用例期望一致） |

移植期间用 ucode 实测过的语义并写进代码：模板空白规则（`{%` 前的空格/制表符、`%}` 后的单个换行被吃掉；
`{%+`/`-%}` 例外）、宽松 `==`、字符串到数字的转换、`{{ null }}` 输出空而 `${null}` 输出 `null`、
glibc 风格的 IPv6 文本化、json-c 的宽松 JSON（尾逗号）。

## 设备步骤（待授权）

`tools/r09_go_live_device.sh`：`install` → `gate` → `enable`（含 `fw4 -q reload` 经候选重载一次，
比较去掉计数器后的 `nft list ruleset` 哈希）→ `probe`（约 3 分钟）。退路：`disable`（一步回到原脚本）、
`rollback`（卸包 + 原实现 reload）。
