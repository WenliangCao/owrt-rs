# R71：P3.2 —— procd-rs 作为 PID 1 在隔离命名空间内完整启动与关机

日期：2026-09-08。候选 `e05091991aa6716e1f0f865aea37b85e`
（oracle:/home/ubuntu/rv-procd，构建于运行前）。探针
[tools/r71_pid1_probe.sh](../../tools/r71_pid1_probe.sh)，产物
oracle:/tmp/rv/pid1d（rs 侧终版）、/tmp/rv/pid1（双侧首版）。
**没有碰物理路由器。**

## 方法

发货 rootfs 复制一份，`unshare --mount --net --pid --fork --kill-child` 里
`exec chroot <root> /sbin/procd-rs` —— 候选是命名空间的**真 PID 1**
（`/proc/1/exe` 实测）。驱动脚本由 inittab 的一条 `respawn` 项从内部启动。
合成 fixture：三个 S 脚本 + 一个 K 脚本的 rc.d、带四种条目的 inittab、
`container=1`（`is_container()`，关机走 `reboot(2)`+exit，在 pid ns 里
结束命名空间而不是宿主）。

## 结果（rs 侧，全部通过）

| 断言 | 结果 |
|---|---|
| 状态机 | `- early -` → `- ubus -` → `- init -` → `- init complete -` 顺序出现 |
| 早期 ubus 服务 | `service list` = `{"ubus":{"instances":{"instance1":{running, pid, command:["/sbin/ubusd"], respawn:{3600,1,0}, user/group "ubus"}}}}`，与 C `service_start_early` 逐字段一致 |
| rc.d 串行 | `S10first→S20second→S30third`，每个 start/end 严格不交错，参数 `boot`，glob 序 |
| respawn（id=null，/dev/null 存在） | 杀掉后 500 ms 内以新 pid 回来（resp 1→2，第 4 条 launched） |
| respawn（id 为空） | 恰好运行一次；被杀后**不**复活（`dev_exist("")`=ENOENT 语义） |
| `system reboot` | STATE_SHUTDOWN：`K90bye shutdown` 运行 → SIGTERM/SIGKILL 清场 → `- reboot -` → 命名空间结束（父侧看到 SIGHUP，reboot(2) 在 pid ns 的语义） |

r65 监管模式回归（/tmp/rv/r65-v9）：同一二进制 `r65: ok`，diff 0，
42 pid 行 / 236 用例标记 / 13 预期失败，与 v8 基线一致——PID 1 路径在
`getpid() != 1` 时完全惰性。

## C 侧对照的边界

发货 `/sbin/procd` 作为同样命名空间的 PID 1 **停在 STATE_EARLY**（150 s 无
输出、无 rc.d 执行；早期日志走 /dev/kmsg 所以 stderr 为空）。机制：
`state.c` 的 EARLY→UBUS 前进由 coldplug 的 udevtrigger 完成回调驱动，
命名空间里没有那套设备事件链。所以 rc 串行性、respawn、关机语义的
"C 行为"依据是源码（rcS.c/inittab.c/state.c，均已在 rcs.rs/inittab.rs
的单测与注释里逐条对应）+ 本探针对候选的验证，而不是同一 fixture 下的
双侧字节对比。设备上的真对照属于 P3.3 的启动窗口。

## 探针自身踩过的三个坑（都会做出假绿/假红）

1. inittab 的 process 字段按空格切分（C `strtok` 同样），`sh -c echo x >> f`
   退化成跑 `echo`——两侧对称地什么都不测。改为 wrapper 脚本。
2. 这份 busybox 没有 `pkill`，`pkill ... || true` 静默无操作，"杀掉后复活"
   一步从未执行。改为 ps+grep+kill 并打印被杀 pid。
3. `timeout` 默认发 SIGTERM，而 ns 里的 PID 1 装了自己的关机 handler，
   卡死的 C 收 TERM 不退出——外层挂一小时。`timeout -s KILL`。

## 已知仍缺（P3.2 余量）

hotplug(/etc/hotplug.json) 与 coldplug（含 udevtrigger 链）、watchdog 的
WDIOC ioctl 面（现在只有 open+5 s 喂狗）、`askfirst`/`askconsole` 在有真
tty 的环境下的行为（探针 /dev 里没有 tty 节点，跳过路径已验，交互路径未验）。
