## P3.3：离线部分全部完成，剩设备窗口

R67 的结论不变：交接点唯一（`initd/preinit.c:114` execvp 写死
"/sbin/procd"），无环境变量选择器，preinit 退出码不被检查。据此：

**切换机制 = 替换 /sbin/procd 本体**，`tools/p33_switch.sh`（stage/undo/status）：
- 运行系统上替换安全：boot 链只在启动时 exec 该路径，运行中的 procd 持旧 inode；
- 改动只落 overlay：failsafe（mesh 按钮 + lan4，不挂 overlay）启动的是原封
  /rom/sbin/procd——这就是"救援进入原路径"的验证依据（R67 实验 + overlay 机制）；
- undo = `mv /sbin/procd.c-orig /sbin/procd`，一条命令，无需网络。

**候选已具备 boot 链用到的全部模式**：PID 1（R71/R72 探针）、
`-h /etc/hotplug-preinit.json`（r72a 差分）、WDTFD 交接（watchdog.rs，
未在无 /dev/watchdog 的 ns 里可测）、监管模式（r65 v13）。

**设备窗口清单**（进入前逐条打勾；窗口本身需明确授权，本会话不执行）：
1. `p33_switch.sh status` 记录基线；scp 候选（md5 对 CI 产物）；
2. `p33_switch.sh stage <bin>`；
3. 正常重启一次 → 核 `/proc/1/exe`、`ubus call system board`、
   `service list`（六个 Rust 组件 + dnsmasq/odhcpd 实例齐全）、
   watchdog 在喂（`ubus call system watchdog`）、logread 无 procd 报错；
4. 再正常重启一次（重复性）；~3 分钟观察窗（按既定监控约定）；
5. 回退演练：`p33_switch.sh undo` + 重启 → `/proc/1/exe` 回到原 procd；
6. 任一步失败：failsafe 进 /rom，undo，写报告。

**明确缺口（计划要求写明的）**：本机启动验证只能在设备窗口做；ns 里
C procd 无法作为 PID 1 启动（EARLY 卡 coldplug，R71），故 PID 1 行为的
"C 对照"依据是源码逐条对应 + 候选探针，不是同 fixture 双侧对比。
