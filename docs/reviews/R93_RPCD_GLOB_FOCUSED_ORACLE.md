## 结论

- `session_access_granted` CPU 四轮均降低 3.59–5.56%，平均延迟均降低 0.66–1.45%；control ticks [196,198,196,195]，候选 [188,187,186,188]。
- `session_access_granted_c4` CPU 四轮均降低 4.80–8.70%，平均延迟均降低 0.45–8.70%。
- `session_access_64` 串行 CPU 四轮均降低 4.39–6.31%；平均延迟三轮较低、一轮 +0.29%。
- `session_access_64_c4` CPU 和延迟都为三轮较低、一轮较高；该轮分别 +1.74% / +7.28%。拒绝路径方向也混合，不能宣称全面提速。
- 与 R89 比较：granted/64 串行候选 CPU 中位数仍为 9.375/9.750，对 R89 9.250/9.525；granted c4 相同，64 c4 候选稍高。各项都低于 C 的 CPU 中位数，但没有全面赢 R89。
- 全部 96 个焦点区间为 97–219 ticks；只有 R89 denied c4 第一轮的 97 ticks 未达到预设 100 tick 目标，保留样本、不自适应补跑。相较前轮，授权 CPU 下降已不只是 1–3 tick 差，但仍不作统计显著性或完整归因声明。
