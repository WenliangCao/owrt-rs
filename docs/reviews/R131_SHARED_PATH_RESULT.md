# R131 共享路径补测：未通过

R131 的事件收益仍然成立，但它在这一轮完整路由器对照中拉长了注册尾延迟。
18 个窗口全部有效；按事先冻结的规则，两个注册场景的 p95 均未通过。
不能把 R131 标为已经完成验收的最终版本。

独立复核直接使用每窗 5000 条原始 latency_ns 和进程 CPU 时钟，重算全部
6 个场景、6 项指标及两组对照，结果与收集器一致。每窗身份、CPU 绑定、
生产 C、清理及原始归档检查均通过，没有足以宣布该轮数据无效的证据。
完整派生值及输入指纹见 [JSON](r131-shared-path-results.json)。

R131 的 05、13 窗有明显峰值，之后又下降，不像简单的单调升温漂移。
13 窗 register_1_8 的 daemon 非自愿上下文切换为 259 次，其他 R131 窗为
12–63 次，R124 为 6–18 次。这支持“该窗受到额外调度干扰”的判断，但没有
指出干扰源，也不足以证明所有差异都是噪声。六个块中 R131 先跑和后跑的
情况都存在，p95 上升方向没有因先后顺序翻转。

窗口前温度约 59.8–60.6°C，注册后约 60.2–60.9°C。该 workload 没记录逐时
CPU 频率，也没抓按符号 profile；不能断言具体哪条指令或调度机制造成退步。
所有窗口保留，不剔除 05/13，不重跑，不改变门槛。

## 计量边界与其他路径

调用者每次从 `add_object` 前开始计时，到 `remove_object` 成功返回结束。
其中包含 caller 编解码、IPC、daemon 和调度等待；p95 是端到端注册周期，
不是 daemon 单独处理时间。daemon CPU 另用其进程 CPU 时钟测量。
20 次预热、签名预检及最后空对象检查均在计量区间外。三版本使用同一
benchmark ELF，daemon CPU1、caller/provider CPU0、相同 argv0。
独立重算使用零基索引 `floor((4999 × q) + 0.5)`；p95 为第 4749 项。

R131 的事件发送准备逻辑也会被 ADD/REMOVE 的对象事件调用；没有事件监听者
并不等于完全没有经过改动代码。不过当前证据只能支持这一场景的回退判断，
尚不能把它归因给批量发送 syscall、结构布局或某个分支。

四个 lookup/invoke 护栏没有触发退步门槛。相对 R124，mean 的配对中位数为
exact +0.21%、all +1.09%、prefix +1.08%、invoke −0.07%；daemon CPU 为
+1.75%、+2.92%、+2.81%、+0.04%。

本轮相对 C：R131 注册 1_8 mean +4.74%、p95 +69.93%、CPU +6.26%；注册
16_8 mean +3.82%、p95 +46.75%、CPU +11.03%。lookup/invoke 仍优于 C。
这些是本轮、同一仪器的结果，不与历史其他调用者的 CPU 数字混合。

**结论：R131 共享路径补测未通过。保留事件收益，同时保留注册尾延迟缺陷；
本报告不授权部署、不宣布整个 ubusd 完成。**
