## F25 的 C 模型与策略

C `lease.c:621–648` 把删除租约压入 `old_leases` 后立即增加 `leases_left`；`do_script_run()` 直到 helper 可消费时才释放该记录。`dnsmasq.c:1177` 的 `helper_buf_empty()` 只限制 helper 写入，不限制 DHCP 新租约。因此 `dhcp-lease-max` 只限制活跃表，永久慢消费者下 C 同样无界。

`helper_queue-{c,frozen}-red-{1..4}.json` 使用 lease-max=1，2048 次续租暖机后做 2048 次真实 ACK/RELEASE。helper 只进入一次；512→2048 次 churn 的 RSS 增量四轮分别为 Rust **1096/1096/1096/1096 KiB**、C **532/532/532/532 KiB**。释放 helper 后继续投递。RSS 读取分辨率 4 KiB；这是明确增长，未模拟设备 OOM，也不是线上自然发生的故障。

新策略是**只对新建 lease record 施加背压**：每包在状态机前按 `max(64, 2 × dhcp-lease-max) − active − pending_deletions` 计算分配预算。`allocate_record()` 消耗预算；同一事务中的 prune 不返还预算，因为移出的记录仍需 callback。乘法和减法饱和处理。64 的下限容纳小活跃表的短时 burst，双倍容量允许完整活跃表退出并保留事件；没有新增配置项。

满时走已有 `NoLeasesLeft` 路径：普通 DHCPREQUEST 返回 DHCPNAK，日志理由为 `no leases left`；rapid-commit/BOOTP 保持已有容量不足拒绝语义。已经建立的租约续租不分配记录；RELEASE/到期仍正常退出并保留删除事件；DNS 和 helper drain 均不阻塞。消费进展使下一包自动获得新预算。

这是相对 C 的有意差异：永久堵塞的外部脚本可以使**新租约暂时无法分配**。此选择保留已接纳状态的回调、守护进程资源上界和现有租约；没有丢事件、改脚本超时、强杀脚本、写无界磁盘队列或阻塞整个 DNS/DHCP owner。C 与原 Rust 都通过活跃租约 flags 合并尚未冻结的 add/old/renew 变化；本修复不新增逐包回调承诺。

总界限不只计算 deleted 容器：活跃与 pending-deletion 记录合计不超过 `max(64, 2 × lease-max)`；provider 和 owner 各最多一个冻结 delivery；Helper writer 只保留一个最大 65,536 字节 payload 的 frame（另有4字节帧头）；pipe 是内核有限容量，helper 顺序执行一项。已冻结 OldHostname 可能额外复制一个 lease，但也是这两个固定 delivery 槽之一。这是记录/帧界限，不将它冒称精确 RSS 上限；每条租约仍有合法变长元数据。

## F25 红绿与兼容验证

可重放回归为 `components/dnsmasq/tests/helper_backpressure.py`，调用形式：

```sh
sudo unshare -n env DNSMASQ_TEST_ISOLATED=1 \
  python3 components/dnsmasq/tests/helper_backpressure.py /absolute/path/dnsmasq
```

`--observe` 记录原实现；另设 `DNSMASQ_BACKPRESSURE_CYCLES=32` 可验证低于上限的正常流量。C 命令可在二进制位置指定匹配 musl loader，后接 `--library-path` 和实际 C ELF。

| 批次 | 四轮实测 |
| --- | --- |
| `backpressure-current-red-{1..4}` | 当前修复前源码每轮接纳 1024 次 churn，无拒绝；回归明确失败于“stalled helper never bounds new leases” |
| `backpressure-c-red-{1..4}` | C 每轮接纳 1024 次，无拒绝；1025 个删除事件完整，记录其无界基线 |
| `backpressure-green-{1..4}` | 每轮第 366 次请求开始拒绝；接纳 365 次 churn；helper 挂起期间 DNS 与 incumbent 续租通过；释放后含 incumbent 的 366 个删除事件逐名恰好一次；新分配恢复 |
| 同一绿批次 512→1024 次请求 RSS | **12 / 12 / 0 / 8 KiB**，没有原来的线性积累 |
| `backpressure-below-limit-{c,green}-{1..4}` | C/Rust 各四轮全部 32 次 ACK，33 个删除事件恰好一次，续租/DNS/恢复一致 |
