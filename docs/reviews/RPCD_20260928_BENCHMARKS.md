## 计量边界与独立复核

每格格式为 **三轮中位数 [三轮最小值, 三轮最大值]**。mean/p50/p95/p99 的单位为 µs；CPU 为 µs/op；吞吐为 ops/s。先在每个窗口内计算统计量，再取三轮中位数；不把三轮请求合并成一条分布。分位数使用排序后 `floor((N−1)×q+0.5)` 下标；c4 仅在同一窗口合并四客户端的延迟样本。三轮范围不是置信区间，范围重叠不等于性能相同。

每客户端预热 20 次。串行 CPU 分母只含正式成功请求。c4 的 RPCD 和 ubusd CPU 来自四客户端共享的唯一外层区间，分母为成功数加 80 次预热，并包括客户端启动、lookup 和收尾；不能累加四份重叠的 daemon 区间。c4 caller CPU 是四客户端各自正式区间之和，除以正式成功数，不含预热。因此三项 CPU 的简单相加不是统一边界的系统总 CPU。

每次延迟只包含 invoke 返回所需时间；响应 JSON 校验位于该次延迟之外，但仍在 caller CPU 与吞吐计时区间内。c4 吞吐使用外层 `/proc/uptime` 差，包含启动与预热，导出精度为 0.01 秒；较短窗口的吞吐应结合该量化边界阅读。未绑定 CPU。

RPCD own、ubusd own、caller own 使用进程 CPU clock；接口声明 1ns 分辨率不代表计量准确度为 1ns。RPCD children 使用已经回收子进程的 cutime+cstime，HZ=100，每 tick 为 10ms；RPCD tree 先逐窗口计算 own+children，再取中位数。只有 luci_features 观察到子进程 CPU；其 60 请求窗口中一 tick 相当于 166.667µs/op，保守的两端计数表示误差边界为单窗 333.333µs/op、成对 666.667µs/op。这个边界只描述导出表示，不是内核记账准确度。ubusd 与 caller 的已回收子进程 CPU 全部为零。

独立复核通过：9 个压缩归档 SHA-256、864 个原始文件清单项及归档成员逐字节哈希、459 个原始客户端结果、216 个派生观察、全部 1,096,740 个延迟样本，以及 CPU 原始计数差、进程身份与 start_ticks、三方夹具一致性。复核重新计算请求分母、均值、分位数、吞吐、own/children/tree CPU 和三轮范围；全部与正式派生结果一致。原始配置、SID、响应、地址与日志不进入公开 JSON。

区块顺序由冻结种子 202609281 生成：B1=H1/R89/C，B2=H1/C/R89，B3=C/H1/R89。比较表中 `↑↓↑` 按 B1/B2/B3 表示 H1−对照的数值方向；延迟与 CPU 向下更好，吞吐向上更好。各区块均保留，未进行“跑到赢”的补测。
