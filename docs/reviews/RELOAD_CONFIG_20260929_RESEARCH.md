# reload-config：2026-09-29 研究与候选筛选

本轮保留 H1/H2 的有界分配与扫描优化，以及 H3 的顺序进程内 ubus 投递。最终正式候选在 AX3000T 实际单包/多包变更负载的命令树 CPU 对 R94 分别下降34.15%/58.41%；原版、R89、R94、最终候选的独立四侧证据见下文。开发 SDK 筛选与最终 canonical 结果分别记录，不混用产物身份。

起点为 `287d75cba0e71afa920f7c3434ec10b9c92a5c22`，继承已收尾 UCI 的 `feb7a4e` 运行时，以及 R94 进程内 UCI show、MD5、一轮 Context 复用、运行锁和 R95 的完整读取/超时取消修复。上述收益不计入本轮新增。正式基线要求保持精确镜像原脚本及执行链、R89 原 ELF、R94 原 ELF；此处的 base 只是从本轮冻结源码构建的短增量起点。

来源映射使用 [匹配镜像源码表](../../reports/ax3000t-stock-openwrt-25.12.5/SOURCE_MAP.md)：ubus `24864e7840b3a02a9ef76284a373f6b2f00b8a9b`、procd `58eb263d5abe03f8c1280bdfa65a3b052614215d`。状态映射按该ubus的 `cli.c:ubus_cli_error/ubus_cli_call` 和 `libubus-req.c` 核对，行为边界以 [C1-01合同](../contracts/config-change-dispatch.md) 与现有差分证据为准。

## 机制与决定

| 假设 | 具体改动与减少的工作 | 关键不变量、证伪条件 | 决定 |
|---|---|---|---|
| H1：规范化/摘要/基线分配 | `md5::hex` 用数字表替代每包16次 `format!`；`normalize` 每条 clear 并复用 Vec，超过64KiB不保留容量；`write_baseline` 使用 BufWriter，去除逐行 Vec 和逐行系统调用 | 完整渲染字节不变，错误/超时保留已渲染前缀；64KiB只限复用容量，不截断输出；flush→sync_all→rename。常用负载CPU无改善且新增驻留成本明显则否定 | Oracle各主要场景CPU下降，保留 |
| H2：扫描重复元数据/排序 | `scan_config_names` 普通文件使用 DirEntry 类型，symlink或类型查询错误回退原 `is_file`；basename一次取值、重复名早跳过，只对最终集合排序 | 普通非隐藏文件、symlink到普通文件、override优先和去重上限不变；不使用mtime/size跳过规范化。若仅大规模合成语料受益则不扩大 | 4包差值很小且方向混合；24/64/128包CPU两轮下降，保留 |
| H3：实际事件的重复进程/连接 | 使用现有 `owrt-ubus`，顺序投递、成功连接复用、逐事件重新lookup；直接编码blobmsg，无外部CLI/JSON往返 | 等待匹配STATUS；共用绝对deadline；传输阶段可取消；事件不重试；权限/状态/原始名称字节一致。诊断变更负载改善须超过预先冻结的15%门，且正式版本须满足故障和512KiB包体门 | 诊断达到扩展门；正式可取消组合通过故障/恢复和包体门，实机实际变更收益支持保留 |

H3诊断首先复用连接和对象ID，专用于成功路径的乐观成本参照，缺少阻塞期间取消与完整错误映射，永不作为部署候选。静态体积并未成为阻断：它比起点更小，删除进程生成/等待路径抵消了新增库链接成本。随后正式实现逐事件重新查询对象，避免 `service` 重注册后使用陈旧ID；旧连接查询阶段的纯传输故障可在原deadline内重连一次，此时尚未发送事件，invoke本身绝不重试。

`Connection::connect_interruptible` 的廉价回调仅由本调用方启用。现有消费者默认None；新的绝对deadline接口区分本地耗时上限与远端状态7。检查覆盖连接backlog、HELLO、发送背压、大小帧/部分帧、连续可读回复及等待。超时/取消关闭连接并清理待处理FD。非tty CLI状态映射保留：连接失败255，lookup失败正状态，invoke失败负状态低8位；例如远端6/7分别250/249，本地预算耗尽为trace `timeout`。`--timeout-ms`较长时仍保留CLI invoke内部30秒上限。

取消边界另有两项修复：投递开始及基线写入/rename前检查取消；基线从同一File句柄读到EOF，使用 `take(1310720+1)` 并检查真实读取长度，不能靠读取前metadata绕过上限。取消仍退出75、停止后续事件、保留旧基线，已发事件不撤销。

没有采用流式MD5、第二套UCI渲染器、mtime缓存、全局索引、并发投递或常驻服务。缓冲和扫描小改动已有普通规模收益，尚无机制证据支持上述额外复杂度；这不是宣称所有可能算法均已穷尽。

最终候选消除了三次ubus子进程启动和十五次失败PATH exec尝试，连接建立由三次降为一次；每事件重新查询对象的次数保持不变。旧/新Rust写入调用由29降为6，返回字节均为2,176；此处累计全部描述符（管道、日志、socket等），不能把全部差值归于基线缓冲；fsync及原子rename各保留一次。两版Rust均发送六次ubus消息、共380字节；直接blobmsg编码省去了CLI JSON解析，但没有减少必要的lookup/invoke消息。C的BusyBox内部执行与PATH搜索方式不同，失败exec为0不意味着没有搜索成本。

## 工程结案

H1/H2在普通24包与合理较大规模有依据，H3在实际配置变更中给出明显收益；可取消组合已用独立正式产物重新计量并通过故障、恢复和共享消费者门。继续缓存对象ID、并发投递、重试不明事件或绕过完整读取会破坏合同；流式摘要、全局索引与编译调参没有足够新证据支持额外复杂度。接受已量化的少量minor faults、日志依赖CPU和个别慢尾窗口代价，保留所有SDK pilot与正式不利结果。本轮不再机械增加变体或测量轮次。

最终源码、APK/镜像/ELF、18项native门、R1/R95、正式四侧、七消费者11门及清理记录由[总验证清单](reload-config-20260929-validation.json)串联。共享门保留原因未明的控制中断，最终状态为 `COMPLETE_WITH_INTERRUPTION`，功能门全部通过；没有把原集合的失败状态改成连续完成。可用公开工具 `tools/benchmark/render_reload_report.py` 从私有采集目录重新生成145行正式表和派生JSON，其全部数值已复现并经过独立审计。
