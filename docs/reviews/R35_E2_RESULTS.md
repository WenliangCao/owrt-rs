# R35 / E2：rustc 侧 target/OUT_DIR 映射 —— 完全的空结果，并因此关掉整条"路径"线索

日期：2026-09-05。基线 `42a7fd2`。继续单变量：这一轮**只**给 rustc 加
`--remap-path-prefix=<本机诊断 target 目录>=/target`。CC 侧映射按你的要求**没有开**，
SDK 路径也没动。对照基线沿用 E1 重收的 A0/B0。

## 因素确实生效

先按 R35 的要求验证（E1 差点栽在这一步）：`cargo-vv.log` 里该 flag 出现 **16 次**，
确实进了 rustc 命令行。所以下面是"已验证的空结果"，不是"未生效"。

## 为什么是空结果：那条路径根本没进过产物

直接查发货二进制里**还剩哪些绝对路径**（A0）：

```
  29  /cargo/registry/src/index.crates.io-…/ring-0.17.14/src/…
  27  /cargo/registry/src/index.crates.io-…/rustls-0.23.43/src/…
  7+  /rustc/48a229ceaefd4985c50990b14116b6d856af0985/library/…
   2  /dev/null
```

`/home/ubuntu/diagwork`（本机 target 目录）出现 **0 次**。
`/cargo` 是配方已经映射好的；`/rustc/<commit-hash>` 是编译器自带的，两台机器**同一个 commit hash**，因此相同。

**结论：发货二进制里没有任何依赖宿主的路径。** 这不是推断，是直接取证。

## 这关掉了什么

E1 已经证明 ring 的 DWARF 路径与发货哈希无关（改了对象，二进制一字节没变）。
E2 现在证明 target/OUT_DIR 路径同样无关，而且**它压根没被嵌进去过**。
加上上面的字符串取证，**"嵌入的绝对路径导致最终二进制不同"这条线索到此为止，可以关闭**。

我在 R34 提出、E0 沿用的那个机制假设（长度不同的路径串移动 `.rodata`、PC 相对引用跟着位移），
到此**在发货产物这一层被完整证伪**。两轮单变量对照各自都是必要的：
E1 排除了 C/汇编侧，E2 排除了 rustc 侧，若按合并方案一次做完，这两条都会被混在一起。

## 下一条线索：zeroize 的 rmeta 差异**不是路径**

拆开 `lib.rmeta`（两边同为 529880 字节，差 338 字节、2 个簇，都在 `0x70929`–`0x70b38`）：

```
CI  : …\x01\xb6*\x01\x00\x01\xc2\x8b\x1c\x00\x00\x01\xd0\x8f\x1c\x01\x00…
HOST: …\x01\xb6*\x01\x00\x01\xd0\x8f\x1c\x01\x00…
```

差异落在一段 **LEB128 风格的二进制编码区**（紧邻 `ch=master` 与许可证文本），
**不是可读的路径字符串**；CI 侧多出一组条目。也就是说这里是**条目数量/顺序**不同，不是内容路径不同。

所以剩下的差异**不属于路径类**。需要解码这段 rmeta 结构才能说清是什么表
（source-file map、span、attribute 之类），这超出了本轮单变量实验的范围。
