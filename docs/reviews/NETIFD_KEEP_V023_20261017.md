# v0.2.3：netifd 未变续租跳过内核写

**连续 7 次相同续租，Rust 与精确 C 均为 0 次 RTM_NEWADDR、0 次
RTM_NEWROUTE。最终 SDK ELF 的 48 病例定向门通过；同源 Oracle 构建的
172 单测、48 定向病例及完整 33 项运行期回归通过。尚未物理部署。**

本轮只消除 netifd 已证实的重复工作，不重写 DHCP 脚本，不改变固定 60 秒租期。
成本模型是每次相同 IPv4 续租原先重复提交一个地址和一条路由；此前 7 次输入的
14 次请求来自代码与输入推导，未冒充旧版本系统调用实测。本轮用 `strace` 直接
计数 `sendmsg/sendto` 的 netlink 请求，不用可能被内核合并的通知代替写入，也不
将减少的请求数换算成毫秒或开机收益。

[实现](../../components/netifd/src/main.rs) 仅在同一设备名称和 ifindex、此前成功、
属性与完整协议项 key 相同时跳过写入。地址比较含每族 index、offlink、默认化的
broadcast、ptp 和 lifetime deadline；IPv6 lifetime 改变仍刷新，过期和失败不跳过。
路由 key 含 flags、metric、table、source，另比较 nexthop、MTU、type、proto。
路由 deadline 更新保留在状态中。reload 重加失败会记录，后续通知可重试。
通知、解析及 `netifd-proto.sh` 的边界未改。

[`cbb83a1857407a28a63dc09412a1f209195914ef`](https://github.com/openwrt/netifd/blob/cbb83a1857407a28a63dc09412a1f209195914ef/interface-ip.c)，

[定向门](../../tools/netifd_renewal_keep.py) 使用真实 ubus 通知和隔离网络命名空间，
覆盖重复续租、真实地址/路由变化、IPv6 刷新与自然到期、初次安装及 reload 失败重试、
`keep=true`、同地址不同 index、重复路由 key 和撤销。48 病例中 **43 个可比内核状态
无差异**；剩余 5 个是明确的故障/既有 C 差异边界，分别断言失败、保留、恢复及撤销，
不宣称它们与 C 状态等价。内核字段完整比较，有限剩余 lifetime 只容许 2 秒时钟差。

独立审阅先后捕获并修复两个候选缺陷，旧失败证据均保留：

- `cdbba777`：旧路由 A，本通知同 key 顺次 B、A，第二项不能再凭旧 A 跳过。
  本轮见过的 key 后续一律写入；真实回放确认旧候选只写一次、新候选与 C 均写两次，
  最终状态正确。`gateway` 与 `routes` 之间也共享此边界。
- `7c7f527e`：本通知 B 成功、C 替换失败时，不能先从状态中移除成功的 B。
  仅在成功、确认 keep 或明确 inactive 后替换状态；失败保留已安装项，随后的
  withdrawal 实际删除 B。旧候选漏删、新候选正确的对照均有内核证据。

C 失败边界没有被隐藏：C 的 `interface_ip_set_enabled()` 忽略地址重加错误，
在人为禁用 IPv6 导致 reload 失败后，相同通知可能不再重试；Rust 记录失败并恢复。
路由替换失败时，Rust 既有 CREATE|REPLACE 语义保留此前成功的 B，C 会先删除 B；
此次保持 Rust 的既有失败边界，并保证 B 仍可追踪和撤销，不重构 C 的 failed-status
模型。成功路径的 keep 条件遵循 C。

完整 suite 用同一最终 Oracle ELF 验证了 33 个唯一 case。初次并行执行发现 r60
变体共用 `/tmp/r60-stub.sh`：C 读取 fail stub 后，Rust 可能读到另一变体的 up stub。
因此**全部 7 个并行 r60 结果均判无效，包括表面通过项**；保留原日志，用原脚本串行
重跑 7 项全部通过。其余 26 项不使用该共享文件；汇总严格检查 33 项各一次、全部
成功及产物/测试源码哈希未变。旧比较器没有修改。

原始记录和已测 ELF 保存在 Git 忽略的 `private/netifd-keep-v023-20261017/`：
`final-suite-summary.json`、`run-final3/`、`run-sdk-cd02d474/`，以及两次审阅缺陷的
正反记录。SDK 原件来自 canonical CI 的 `core-candidates/netifd-rs`；没有固件、
配置备份、设备原始数据或密钥入 Git。

当前结论支持将该 SDK 产物纳入 v0.2.3。以上是 Oracle/SDK 运行期证据，不是物理
路由器部署或客户端健康验收；后续仍须执行已授权流程中的备份、回滚及客户端验收。
