# R131 尾延迟补测

18 个物理路由器隔离窗口全部完成，C/R124/R131 使用同一份逐操作计时 caller，
每个场景 5000 次、预热 200 次。全部 payload、原始样本、身份、健康和清理门通过。
原始数组不与旧 CPU-only caller 混算；按每个窗口计算分位数，再取六个配对变化的中位数。

| 八处理器、一个连接 | 相对 R124 | 相对 C |
| --- | ---: | ---: |
| 平均端到端耗时 | −16.62% | −12.94% |
| p50 | −15.87% | −13.46% |
| p95 | −20.04% | −9.20% |
| p99 | −17.25% | −11.49% |
| daemon CPU/op | −20.29% | −18.42% |
| caller CPU/op | −8.54% | −5.68% |

相对 R124 的平均耗时六块全降，范围 −29.80% 至 −12.54%；主场景 p95/p99/daemon CPU
均未触发 +5% 回退门。单处理器与无匹配场景没有触发预冻结的 guard，故本次
`pass_latency_supplement`。它补上了旧 router-04 缺失的尾延迟证据，不能倒写旧批次为已经测过。

反向结果保留：无匹配场景 p99 相对 C 的配对中位 **+5.43%**，六块为
`+2.93%, +25.06%, +7.93%, −1.95%, +9.74%, −19.47%`；相对 R124 中位 +4.45%，
也混号。八处理器 p99 相对 C 仍有一块 +5.77%，其他五块下降，其中一块 −79.06%。
这些尾部波动不能删除，不能据总体中位数声称每个窗口或所有尾延迟都胜 C。

本结论只覆盖三种 serial event fixture，六个窗口块不是统计等价证明。
时钟与 callback 校验都在端到端延迟中，时钟开销没有扣除。其他 owner、monitor、背压、
内存与共用发送路径的验收另行记录。
