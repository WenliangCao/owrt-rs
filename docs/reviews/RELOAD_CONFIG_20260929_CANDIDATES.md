## 未采用方向

| 方向 | 具体理由和边界 |
|---|---|
| 仅把 `ubus` 改成绝对路径或自行缓存PATH解析 | 只可能省少量搜索，仍保留每事件fork/exec、连接、lookup和JSON解析；自行PATH解析还引入可执行权限/搜索顺序语义。未形成独立性能候选，不声称已测失败 |
| H3诊断直接投产 | 明确违反取消与对象/错误边界；无论成功路径多快均拒绝 |
| 每轮永久缓存service对象ID | 可能遗漏对象重注册。最终仅复用连接，每条重新lookup；诊断缓存收益不能冒称最终收益 |
| 辅助线程包装阻塞API | 连接建立期间无法可靠中断，需要额外关闭/生命周期协调，增加线程和栈成本；显式传输取消回调更小 |
| 重写UCI parser/show或流式摘要 | 当前瓶颈已有低复杂度缓解；完整输出和已渲染前缀语义增加流式改造代价，无新增数据支持 |
| 全局包索引、mtime/size跳读 | 不重新开启UCI已拒绝方向；必要完整读取、delta重放不可跳过；扫描曲线无需新索引 |
| 并发投递、仅写socket返回、失败自动重试 | 分别违反旧基线顺序、完成边界、状态不明时不得重复投递的合同，不作为性能候选 |
| 调编译参数/关闭trace/去掉sync_all | 本轮没有此候选；不能把这些语义/工具差异伪装成算法收益 |

H1/H2小规模不利数字、H3诊断无变化CPU增加均已列入研究报告。只有正式组合的实测、资源取舍及故障门齐全后，才可填写最终保留与本轮停止结论。
