## 身份与成本模型

| 实现 | SHA256 |
|---|---|
| 精确 C | `53e534a12d412b1f138ab95d15431bc109bbb356dbfadfb8625397d585d2be82` |
| 最终 Rust | `589226a178668c0e53fa8db5ff726e2b4e69464f9521355fad229b1862c3043e` |

Rust 为 802,936 B 静态 AArch64，来自 SDK CI `39122603394`，产品源码
`162d9ba8305c9f8508a0ec099336f58235329931`；69 单测、Clippy、真实私有
ubus 和新 ELF 的 129 项实包检查已经通过。

当前模型：事件/实际期限唤醒消除了静默窗中的多余工作；一次性文件导出期限
减少连续请求间的同步 I/O 阻塞。上一限定批次空闲 C/Rust 为 18.859/0 µs/s，
Renew 为 544.462/288.572 µs。预测这两项仍不退步；同一 ELF 的其余路径
可能受调度和代码布局影响，因此不能由这两个数字转授全项资格。本轮直接
测这一未知数。预测更新 CPU 不退步、RSS 仍低于 C，RS/其它 DHCP 延迟不超
校准噪声；任一反例即推翻发货判断，不新增分析实验或优化轮。

## 复用原完整场景

按[原完整计划](ODHCPD_DEVICE_AB_PLAN_20261018.md)的最终三 NA 场景执行。
仅让 full profile 接受显式最终候选 SHA；默认旧 c7 合同仍能重放，采样 C
仪器、场景数量、顺序、CPU 时钟和噪声计算不改变。使用现有静态 probe 与
namespace helper，Oracle 只校验新绑定的 full 模式功能，不判断性能。

1. 独立地板：16 次连续时钟读取、16 次真实 UDP echo，原样保留，不扣除。
2. 校准 `ABBAAB`、正式 `ABBABAAB`，十四个全新私有实例。
3. 每实例安静 2 秒，测零租约的 3 秒空闲进程 CPU，再取空内存；执行 16 次
   RS 和三 NA 客户端轮换的 16 组 Solicit/Request/Renew；取三 NA 内存；
   最后八次实际 provider 通知，经 dump 观察含新 RDNSS 的 RA。
4. 回复延迟取各 16 次中位数；更新 CPU 取八次中位数，窗到匹配 RA＋1 ms，
   包含目标线程和等待中的后台工作，不含 provider/ubusd/脚本子进程。

十项门值：RS、Solicit、Request、Renew 延迟；每次接口更新 CPU；空闲 CPU；
空与三 NA 两阶段的 RSS/RssAnon。内存按实际页大小量化。这里不添加首主动
RA、PD 内存或前缀切换性能等原完整批次没有的场景；有效 PD 功能仍由实包
夹具覆盖。

每项独立重新校准
`N=max(C 三个校准值极差, Rust 三个校准值极差, 2×实际量化)`；空闲 CPU
按实际墙钟窗折算，噪声也同比例折算。四个相邻 AB/BA 对逐一比较 Rust−C，
**任一指标任一对 > N 即停止**。固定批次结束后分析一次，不以总体中位数
抵消失败。超时、缺样、仪器或隔离失败同样停止；不补样、不设固定微秒门槛。

## 隔离、恢复与后续

沿用只读根、私有 mount/net/PID/IPC/UTS namespace、空 bridge 和私有 ubus；
无物理端口，不加载模块或改 CPU 策略，生产继续运行 C。保留内核生成的 MAC，
固定 IPv6 地址和客户端 DUID。该路径不是 Wi-Fi 往返时延。

先核对新备份、回滚镜像、救援原件及客户端健康；每样本自有 namespace 自动
收尾，整批另设 600 秒守卫。结束后逐哈希归档、清理临时文件，再核对生产
boot/PID/ELF/配置/挂载和客户端健康。全部通过才恢复 v0.3.0 构建与部署流程；
任何退步都保留此最终候选、停止汇报，不再修补。
