# v0.2.3：省去未变化的防火墙与续租内核更新

本版只改 fw4-rs 的 reload 判定及 netifd-rs 的地址/路由 keep 行为，不重写 DHCP
脚本。当前处于实现与验证阶段，尚未发布或部署。用户已授权按备份、回滚、客户端
健康流程部署本版；现役 v0.2.2 是完整固件回滚目标。

## 实现前模型和边界

[启动测量](DHCP_EVENT_REBOOT_20261017.md) 已证明当前 WAN6 的 21 份状态对应
相同有效防火墙规则，且 7 次相同 IPv4 续租仍提交 14 个可省的内核请求。
本轮验证目标是这些确定的操作是否消失，以及真正改变/失败时是否仍完整执行。
不拿微秒差异当门槛，不扩大未修改八组件的性能矩阵，也不重新训练 DNS PGO。

- fw4：仅在持锁、可判定生成规则等价、确认当前内核内容仍匹配已成功应用结果时
  跳过下发。支持现网软件 flowtable 与计数器、纯注释自动 include；活动 script
  include、不可判定的 nft include/运行时状态、查询或缓存故障照常重载。必须防止
  apply 后外部修改导致把新文本与错误内核快照配对。print/check 输出合同保持。
- netifd：使用精确 C 的完整 keep 条件，不仅比较地址字符串。有限 IPv6 lifetime、
  offlink/broadcast/路由属性变化、L3 设备更换及失败重试仍须提交内核；不改 DHCP
  客户端动作/环境、notify_proto JSON 或 netifd-proto.sh。
- 语义差异：fw4 参考是原版 shell/ucode+nft（通常称 C 栈）。其 reload 无条件重新
  下发；本版已确认相等时保留已安装规则、计数器及 flowtable。restart/stop/flush、
  includes 和无法确定等价的情况不借缓存跳过。精确差异随最终实现及测试更新。

## 版本与验收顺序

统一版本 `0.2.3-r1`；新 fw4/netifd 参考 ELF 来自 canonical x86_64 CI 的 SDK
产物，再由 release-image 重新构建并比对。另八组件、内核、驱动及执行面保留。
全部 Rust 构建/测试在 Oracle 或 CI；Mac 不产生 target。

1. 两组件各自 Oracle 定向功能/边界测试及精确参考对照；各自小提交。
2. 完整现有 host/SDK CI，固定两项新 ELF；生成唯一正式 v0.2.3 镜像。
3. 对最终镜像复用原离线恢复、guard、PID1 交接及 guarded boot 检查。
4. 重新取当前配置备份，核验离线原件、现役 v0.2.2 回滚镜像及当次自动回退；
   用原 stage/activate 工具保留配置刷写，验证十组件身份与客户端连续健康。
5. 观察自然 WAN6 事件与固定 60 s 租约的续租；用实际规则/内核写证据验收，
   不把 hotplug 的“Reloading firewall”触发日志当成实际 nft 下发次数。
6. 清理自有临时守卫和采集材料，保存干净备份，发布同一 CI 字节的 v0.2.3。

本版完成后再进入 odhcpd-rs：仅 RA+SLAAC、DHCPv6 IA_NA/IA_PD、租约和
leasetrigger、ubus dhcp、UCI、netifd 前缀订阅；NDP 代理、中继、DHCPv4 模式
拒绝启动。首条 RA/首个 DHCPv6 回复不慢于 C，旧前缀正确废止，内存≤C 的两倍，
ubus 能重连；不设微秒门槛，不做 PGO。它不混入本次两项改动的 v0.2.3 镜像。
