R135、R136 与 Oracle 结果不拼接，也不改写其负项。

复用 R134 已完成 recipe 和保护驱动，共 46 个物理窗口：

- 事件背压：C/候选各一次，grouped、interleaved、monitor、slow 四场景。
- 主矩阵：15 条负载，ABBA × 4，共 16 窗；每条 10,000 操作。
  使用两侧相同 Rust `owrt_ubus::Connection` benchmark，daemon CPU 1。
- 直接 SEND：3 条原版 libubus 负载，ABBA × 4，共 16 窗；
  每条 5,000 操作、200 次预热，daemon CPU 1、caller CPU 0。
- 内存：idle、large、fanout 三夹具各 ABBA × 1，共 12 窗；
  每侧每夹具两次，保持原有负载大小、采样相位和等待时间。

R136 同一 ELF 已通过的实机 wire/FD 记录作为哈希前置门，不重复收集。

不按结果追加或重跑。沿用已完成 R134 记录的实际时长，预计约 30–35 分钟。

唯一主要判定沿用 R136 的描述性规则：八个不复用的相邻 AB/BA 配对，
候选/控制百分比变化中位数低于 −1% 且至少 7/8 对下降记胜；高于 +1%
且至少 7/8 对上升记负；其余未分辨。mean、p50、p95、p99 和 daemon
进程 CPU 时钟全部公开；禁止 tick 回退。±1% 不是 A/A 校准的等效区间，
未分辨不证明等效，逐指标结论没有多重比较校正。

不从胜负数量推导全局采纳门或全面胜 C。现有定向采纳结论仍限于原八窗。
