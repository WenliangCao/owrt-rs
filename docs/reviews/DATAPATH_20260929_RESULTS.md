# 整机网络性能与固件维护：本轮结果

2026-09-29。**九组件固件保持原版本与原网络配置。局域网无线↔有线 TCP 中位吞吐为 797 / 628 Mbps；完整软件→硬件→软件对照没有证明开启硬件流量卸载能降低当前 Wi-Fi 上网路径的 CPU 成本，因此候选未保留。发布工具已支持后续版本，自动构建候选也不再取代稳定 Latest。**

本轮实际覆盖无线桥接和 Wi-Fi→WAN 组合路径；纯有线 LAN→WAN 尚未单独测量，不能据此给出有线 NAT 线速上限。没有更换九组件二进制或重建生产固件。

## 1. 环境与方法

- AX3000T，OpenWrt 25.12.5 / Linux 6.12.94，正式节点 [ax3000t-rust9-v0.1.0](https://github.com/WenliangCao/owrt-control-plane-rs/releases/tag/ax3000t-rust9-v0.1.0)，源码 `a4053dd5d4b4b2dbed3ff8a56d595aeabd33e0d0`。
- Mac 连接 5 GHz Wi-Fi，80 MHz、两空间流；Windows 经 USB-C 网卡连接 LAN4，最终协商为 1000 Mbps 全双工。WAN 为 DHCP、1000 Mbps 全双工。软件流量卸载开启，WED 关闭，packet steering 开启。
- 局域网 iperf3 3.21：4 并行 TCP 流，每次正式 15 秒、排除 2 秒预热，双向交替各三轮。取接收端吞吐。Mac 工具由官方源码构建；Windows 使用指导下载的 3.21 便携构建，未远程取得其可执行文件哈希。
- 外网使用 macOS 自带 networkQuality，固定 `-M 25 -I en0 -c`，同时上传下载，软件 A₁ / 硬件 B / 恢复软件 A₂ 各三轮。工具会在收敛后提前结束，CPU 观察随实际执行结束停止。端点由工具选择，包含 Wi-Fi 与宿舍上游，三轮不是普遍吞吐保证。
- 路由器 CPU 来自 `/proc/stat` 差值，整机百分比以两核总容量为分母，包含测试期间内核、其他服务及采样通信。不是九个 Rust 进程的 CPU。
- 延迟使用 Mac→路由器 HTTP 端口的 TCP 建连，每 0.5 秒一次，1 秒超时；包括客户端调度和无线链路，不是 ICMP RTT。p95 用成功样本的 nearest-rank，失败单列，样本规模不用于 p99 声明。

[冻结计划与人工中断说明](DATAPATH_20260929_PLAN.md)、[派生数据及全部原始文件哈希](../../reports/ax3000t-stock-openwrt-25.12.5/DATAPATH_20260929.json)。原始 IP、MAC、服务器名称和输出保存在 ignored `private/datapath-20260929/`。

## 2. 无线↔有线局域网

方向从 Mac 看，双方在同一个 LAN 桥上，没有经过宿舍外网。表中 CPU 为三轮各自平均占用的中位数；吞吐同时列全部三轮，避免只报最快一轮。

| 路径 | 三轮接收端吞吐 Mbps | 中位吞吐 Mbps | 路由器 CPU 中位数 |
|---|---|---:|---:|
| Mac Wi-Fi → Windows LAN | 727.11 / 836.49 / 797.21 | **797.21** | **68.61%** |
| Windows LAN → Mac Wi-Fi | 621.52 / 655.21 / 627.72 | **627.72** | **52.44%** |

六次 iperf 请求均成功。同步 TCP 建连探测共 204 次，失败 0；另有 20 次空闲探测。

| TCP 建连场景 | 样本数 / 失败数 | p50 ms | p95 ms |
|---|---:|---:|---:|
| 空闲 | 20 / 0 | 7.63 | 13.65 |
| Mac 上传至 Windows 时 | 102 / 0 | 20.72 | 50.90 |
| Windows 下载至 Mac 时 | 102 / 0 | 6.87 | 19.25 |

Mac 作为发送端的三轮 TCP 重传为 455 / 66 / 134；Windows 发送端未提供该计数，记为缺测而非零。无线 station 的 retry/failed 计数是驱动统计，也不能直接当成 IP 丢包率。

这证明当前配置具备数百 Mbps 的实际局域网承载能力。满载上传时连路由器本机的等待也增加，后续研究应区分无线排队、主机调度和路由器处理成本。没有足够证据把延迟全部归因于某个 Rust 组件或宣称达到了无线硬件绝对上限。

## 3. 软件与硬件流量卸载对照

预检查中，Rust 与镜像保留的原版 fw4 在同一临时配置下生成的候选规则逐字节相同，内核检查接受 `flags offload`。只改变 `flow_offloading_hw`，WED、信道等保持不变。

| 窗口（各三轮） | 下载中位 Mbps | 上传中位 Mbps | 整机 CPU 中位数 | networkQuality 响应性 RPM |
|---|---:|---:|---:|---:|
| 软件 A₁ | 381.21 | 490.59 | 65.15% | 578.94 |
| 硬件 B | 366.94 | 463.84 | 66.67% | 610.71 |
| 恢复软件 A₂ | 403.60 | 460.65 | 66.74% | 494.85 |

相对前后六个软件轮次的中位数，硬件候选 CPU **+0.70%**、下载 **−5.30%**、上传 **−1.44%**。这些小差异不作为稳定退步结论；明确的结论是没有达到事先设定的“CPU 至少降低 15%”收益门。

| 窗口 | 负载时本机 TCP 探测数 / 失败数 | p50 ms | p95 ms |
|---|---:|---:|---:|
| 软件 A₁ | 103 / 1 | 45.02 | 100.90 |
| 硬件 B | 100 / 0 | 36.37 | 82.08 |
| 恢复软件 A₂ | 88 / 1 | 41.59 | 97.29 |

外网工具的全部九次测试成功；上表另外两次失败是同时进行的本机 TCP 建连探测超时，不能写成“整个负载零错误”。B 的这些延迟读数更好，但样本有限、负载和上游有波动，不能据此保证稳定改善，也没有抵消未满足的 CPU 收益要求。

B 窗口的整机连接表确实出现过硬件卸载连接，按每轮开始前/结束后的顺序，六个快照的计数为 2 / 12 / 2 / 10 / 6 / 26。该计数包括其他客户端，不证明每条测速连接都进入了硬件。WED 仍关闭，本次没有测试“HFO + WED”的组合，也没有测试纯有线客户端的 HFO 收益。

**处置：候选不接受，保留原软件卸载配置。** WED、SQM、信道宽度等未一起改变，以免无法判断效果来源。没有依据这一轮去重写 DNS/DHCP、无线认证或内核。

## 4. 固件维护的实际改动

1. `native_release_prepare.py` 原先硬编码 v0.1.0、OpenWrt 25.12.5、包版本、镜像大小、910 个文件等。本轮改为从标签、正式 manifest 和匹配验收记录取值，后续版本不再带着旧版数字；保留源码和镜像身份一致性检查，并核验固件实际字节数。
2. 通用 `v*` 标签产生的构建 Release 改为 prerelease、`--latest=false`。没有经过真机验收的候选不会自动替代稳定 Latest；生产节点仍从已有正式产物晋升。
3. 增加五项发布工具回归：后续版本的实际元数据、验收源码错配、产物损坏、错误硬件 profile、错误标签。已用现有正式产物重新生成本地发布资产，确认固件未重建且 SHA256 不变，八份资产校验通过；没有重新发布 v0.1.0。
4. 新增可重复的网络测量和脱敏分析工具；原始地址、设备输出和配置保持在 private 中。完整 164 包分层归类见[系统分析](NEXT_PHASE_20260929.md)。

本轮没有为了缩小镜像随意删除协议、共享库或恢复文件。原有离线镜像装配、配置迁移和九入口所有权验证继续使用。[发布说明](../RELEASE.md)记录后续流程。

## 5. 测量失败与配置恢复

- Windows 最初没有枚举出 USB 有线网卡；用户换 USB-C 口后取得地址，链路由先前观察到的 100 Mbps 变为 1000 Mbps。没有修改路由器来解决该问题。
- Windows 临时防火墙规则首次因非管理员终端而失败，随后管理员终端添加成功。Mac 普通 TCP 工具随后可连接该端口。
- 同一个 Mac iperf 可执行文件从代理环境启动持续立即返回 `No route to host`，从系统 Terminal 启动后成功。结果支持启动环境相关的访问限制；没有直接观察到系统内部最终判定，不能把具体权限机制写成已完全证明。Apple [TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)说明了命令行程序与负责启动它的应用之间的权限归属。
- 自有远端 iperf 端口超时，未修改其云网络规则。首次 networkQuality 文件参数错误、所有失败输出、连接 pilot 与首次中断的 HFO 窗口均保留，不混入正式九轮对照。
- 两次 HFO 候选窗口均有独立限时恢复；正常结束主动恢复原值。最终配置没有 pending delta，防火墙原文件 SHA256 为 `c7bd93a53be8cc55f3df0a41c7460d7eba4b99ad5ad97b6db4c7f2a1d65280c9`，临时路由器文件归档后清除。没有留下常驻采集服务。
- 最终只读复核：软件卸载为 1、硬件卸载为 0，运行 flowtable 没有硬件标志；九个 Rust 程序哈希全部匹配，LAN/WAN/WAN6 均为 up，客户端管理 HTTP 返回 200。路由器测试目录及测试进程均已清除。
- Mac 测速进程已结束，本轮创建的桌面测速入口已删除。iperf 仅从项目 private 目录运行，没有安装系统服务；原始证据与构建文件继续保存在 private 中。
- Windows 用户已停止接收端并关机；临时防火墙规则的删除尚未确认，留待下次开机在管理员 PowerShell 执行 `Remove-NetFirewallRule -Name "OWRT-Iperf3-20260929"`。不需要为本轮测量重新开机。
