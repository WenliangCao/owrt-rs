## 范围与下一处定位

- 多数方法仍低于 C 开销，但“全面优于 R89”的要求未达成；不能用 `uci_get_64` 优势抵消权限查询退步。
- R89 到 source05 的 session access 主逻辑未变；总线期限保护及 daemon 维护路径有改动。这是定位线索，不是已经证明的根因，不能撤掉期限保护来换分数。
- 三侧仅替换 rpcd，依赖保持原版，生产栈保持 R92。候选为同 SDK recipe 的诊断构建，构建 host 与 canonical R89 不同，不能把全部差异唯一归因于代码。
- 此轮没有修改 rpcd 性能算法；source05 恢复修复仍通过对应故障门。
- c4 CPU 使用单一外层区间，按成功与预热总数归一化；客户端在同一路由器消耗 CPU。每个数值为逐轮统计的中位数，不能当服务端极限。

逐轮范围、分位数、内存及身份：[r93-rpcd-device-baseline.json](r93-rpcd-device-baseline.json)。
