## 实现边界

- 共用 ubus 保留 deadline、取消、部分读写、背压和 framing；普通管道/socket 使用
  rustix。数字 FD 快照、poll/epoll teardown、精确 20 B 单 FD SCM_RIGHTS 的最小
  ABI 留在 platform，不把可能无效的整数伪造成 BorrowedFd，不增加 payload 复制。
- uci 的读写/目录筛选和 CLI 逻辑在安全 library 中。fw4 也将规则/CLI 逻辑放入
  forbid 根。两者原 libc `main` ABI 保留为各自 `platform/entry.rs` 的薄二进制入口，
  不引入 Rust runtime prologue，不改变继承 SIGPIPE、原始 argv 字节或既有启动成本。
- httpd 保留 parked socket/线程交接、短读写、HTTP deadline、TLS/CGI 状态机；
  logd 保留环形缓冲、批量输出、断连和流式背压；reload-config 保留取消和锁语义。
- netifd/rpcd/procd 的协议与服务策略保持原位。owned FD、netlink 和一般 syscall
  使用 rustix；少数 ioctl、NSS、syslog、POSIX regex、时间格式和固定进程/信号边界
  留 shared platform，逐处说明前提。相同 libc 符号使用一致 ABI，不用 allow 压警告。
- ubusd 的 ACL、随机 ID、队列、断连和 framing 保持原位；接收 FD 的唯一 ownership
  与内核截断关闭行为维持原契约。procd 保留 fork/exec、PID1、watchdog handover
  与升级模型，不以自执行替换，不另造通用 fork 证明机制。

源码计数不是安全证明；diagnostic examples 与必要启动 ABI 单列，不伪称整个依赖图
没有 unsafe。最终编译必须实际通过根上的禁令，目标警告必须由真实 SDK 数据证明。
