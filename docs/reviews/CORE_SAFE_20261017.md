# 九组件警告与安全边界清理

**9 个组件及共用 ubus 库的业务源码已设置 forbid(unsafe_code)，静态扫描 unsafe 为 0；编译和运行资格尚未完成。**
工作树 `owrt-core-safe-20261017`、分支 `research/core-safe-20261017`，从 dnsmasq
受限 fork 产品 `a97edbc1` 的后续工具提交建立。main 和路由器生产状态未改。

## 范围与顺序

组件为 uci、reload-config、logd、httpd、fw4、rpcd、ubusd、netifd、procd；共用 ubus
库一并清理。只接入一个共享 `components/platform` crate，新增第三方库固定为
rustix 1.1.5，保留既有 TLS 等依赖版本。先完成共用接口，组件并行修改，最后合成
单一候选统一验收和发布；不逐组件发版，本任务当前不部署。

Oracle 和路由器优先完成独立 dnsmasq v0.2.2 的 PGO、正确性及既定 40/148 批次。
这条链由 Oracle/device 子代理顺序推进，只向主代理报告结果或失败。九组件先编辑、
审查和准备测试；独立 GitHub runner 可执行统一编译，不占用这两台测试机器。
Mac 没有执行 Rust 构建或测试，只作编辑、git 和格式/语法检查。

## 实现边界

- 共用 ubus 保留 deadline、取消、部分读写、背压和 framing；普通管道/socket 使用
  rustix。数字 FD 快照、poll/epoll teardown、精确 20 B 单 FD SCM_RIGHTS 的最小
  ABI 留在 platform，不把可能无效的整数伪造成 BorrowedFd，不增加 payload 复制。
- uci 的读写/目录筛选和 CLI 逻辑在安全 library 中。fw4 也将规则/CLI 逻辑放入
  forbid 根。两者原 libc `main` ABI 保留为各自 `platform/entry.rs` 的薄二进制入口，
  不引入 Rust runtime prologue，不改变继承 SIGPIPE、原始 argv 字节或既有启动成本。
- httpd 保留 parked socket/线程交接、短读写、HTTP deadline、TLS/CGI 状态机；
  logd 保留环形缓冲、批量输出、断连和流式背压；reload-config 保留取消和锁语义。
- netifd/rpcd/procd 的协议与服务策略保持原位。owned FD、netlink 和一般 syscall
  使用 rustix；少数 ioctl、NSS、syslog、POSIX regex、时间格式和固定进程/信号边界
  留 shared platform，逐处说明前提。相同 libc 符号使用一致 ABI，不用 allow 压警告。
- ubusd 的 ACL、随机 ID、队列、断连和 framing 保持原位；接收 FD 的唯一 ownership
  与内核截断关闭行为维持原契约。procd 保留 fork/exec、PID1、watchdog handover
  与升级模型，不以自执行替换，不另造通用 fork 证明机制。

源码计数不是安全证明；diagnostic examples 与必要启动 ABI 单列，不伪称整个依赖图
没有 unsafe。最终编译必须实际通过根上的禁令，目标警告必须由真实 SDK 数据证明。

## 统一验收

1. 各组件、共用 ubus/uci/platform 的既有 host tests；platform 的进程全局 signal
   测试串行，保留原语义，不新增测试启动框架。所有实际编译使用 -Dwarnings。
2. 保留原六包 SDK recipe、三个 standalone core recipe 及各自固定绝对路径；
   检查 target ABI、ELF/package、原始日志。Rust/Cargo/linker/未知 warning 失败，
   已知 SDK 配置元数据提示单列。
3. 机器资源释放后跑既有完整差分、集成和隔离真机性能。procd 重点是 PID1/回收、
   信号/启动失败、watchdog 最后 close 和 sysupgrade；ubusd 重点是 FD 传递/截断/
   泄漏、背压、ACL 与断连回收。保留失败，按具体原因修复，不择优重跑。
4. 共用 ubus 输入变化会改变整合版本的 dnsmasq 源身份。独立 a97 的 PGO/通过项
   不自动授给整合候选；统一版本必须绑定自己的实际源码、profile、产物和验收。

当前不声称编译警告已清零或性能不退化；这些结论等待统一构建与测量。

### 两个新增窄边界回归（待 Linux 执行）

- `platform::ipc::tests::two_rights_keep_first_and_close_truncated_descriptor` 用 typed
  rustix 一次发送两个 pipe writer；20 B 接收区只交付第一个，第二个 reader 立即 EOF，
  第一个仍可写，drop 后其 reader EOF。全程非阻塞，无 sleep、无新 unsafe。
- `watchdog::tests::inherited_watchdog_exec_flags_and_final_close` 在仅运行该 test 的
  子进程内交接 pipe，避免污染并发测试的环境；断言原 FD 号不变、WDTFD 已移除、
  CLOEXEC 开/关/恢复后的真实 shell exec 可见性，以及 `X` 后唯一 `V`、writer EOF。
  随后重用原 FD 号，drop watchdog 不得关闭新 owner。这不打开 `/dev/watchdog`。

两项都进入既有 `cargo test`，无需新 runner；可以用精确 test 名单独运行。Mac 仅做
rustfmt 解析和 diff 检查，没有运行 Rust 测试。它们覆盖 FD 所有权和 exec 标志机制，
**尚未替代 `sysupgrade::exec_upgraded` 失败分支的完整 PID1 验收**；该分支需在已有
`native_trial_handoff_check.py` 的私有 namespace/inert recorder 中补开普通文件的
WDTFD、故意缺失 upgraded，再观察恢复后的环境/CLOEXEC，不能在测试宿主直接 chroot。
当前保留这一明确未验证项，不把普通成功 exec 或算术单测算作该路径通过。
