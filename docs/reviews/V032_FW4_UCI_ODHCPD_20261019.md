# v0.3.2 fw4、UCI、odhcpd 边界修复

仅 Oracle Linux 回归；没有设备写入、部署或 Rust 本机构建。
证据目录：Oracle `/home/ubuntu/v032-root-fixes-20261019/`，本地保全于
`private/review-v032/fw4-uci-odhcpd/`。匹配源码身份见
`manifests/ax3000t-stock-openwrt-25.12.5/source-baseline.json`。

## fw4 锁文件打不开

模型与预测：`Option<Lock>` 让失败继续进入 nft，缺陷在入口失败边界；把锁设为目录，
C 应退出 1 且不调用 nft，旧 Rust 应仍执行 nft。测量是退出码、子进程记录与状态文件
是否保留，不依赖时间噪声；健康锁是阳性控制。修复要求失败立即退出，不能以仅失去
reload 缓存优化来降级。

匹配 firewall4 `b6e51575` 的 `root/sbin/fw4`：start/reload/stop/flush 均在
`1000>$LOCK` 重定向内执行。目录导致 shell 在进入语句块前失败。Rust 的锁获取现在
必须成功，open/flock 错误退出 1；仍持有文件直到动作结束。

`components/fw4/tests/lock_failure.py` 在独立 mount namespace 内运行提取镜像的
BusyBox/fw4 与 Rust，nft 为只记录参数的夹具。4 个动作各 4 轮：修前 C 16/16 拒绝、
Rust 16/16 错误执行 nft；修后 C/Rust 拒绝与 Rust 健康控制共 **48/48**。
同时验证失败不删除已有 state。证据 `fw4-lock-expanded-red.json`、
`fw4-lock-green.json` 含 ELF/脚本哈希。组件测试 **19 passed**。
未模拟实际并发规则损坏；flock 系统调用错误路径由控制流保证，本轮故障注入针对 open。

## UCI reorder 溢出

模型与预测：共享 `strtoul_int()` 的 wrapping 乘加在 `ULONG_MAX+2` 变成 1，
而匹配 UCI `66127cd7` 的 `cli.c:521`、`delta.c:231` 都使用 `strtoul()`，
先饱和为 `ULONG_MAX`，再转换为 int。负号不改变溢出时返回 `ULONG_MAX` 的规则。
按精确目标 aarch64 的 64 位 unsigned long 处理；未改变正常整数的低 32 位转换。

`components/uci/tests/reorder_overflow.py` 比较提取镜像的 C CLI 与 Rust，12 个数值
覆盖普通值、尾随字符、32 位转换、64 位正负边界及 128 位十进制文本；CLI 与
保存的 delta 两入口各 4 轮，共 96 个完整退出码/输出/delta 对照。
修前 **80/96** 一致，修后 **96/96** 一致；证据 `uci-reorder-{red,green}.json`
含 C/Rust/库哈希。直接转换回归覆盖因最终 section 顺序相同而可能被端到端掩盖的值。
组件测试 **50 passed**。没有修改文件提交/回滚语义。

## odhcpd DNS option 与完整 UDP 回复上界

模型与预测：4096 个 IPv6 DNS 地址占 65536B，16 位 option length 回绕为 0；
4094/4095 个地址虽然 option length 可表示，但完整回复已经超出 UDP payload。
匹配 odhcpd `5d7be43f` 的 `src/dhcpv6.c:472` 同样将
`dns_addrs6_cnt * sizeof(*dns_addrs6)` 传给 `htons()`，iovec 仍携带完整地址数组。
这是继承的配置边界，不能声称是 C 独有保证或本轮运行过 C daemon 的网络差分。

修复只增加两个检查：DNS option 超过 65535B 时在租约变更前拒绝；最后完整回复
超过 65527B（IPv6 payload 上限减 UDP header）时不返回可发送报文。正常配置保持
原响应，超大配置明确采用拒绝，不截断 DNS 列表。

`components/odhcpd/tests/dns_option_bounds.rs` 由真实 UCI 导入 1、4093、4094、4095、
4096 项 DNS，实际调用 engine 并完整解析合法响应的每个 option；4093 项返回
65526B，为此 Information Request 布局的最大合法 DNS 个数。
四轮红均记录 `(4094,65542,65504)`、`(4095,65558,65520)`、`(4096,65574,0)`
（配置数、报文总字节、wire option length）；四轮绿均接受前两种合法配置并拒绝
后三种。证据 `odhcpd-dns-all-bounds-red-{1..4}.log`、`odhcpd-dns-green-{1..4}.log`。
最终组件测试 **79 passed / 2 ignored**。属于管理员极端配置与协议引擎验证，
没有发送接近 64KiB 的物理网络报文，也不把它当作配置内存分配总量上界。
