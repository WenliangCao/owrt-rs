# R125 八接收者剩余差距：先定位

R124 固定实机系列中，单接收者与无匹配事件已取得下降方向；八接收者的耗时中位仍高于 C 约 2%，
client CPU 也高约 2%。低连接第 9 窗口存在 −41.09% 耗时比值，身份与 payload 均有效，保留且不预设原因。
不据此再换容器或控制流；本步骤只扩展 R121 的精确 ELF 采样到八接收者。

沿用原版 libubus v3 ACK helper、cpu-clock 499 Hz、无 callgraph、精确 ELF map/dynamic symbols。
给行计划增加可选 listeners（默认 1，仅允许 1/8），收发断言相应按 n×listeners 计算；
不改变历史默认语义。工具哈希变化明确记录，旧证据仍使用其原工具身份。

对象只有精确 C 和 R124，不重建性能二进制。低连接/64-held 各两个反序比较块，
合计八个正式 Oracle 采样窗；每窗 n=100000、warmup=5000，listener=8。
另先用 n=1000、warmup=100 的 C/R124 两个短窗验证新计数断言，排除出正式数据。
每窗 daemon CPU1、caller CPU0，统一 argv0。无丢样/throttle/身份异常，否则停止保留失败证据。
JSON 与确切工具/ELF身份在采样前冻结，不追加直到获得某种热点排名。

报告已解析符号的平坦样本及未知部分，不把单符号比例当成整条算法的收益上限。
这是 daemon profile，不能据此直接解释 client CPU 差距；若仍不能定位，就明确记录这一限制。
Oracle 结果只用于选择下一项可反证假设，不是路由器性能结论。本步骤不产生运行时改动。
