# R124 当前 ubusd 实用前沿判断

R124 ELF `42435a31e2917186fb353e2c70143f4b3f6d82ec3dd53265bf6d826897b69926` 是目前最适合作为继续集成和最终候选基线的版本。这个结论来自当前 AX3000T 的新实测，不能把 R89/R109 的历史数字拼接进来，也不声称证明 Rust 的理论极限。

性能占主要权重时，R124 在 R127 当前严格验证的路由器查询/调用矩阵中全部以较低耗时为方向：单对象约低 5.7%/6.0%，64/128 对象全量查询约低 32%–35%，四客户端全量查询约低 59%–61%，四客户端 invoke 约低 11%。恢复审计确认 R127 daemon 的 CPU1 和统一 argv0 已落实，但原报告 caller CPU0 的说法错误：客户端未显式钉核，也未保存其 mask。数值只适用于这组实际调度条件，不能作 CPU1/CPU0 隔离的实现归因。R124 的单接收者事件耗时约低 5.4%–5.9%，无匹配事件约低 4%；八对象同一连接的 fanout 仍约高 2%，所以不能写成所有事件场景全面优于 C。

开销占较小权重时，R129 的 64 个空闲连接快照显示 RssAnon/VmData 增量 R124 为 28/28 KiB、C 为 48/52 KiB；R124 的大事件驻留增量与 C 相同（32/256/768 KiB 分别 +36/+260/+772 KiB），但 VmData 基线多 4 KiB。R124 没有在这些测量中表现出更高的连接或大事件增长，PSS 不可用，故不把快照差当作完整内存胜出。

注册路径存在计量缺口：R128 原先声称 daemon CPU1、统一 argv0，但恢复审计发现自定义 workload 直接启动二进制，daemon/caller 均未显式钉核，C/Rust 的启动 argv0 也不同，raw 未保存 mask/cmdline。1 method/8-byte name 中位 mean 高 C 3.1%、16 methods 低 1.3% 的原值和异常/反向窗口全部保留；这些是未控制启动条件下的观察，不能再称为已确认的实现退步或优势。注册是否仍落后需要落实并记录启动条件的新比较。

R126 把不存在目标的回复检查前移，行为和路由器回归通过，但 Oracle 八对象 A/A 校准出现 +0.9618%（预冻门为 ±0.5%），因此没有把它带到路由器性能测试，也没有把 R126 合入 R124。R125 的函数采样没有给出可单独证明收益的下一项低风险改动；HashMap 小热点和发送合并仍是待证伪假说，不是可接受补丁。

因此当前版本选择为 **R124 作为 Rust 集成和后续九组件协同的候选基线，C 继续作为路由器生产回退**。这不是“全面优于 C”的宣称：已测查询、调用、单接收者事件和连接驻留达到目标方向，八对象 fanout 仍落后，注册有待受控重测。若要继续投入，应先修正注册测试的启动条件，再针对可反证的源码假说和实际业务权重研究，并补九组件协同矩阵；任何新改动都必须有独立 A/A 校准和路由器验证。R129 独立使用了归一化启动，80 份前后 status 均记录 daemon CPU1，不受 R128 的启动缺陷影响。

本判断范围是精确 OpenWrt 镜像、当前 AX3000T、已覆盖协议和负载。所有窗口结束后生产 PID 869 仍为精确 C，临时命名空间已清理。
