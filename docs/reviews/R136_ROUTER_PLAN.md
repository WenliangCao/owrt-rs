# R136：组合候选的路由器定向确认（测量前冻结）

只测试 Oracle 批次选出的 `combined`，不运行五候选实机矩阵。候选 ELF `ce3d1aa29e49a8ea51bb7afa2587846ccd7563aa4b7c983cf401a6b4d6de2330`；控制为匹配镜像 C 和 R134 `98d7ff9ddd04db45d9d71b8f7a4f317f193c3539752532c30f01075e0e7197c0`。主运行时尚未采纳，路由器生产始终为 C。

选择依据：Oracle 两组 CPU 对、两种调用者亲和性，共 20 分组的 mean 与 daemon CPU 配对中位变化均下降；有监听者的对象事件 CPU 下降约 4–6%。单项结果全部保留。raw sendmmsg 的 CPU 普遍增加，停止该候选的性能推进。这里不能推导实机收益，也没有证据称注册尾延迟已修复。

## 正确性前提

组合候选已有 55 项 SDK 单测，九个 examples 完整编译；Oracle 的七类 wire、六类 FD 和两项 ubusd 恢复门通过。FD 保留 R134 已显式记录的 read-ahead 契约，不能宣称任意 handcrafted sender 都与 C 同义。实机先重跑七类 wire 和六类 FD，任何健康或清理失败停止。

## 一次确认，固定八窗

- 每窗包含 C、R134、候选，端点顺序正反交替；R134 固定居中。复用已验证的隔离脚本、原版 libubus 调用者及保护驱动。
- 五条负载：1/16 方法对象注册；1/8 监听者对象事件；不匹配监听者。每条 10,000 次，预热 20 次。
- daemon 固定 CPU 1，caller 可运行 CPU 0–1；相同 argv0、socket、默认 ACL、同一启动周期；每窗检查九组件身份、配置、挂载和清理。
- 独立使用本轮八个配对；不拼接 Oracle 或历史数据，不看结果追加窗口或重跑失败窗。
- 全量报告 mean、p50、p95、p99、daemon CPU、caller CPU，两个控制、每个窗口的变化均公开。

## 决策

以同窗候选/控制的百分比变化中位数作描述：低于 −1% 且至少 7/8 窗下降记 win；高于 +1% 且至少 7/8 窗上升记 loss；其余未分辨。±1% 为工程平手带，不是经过 A/A 证明的等效区间，也不声称多指标统计显著。

主指标预先选择 **8 监听者对象事件 mean 相对 R134**：中位改善超过 1%，至少 7/8 窗下降。它在 Oracle 四个分层均有结构对应的延迟/CPU 改善，符合用户以性能为主的权重。候选还必须在五负载的 mean/p95/p99 中没有相对 R134 的描述性 loss；CPU 节省不能抵消已检出的延迟退步。其他指标全部披露。

通过只表示值得在 R134 上采纳这三个小优化并完成受影响范围验证；不等于九组件整体完成、所有性能指标优于 C，或语言极限已证实。未通过则保留 R134，不对同一改动换编译布局反复摸奖。本轮不另造加权分数，也不把未检出退步说成证明没有退步。
