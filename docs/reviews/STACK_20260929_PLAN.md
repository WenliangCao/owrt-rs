## 冻结的正式设计

三个顺序窗口：stock-1、rust-1、stock-2。每窗口先执行已有冷启动流程，连续客户端健康至少 180 秒，再做最终 30 秒观察；确认全部九组件身份后执行同一套采集。

| 负载 | 每窗口设置 |
|---|---|
| 客户端 HTTP/HTTPS | 3 轮；普通负载每轮 400 请求；每连接预热 4 次 |
| LAN 负载集合 | HTTP 静态 c1；TLS1.2 静态 c1/c4；TLS1.2 授权 UCI RPC c1/c4；新 TLS1.2 连接 c1；相同 AES256-GCM 套件静态 c1 |
| 新连接 | 每轮 100 请求、20 starts/s，保持原防火墙 SYN 限制 |
| 路由器查询/HTTP | 3 轮，每 lane 2000 次；四客户端混合每客户端 2000 次 |
| 短命令 | 每轮 UCI export 100 次、fw4 print 30 次；保持原有预热 |
| 空闲资源 | 主负载前后各 120 秒，每秒快照 |
| 无变化 reload_config | 每轮 20 次、预热 1 次 |
| 真实配置变更链 | 每轮 10 次、预热 1 次；只改新建的 owrtstackprobe 配置。保留真实 commit/存储、默认 1000 ms trigger 延迟；5 ms 轮询直到服务回调实际读到新值，5 秒截止。完整事件次数/顺序另核验 |

所有窗口使用同一工具、相同设置和负载顺序；不根据胜负加轮、删慢窗或改门槛。每侧只有一个 Rust/两个 C 启动窗口，轮内请求不是独立启动样本。结果用于有界工程对照，不作长期稳定或全面统计显著声明。C₁、C₂分列，并展示 Rust 相对两者的变化；前后 C 差异不能被平均值隐藏。

记录 mean/p50/p95/p99、吞吐、成功/错误、细粒度进程 CPU 时钟、短命命令树 getrusage、调用者 CPU、整机 CPU tick、MemAvailable/缓存/slab、各守护进程 RSS/Anon/fd/线程、温度、存储、启动恢复时间。混合负载仅使用一个外层 CPU 区间，不重复相加各 lane 的重叠计数。整机 CPU 包含路由器内测量客户端；该成本与控制面成本分列。边界内存快照不冒充连续瞬时峰值，RSS 合计不等于独占物理内存；真实最近日志的正文会随实现变化，不能将 log read 差值全归因于算法。

## 回退与终态

启动保留原 900 秒未确认回退；Rust 采样另有独立 1800 秒设备端 lease。确认启动不解除整个试运行的 lease。定时器只覆盖到达 init 的系统，早期 PID1 失败仍依赖已核验离线救援。临时计时器的资源属于测量环境，不能隐去。
