# R134 ubusd：实机验证完成，仍有注册慢尾

冻结候选 `98d7ff9ddd04db45d9d71b8f7a4f317f193c3539752532c30f01075e0e7197c0`（518,867 字节）。本轮没有再改运行时；性能和内存结果均来自 AX3000T 上隔离测试，生产始终是 C。Oracle 结构诊断另行标注，不混入实机性能结论。

结论：按性能优先的取舍，R134 值得保留为继续工作的基线。18 条负载的平均延迟和 daemon CPU 中位数都降低，并满足预定至少 7/8 对同向的规则。但注册相关仍有 5 项明确的尾延迟退步，不能称“全面胜 C”“没有 bug”或“已达 Rust 语言极限”。本轮补齐的是当前基于 R131 的 R134 候选，未做新的 R89/R131 同场性能排名。

## 内存

每个夹具 C/R134/R134/C 四窗，各侧两次。以下仅为描述性快照，不是峰值或统计优势；PSS 不可用。VmRSS 包含共享映射，不能把进程 VmRSS 的下降当作整个系统节省同样多内存。

64 连接相对于各自同一进程的连接前样本，匿名增长 C 48 KiB、R134 32 KiB，即 0.75/0.50 KiB 每连接。本次生产总线快照有 16 个已连接 socket；不能把 64 连接压力条件当日常规模。

单监听者大消息 32/256/768 KiB 的匿名新增驻留两侧同为 36/260/772 KiB。小包八监听者扇出仍有代价：1 KiB 负载的 held 相对 connected，R134 多增加 12 KiB RssAnon 和 28 KiB VmData；尽管绝对 RssAnon 是 C 80/R134 64 KiB。断开后相对 empty 的匿名增量是 C 4/R134 20 KiB，不能宣称所有内存增量都胜过 C。

主矩阵结束时仍持有 128 个对象，RssAnon 为 C 144/R134 136 KiB，VmRSS 988/592 KiB；这个快照不是空总线基线。

## 正确性、边界与状态

55 项实机单测、21 份协议记录、18 个 FD 案例、8 个事件/背压案例通过；所有性能/内存窗口完成结果校验及清理。恢复门、二进制身份、原始归档也已核验。测试脚本曾有失败退出码吞没、手工 FD 仅报告不断言、缺收集器哈希字段三项问题，均单独修复并保留失败/补验证记录，未据失败尝试发布性能结论。

R134 保留一项明确 FD 契约差异：手工多帧附描述符不保证与 C 归属相同；镜像发送方常用的逐帧模式通过差分。ID 使用 RandomState 带密钥计数哈希，保留保留值与冲突重试，不宣称密码学随机性等同 C。详细边界见 [合同](../contracts/ubusd.md)。

本轮验证已完成，但 ubusd 的全面胜 C 目标尚不能结案：注册慢尾未解决，也不能把本系列推成 R89/R131 排名、长期稳定性或九个 Rust 组件共同运行的性能保证。下一步有明确对象：先针对注册慢尾做可区分机制的诊断，再决定是否值得改候选；不盲试接收控制流变体。

最后核验：九个生产组件仍是精确 C，ubusd PID 869、boot 与原配置保持一致；测试目录和测试进程均已清理，候选未部署。
