# v0.2.3 刷机前单轮 A/B：停止发布

**fw4 变化 reload 墙钟中位数 70.57→91.12 ms（+29.1%），首次 start
25.71→39.01 ms（+51.7%），退化超过事前冻结噪声，因此停止 v0.2.3 发布和刷机。**
不变 reload 明显更快，netifd 相同续租 CPU 571.69→415.15 µs（−27.4%），
但收益不能抵消其他项目失败。现网保持 v0.2.2；没有追加优化、重测或 PGO，
也没有开始 odhcpd-rs。

## 结果与判定

唯一真机批次完成于 **363.41 s**，未触及 600 s 上限。五种 fw4 场景各 14 次：
每版 3 次校准、4 次正式；netifd 8 对事件：3 对校准、5 对正式，约 30 s 轮距。
下面均为正式样本中位数，fw4 CPU 包含已回收的 nft 子进程，不含独立 ubus/provider。

| fw4 场景 | v0.2.2 墙钟 ms | v0.2.3 墙钟 ms | 墙钟变化 | v0.2.2 CPU ms | v0.2.3 CPU ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 不变 reload | 78.775 | 22.046 | −72.0% | 23.897 | 21.138 |
| 变化 reload | 70.569 | 91.124 | +29.1% | 23.682 | 38.333 |
| 首次 start（空规则/state/cache） | 25.707 | 39.009 | +51.7% | 23.273 | 37.404 |
| check | 58.707 | 55.705 | −5.1% | 22.088 | 22.349 |
| print | 7.334 | 7.252 | −1.1% | 5.838 | 5.742 |

按[事前冻结计划](V023_DEVICE_AB_PLAN_20261017.md)，每项分别使用
`N = max(A 校准极差, B 校准极差, 2×仪器量化)`；任一正式配对 `B−A > N`
即停止。不是仅凭上表中位数判断。

| 越界指标 | 噪声 N | 正式配对 B−A | 越界对数 |
| --- | ---: | --- | ---: |
| 变化 reload 墙钟 | 20.200 ms | +21.376、+20.053、−10.011、+39.638 ms | 2/4 |
| 变化 reload CPU | 2.920 ms | +14.874、+15.158、+13.011、+14.537 ms | 4/4 |
| 首次 start 墙钟 | 0.815 ms | +13.592、+13.191、+13.141、+12.696 ms | 4/4 |
| 首次 start CPU | 0.768 ms | +14.188、+14.317、+13.975、+12.907 ms | 4/4 |
| check CPU | 0.543 ms | +0.293、+0.563、−0.040、+0.102 ms | 1/4 |

check CPU 的一次越界仅超出 N **20 µs**；这是一轮保守筛查中的边界失败，不能
据此单独断言稳定退化。变化 reload/首次 start 的 CPU 四对均明显变慢，已经足以
作出停止决定。其余 fw4 指标未越界；print 的小差异处于噪声内，不声称存在收益。

netifd 的单事件 CPU 含回复后固定 1 ms 的处理尾部，中位数 **571.692→415.154 µs**。
五对差值为 **−125.155、−269.231、−162.153、−130.385、−155.385 µs**，
校准 N 为 **107.230 µs**；五对均改善且超过该噪声。两版各八个独立 idle floor
都是 0 ns，没有从事件 CPU 中扣除；最大实际起始迟延 63.981 µs。

## 仪器、行为与边界

使用[计划中的四份精确 ELF](V023_DEVICE_AB_PLAN_20261017.md)，路由器上传后逐文件
校验，逐样本再校验被测 ELF。只在私有 mount/net/PID/IPC/UTS namespace 中运行，
根只读，配置、ubus、接口和 nft 状态独立；没有改生产服务、规则、接口、调频或
CPU affinity。netifd 的 WAN 是由私有 UCI 管理的无端口空桥。

fw4 每次恢复独立初态，计时前固定安静 1 s。真实 nft handles 验证全部通过：
不变 reload 的新版保留规则及 flowtable，旧版重建；变化 reload 两版都重建并安装
新端口；start 两版从空规则安装；check/print 不改规则。netifd 两版都保持相同的
真实内核地址和默认路由。初始安装、恢复、状态验证均在计时外。

fw4 直接 fork/exec/wait4 的六次 true 地板：墙钟 1.423–1.558 ms、中位 1.484 ms；
CPU 1.258–1.333 ms、中位 1.289 ms。没有扣除。netifd 采用目标守护进程的 POSIX
CPU 时钟，分辨率 1 ns，不含 ubusd、客户端或子进程，也没有退回 100 Hz tick。

“首次 start”是首次防火墙状态，不是物理重启或清空 CPU/page cache 的测量。
空桥/私有 ubus 没有真实转发流量，所以这些数字不等于整机开机联网时间。fw4 的
墙钟包含内核提交等待，CPU 与墙钟因此分列。实际生产的自然续租/重载继续运行，
校准与交错配对反映其调度噪声；不据本轮外推所有负载下的性能。

Oracle 只做仪器功能预检，没有用于性能筛选。预检曾因手工创建、未纳入 UCI 的
空桥被 netifd 初始化清理而失败；在产生任何真机样本前修正 fixture，旧记录保留。
真机只有这一批，样本完整，无重试、补样或挑选。所有沙箱已停止并删除自有临时目录。

## 当前模型与下一步

不变 reload 的主要收益是省去 nft 提交及等待；其 CPU 只降低 11.5%，墙钟降低
72.0%，说明墙钟收益不能直接解释为等量 CPU 节省。新版实际提交路径增加了
GETGEN、有效输入检查、`nft -s list table` 快照和缓存写入；代码路径与两种提交
场景约 14 ms 的 CPU 增量方向一致。本轮未做分段 profile，不能把全部增量精确
归因于其中一个步骤。此前“其他路径差异在噪声内”的预测已被推翻。

按用户停止条件，本轮到此结束；保留实现、测试证据和候选镜像，不执行最终恢复
资格检查、刷机、发布或 odhcpd-rs 开发。后续取舍留待用户决定，不自动缩减版本
范围，也不启动第二轮优化。

前后 boot、十组件运行身份完全相同，配置及受保护文件哈希不变。客户端 en0 的
TCP DNS A/AAAA、直连 IPv4/IPv6 HTTPS，以及路由器接口、两频 AP、本地服务和
watchdog 均通过。沿用已记录的客户端 UDP DNS 限制，没有把 TCP 通过写成 UDP 通过。
