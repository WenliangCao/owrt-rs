# R139：原始 caller 复现注册慢尾，同核缩小相对差但未修复绝对尾延迟

**四窗共 24 case 全部完成且通过证据校验。** 使用原全矩阵 caller `0ca42fb…`、
精确 C 与 R136；每 case 新 daemon、1 方法 ADD/REMOVE、10,000 周期、20 预热。
daemon 始终 CPU1，只有 caller 放置变化。没有部署或修改生产设置。

原 CPU0–1 allowance 下，R136/C p95 的四个配对变化为 **+22.988%、+24.589%、
−22.273%、+14.262%**；中位 **+18.625%**，3/4 上升，达到预冻结的复现门。
原 R136 四项正式负值不撤销。

caller 固定 CPU0 后，p95 差距中位仍为 **+16.355%**、4/4 上升；相对原 allowance
的差距变化为 **−2.270 个百分点**、3/4 下降，未达到 10 个百分点的交互门。
caller 与 daemon 同在 CPU1 时，差距中位为 **+0.420%**；交互中位
**−14.806 个百分点**、3/4 下降，达到预冻结的放置敏感门。
这只证明本诊断中的相对差距对放置敏感，不能确认某个内核机制。

## 证据与边界

[分析器](../../tools/r139/analyze_affinity.py) 校验冻结输入、归档与展开文件、四窗
同 boot/stock 健康状态、六项清理门、精确 ELF、fresh daemon PID/starttime、前后
argv/CPU mask、空对象和全部 caller 退出码；24 份原 latency 的 mean/p50/p95/p99
均重新计算，daemon CPU 按 process-clock 前后快照复算，无 tick 回退。

原 caller 没有自身前后 context/CPU 位置快照；其 CPU 只有有效正时钟差，无法
独立用 before/after 重建。固定 mask 的证据是精确 helper 的前置执行校验、父
shell allowance、完整启动 argv 与成功退出，没有计时中 live mask 或迁移轨迹。
daemon context 只是窗口边界计数，未以 wall 减 CPU 估计等待。
