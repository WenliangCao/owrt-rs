## 行为边界与验证

此次明确升级的安全行为不以 25.12.5 的宽松响应为通过条件：100/101 字段、
16384/16385 字段字节、非法名字、chunk whitespace/扩展、LF 分帧、
受保护 `/ubus` 路径及 scalar params。历史 300 字段成功用例属于旧版合同，
不能继续要求当前候选成功。LF-only 的请求头兼容性仍保留；chunk 分帧使用 CRLF。

新增/更新的回归覆盖：

- 字段预算边界、前导空行、每条 pipeline 独立预算、共享 trailer 字段和字节预算。
- 嵌入 CR、非法字段名、合法特殊 token、OWS 与非 ASCII 值边界。
- 空/带符号/前缀/空白/溢出 size，合法和非法扩展，各分帧处 LF 拒绝；
  已有任意输入切分恢复用例继续适用。
- 真 TCP `/ubus`、list、subscribe、call、query 路径的 Basic challenge、错误凭据、
  正确凭据和相邻不匹配前缀。
- Unix socket ubus fixture 确认各种非对象 params 和 session 注入不会发 INVOKE，
  正常空对象仍能发一次调用并返回正确 JSON-RPC envelope。
- 相对/绝对 symlink、普通文件、链接链的一跳 MIME 行为。

运行结果：oracle Linux 的 `mbx test --locked --manifest-path components/httpd/Cargo.toml --tests`
通过 67 项，0 失败。`mbx clippy --locked --manifest-path components/httpd/Cargo.toml --all-targets`
通过，无源码诊断；顺带清理三处既有冗余借用/转换。新增文件与 socket fixture 使用唯一目录、
`create_dir` 和作用域析构清理，失败也不留下影响下次运行的残留。
`mbx build --locked --release --target aarch64-unknown-linux-musl
--manifest-path components/httpd/Cargo.toml` 成功；使用任务中的 25.12.5 SDK 链接器作诊断候选，
不是 25.12.6 SDK 发布构建。最终通过任务私有 SDK wrapper 构建，未更改原 SDK，
无 linker warning。`mbx explain --last` 已记录缓存命中/未命中原因。

[`tools/test_httpd_25126.py`](../../tools/test_httpd_25126.py) 在各自独立的 mount/network/PID
namespace 中使用一次性 rootfs 副本，启动镜像内的 ubusd/rpcd/uhttpd 或 Rust 候选。
每侧 45 个场景：35 项状态、选定头和正文的规范化精确比较一致；10 项非法 chunk、
trailer pipeline、未读 body 安全不变量通过。每项要求连接终止，非法分帧不执行隐藏请求，
合法 trailer 后的下一条请求正常执行。最后健康检查通过。参数用例对真实镜像的 session
对象执行，并确认返回 -32602。未测吞吐或时延，不从沙箱结果推断真机性能。
