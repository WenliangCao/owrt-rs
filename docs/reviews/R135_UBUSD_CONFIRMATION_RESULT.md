## 能说什么，不能说什么

四窗诊断使用旧 ELF `df483ee2116acd910fac614220e061b08858c710a138e60b9bd0eb4cd05321e0`；正式验证使用与实际源码相符的新 ELF `c6f002dad50f4cc7fbe6e19738246a4c55e20aa82285272ec81f0b133f403615`。两者的源码只差三行 doc comment，但实际指令布局不同。**本次正式否决针对新产物**；不能把跨轮差异直接归因于注释、代码布局、亲和性或某项内核调度机制，也不能据四窗结果宣称旧 ELF 已完成独立确认。原 R134 的已确认慢尾仍未解决。

新产物自己的前置检查通过：55/55 Oracle release/musl 单测、七个三方 wire transcript、六个 FD 案例、两个限定 ubusd recovery。手工附 FD 仍遵守已有 read-ahead 契约，不强称与 C 完全一致。旧 split 通用恢复套件的范围外 C netifd 失败依旧保留，未改写为整套通过。

Oracle 批量预筛已成为可复用工装：八因子组合加两个参照的 480 case 用约 96 秒，串行 96 case 用约 37 秒。它加快了候选筛选，但本轮说明服务器尾部排名不能直接代替实机，也不能用四窗探索结果取代独立确认。

没有宣称 ubusd 已达语言极限或全面胜 C。后续首先要守住精确 ELF 身份，避免把代码布局变化与算法效果混为一谈；另一个尚未实现的方向是对两条独立小回复使用 sendmmsg，相关短写语义已查上游 Linux 6.12.94，但仍须核对镜像内核补丁并验证实际收益，不能先当成修复方案。
