# R136 组合候选通过路由器定向门；注册慢尾仍保留

八个预冻结实机窗口已完成并独立核验。精确 C、R134、combined 三侧各五条负载，每条每窗 10,000 周期，共 **120 case**。原始归档与展开文件一致，身份、亲和性、健康和清理检查通过；生产继续运行 C，未部署候选。

**本轮采纳门通过。** 主指标 event_8 mean 相对 R134 的八窗配对变化中位数为 **−3.49355%**，7/8 窗降低；五负载 mean/p95/p99 的 15 项护栏没有达到预定的描述性 loss。对 R134 的全部 30 项为 **8 胜、0 负、22 未分辨**；对 C 为 **20 胜、1 负、9 未分辨**。

明确的 C 负项是 **register_1 p95 +19.53488%，8/8 窗更高**。原有注册慢尾没有修复。0 个 R134 描述性 loss 也不等于已经证明无退步：register_1 p95/R134 +3.26205%、event_nomatch p95/R134 +3.92611%，都在 6/8 窗上升，只是没有达到冻结的 7/8 同号门。

验收按测量前规则执行：胜要求配对中位数低于 −1% 且至少 7/8 窗降低；负要求高于 +1% 且至少 7/8 窗上升；其余为未分辨。主门另要求 event_8 mean/R134 记胜；任何五负载 mean/p95/p99 对 R134 记负即拒绝，CPU 节省不能抵偿。没有改变规则、删窗、追加窗口或拼接 Oracle/R135 数据。

主指标八对变化依次为：−1.3472%、−3.7186%、−5.5330%、−3.2685%、+2.5890%、−0.3111%、−5.8276%、−4.1876%。保留上升窗口，未将其称作异常并删除。

## 调用者勘误与产物边界

冻结计划中的“原版 libubus 调用者”是文字误写。本轮实际使用统一的 **Rust `owrt_ubus::Connection` benchmark**，三侧均为同一个 `85dd537a070e39373a4a21a6bf982da9359bc70e61e53cdf93516b9c34684b1d`。计划和实测 ELF 身份一致，测量期间没有修改冻结文件；本轮不作原版 libubus 调用者性能结论。

本页结果属于实测 combined ELF `ce3d1aa29e49a8ea51bb7afa2587846ccd7563aa4b7c983cf401a6b4d6de2330`。**source02／主线 `195e45f` 已用原固定源码根和全新 target 逐字复现该 ELF**。先前不同 SHA 来自构建源码绝对路径变化；已测产物未被替换。后续复现须使用[已验证 recipe](R136_BUILD_IDENTITY.md)。本轮不同候选使用不同 work_root，路径引发的代码布局也是筛选混杂因素，不能把微小差距精确归因某个结构修改；精确 ELF 的实机对比仍有效。

三个运行时优化和两处 examples 接口同步已通过 `195e45f` 采纳到源码，最终 release ELF 身份核验仍单独待办。这不是 ubusd 完结、全面胜 C 或达到语言极限。本候选的完整性能矩阵和内存负载尚未重跑，本页也不覆盖九组件协同。±1% 是预定工程带，不是 A/A 证明的等效区间；这些描述性规则没有多指标显著性校正。
