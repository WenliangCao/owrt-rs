# R136 Oracle 批量预筛：只将 combined 送入实机确认

七侧（精确 C、R134、path、entry、strings、combined、sendmmsg_raw）已完成 **560 个测量**：两个互不重叠的 caller/daemon CPU 对、每对四块、两种 caller 亲和性、五条负载，每条 10,000 个周期、20 次预热。56 个 daemon 会话、2,188 个原始文件的哈希、实际参数、进程身份、亲和性、原始样本统计及清理通过复核。没有把两个 CPU 对池化成八次同核心重复。

**仅优先验证 combined。** 它把路径临时 Vec、重复 HashMap 查找及对象事件字符串临时分配三个独立方向组合起来。各 CPU 对、亲和性、负载的 mean 与 daemon CPU 配对中位方向均为负，尤其 event_1/event_8 的 CPU 改善较一致。这个结果只支持候选排序；注册 p95 改善很小、p99 仍有上升，不能据此说路由器慢尾已经修好。

**sendmmsg_raw 不送实机计时。** 它在每个 CPU 对/亲和性/负载分层的 daemon CPU 配对中位数都增加（约 +2.16%～+5.04%），mean 通常也增加。未使用个别 p99 下降抵消这些代价。其 syscall 原型与功能检查另有记录；本页只报告这一个精确 ELF 的计时。

单项也有实际代价：path 在 CPU 2/3 split 的 event_1 mean/p95 分别 +1.32%/+2.41%；entry 在 CPU 0/1 split 的 register_16 p99 +12.30%；strings 同一分层 event_1 p99 +10.56%，四块都更高。combined 没有全面优于每个单项，其 CPU 2/3 allowed 的 register_1 p99 仍 +3.83%，CPU 0/1 split 的 event_nomatch p99 仍 +4.69%。这些负项都保留，不能只展示 mean 和 CPU。

完整 [派生 JSON](r136-ubusd-oracle-results.json) 公开全部 **140 个分层、六指标、两个对照和逐块变化**，包括 228 个候选正中位数项（含未分辨带内的小增幅），以及 560 条不含 PID/机器路径的派生测量记录。没有删除任何窗口，未合并 R135 或路由器数据。

四个分配候选各通过 SDK release/musl 的 55 项 ubusd 单测。审计同时抓到了真实的构建遗漏：path/combined 改借用接口后，两处 examples 仍传 Vec；初次 path 全目标构建失败的证据保留。`251722b` 修正生成器，两种 source02 测试副本随后编译通过全部九个 ubusd examples 和单测 target；examples 没有被声称运行通过。缩减快照漏掉的共享 `profile_support` 只从基准提交复制到独立测试副本。source01 测量产物没有被替换。

路由器确认使用独立冻结计划：event_8 mean 相对 R134 的配对中位改善必须超过 1%，至少 7/8 窗降低；任一五负载 mean/p95/p99 出现预定的描述性退步即拒绝，CPU 节省不能抵偿延迟退步。该正式结果不包含在 Oracle 本页。生产仍使用 C，尚未部署候选。

Oracle 与路由器的硬件、内核、共享缓存和调度环境不同；本轮只用于缩小候选范围，不是已达语言极限、总体显著性、无回归或九组件协同优势的证明。原始材料位于 ignored `private/r136/screen-01/`；单测和 examples 编译证据分别位于 `private/r136/units-01/`、`private/r136/units-02/`。
