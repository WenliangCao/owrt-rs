# ubusd R89–R116 候选选择审计

日期：2026-09-22

这份审计把 R89 到 R116 的所有 ubusd 相关轮次放在同一张决策表中。性能数字只采用
AX3000T 路由器实测；Oracle、单测和源码阅读只用于定位与正确性，不替代路由器结论。
正确性是硬门。通过硬门后，性能权重 90%，CPU/内存等开销权重 10%。

## 判定方法

“性能优于 C”按已测工作负载分别看 daemon CPU、总 CPU、墙钟延迟和尾延迟；只要候选
依赖一个未覆盖的协议路径，漂亮的 CPU 数字不能进入最终候选。内存使用按常驻增长和
连接规模看，不能用单次绝对 RSS 代替规模曲线。R89 的完整矩阵和 R113–R116 的新一轮
结果不是同一夹具，不能把百分比直接相加；这里只比较各自报告明确覆盖的范围。

## 选择结果

如果必须从现有字面版本立即选一个，选择 **R89**。它是 R89–R116 中唯一同时具备完整
历史路由器性能矩阵、R88 修复后的功能/回退门、没有后来发现的 R94 读前缓冲 FD 缺陷，
并且在主要 ubusd CPU 负载上明显低于 C 的版本。R89 仍有 `lookup_all_64/128` 的延迟
反例，所以这个选择表示“现有字面版本中风险/性能最优”，不表示全面目标已经完成。

如果要求使用当前修复后的源码线，**R115 是正确性 frontier，R113 是更保守的基线**；
两者都没有满足“性能大幅领先 C”，不能仅因版本号更新而取代 R89 的实测结论。R109 的
性能冠军数字不能用于最终选择，因为它的 FD 语义已被反例否定。

## 下一项唯一值得做的实验

在 R115（R113 的 bounded prefix/body、R114 借用派发、R115 interest 条件）上做独立的
R117 小帧接收实验：prefix 仍用有界 `recvmsg`，收到长度后立即分配精确大小的 owned
`Vec`，后续 body `read` 直接写入该 Vec，并跨 readiness 保存 `got` 与 FD；完成时直接
移动 Vec，不再先写事件循环的 4096 字节 scratch 再 `to_vec()`。LargeFrame 已经采用同类
生命周期。这样保持 C 的 FD 边界和 ancillary discard 语义，只消除一次小帧 memcpy；每帧
仍是一份必要的 owned allocation。

R117 必须单独冻结和判定：先跑现有单测、FD wireprobe、六个主机门，再上路由器低量 pilot。
若 daemon CPU 没有同号改善，立即停止接收路径实验；不能再用阈值、`inline` 或 spare 的
控制流变体替代指令级定位。R117 通过前，最终建议是保留 C 生产运行、把 R89 作为历史
性能候选、把 R115 作为正确性开发基线。
