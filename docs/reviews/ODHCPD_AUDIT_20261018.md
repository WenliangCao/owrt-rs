## 共同既存边界与明确限制

真实内核多块地址 dump 在 1000 个合成地址并发删除时产生 `NLM_F_DUMP_INTR`
和缺项；共享 Rust transport 与精确 C 的 libnl-tiny 都没有拒绝该标志。因此保留
为既存一致性风险，不能称为 C 正确、Rust 新引入的回归。当前本机双前缀场景
没有该反例，本轮不扩展共享 netifd transport 或改变另外十个 ELF。未来若扩展
地址规模/高频并发变化，需要完整消费失败序列并重新取样；此限制没有被“功能
检查全过”消除。详见 RA/内核报告的真实内核证据与未覆盖边界。

审计还要求补足两条实际调用链：修改 UCI 后通过原 init reload 验证续租参数及
PID 稳定，以及 LuCI 的租约/功能发现消费者。`4c4339b5` 已加入精确镜像启动
夹具，等待新 ELF 运行。这些是功能回归，不是性能重测或新的物理试运行。
