# R113：FD 修复后的实机基线

候选 `befbb16` / ELF `8a00bc66…009b1` 保留共享栈和独立 Client 存储，
按精确 C 的 12 字节 prefix / 有界 body 接收，修正跨帧 FD 归属。
生产始终是 C；没有部署候选。

## 正确性

[实机结果](r113-correctness-results.json)：44 条单测、七组已有协议门和新增六种 FD
封包差分通过；[六组主机功能及恢复门](r113-host-gates.json)全部通过。
C 与候选的 FD 差分输出逐字一致，旧 R112 稳定触发三个已知失败。

[额外 Oracle 审阅](r113-additional-fd-audit.json)补了 prefix 第 1/6/11 字节才附 FD、
同一 prefix 两个 FD、小/大残帧 EOF、非法长度携 FD、大帧后续携 FD 帧，共九项 C/R113 对照。
第一次即时 EOF 释放探针出现失败，证据保留：socket EOF 并不保证其他字段的析构已完成。
改用有界的泄漏检查后九项均匹配；这不证明释放时延相等，也不算新的实机覆盖。

## 内存

[冻结计划](r113-memory-plan.json)的五侧正反顺序十窗口全部完成，50 个观测均核验
同一 status 快照、PID/启动身份、钉核、FD 数和断连回收；每窗口均清理且健康检查通过。
[完整结果](r113-memory-results.json)保留全部 0/1/8/32/64 连接观测和三个指标。

| 版本 | 64 连接 RssAnon 增长，两轮 KiB | 64 连接 RssAnon，两轮 KiB | 64 连接 VmData KiB | 断连后 RssAnon 增长 KiB |

| 精确 C | 48 / 48 | 120 / 120 | 96 / 96 | 8 / 8 |

候选每连接增长 0.4375 KiB，两次均通过预设的总增长 ≤38.4 KiB 门。
这项 HELLO/PING 长连接规模成本低于同轮 C 和 R89；不能外推到忙连接、峰值或整机内存。
无连接时 VmData 候选 48 KiB、C 44 KiB；64 连接断开后候选 56 KiB、C 52 KiB，
这两个 4 KiB 差距仍在。PSS 不可测，保持 NA；VmRSS 包含共享文件页，不能当作可回收整机 RAM。

## CPU 与后续

[CPU 诊断计划](r113-cpu-screen-plan.json)单独冻结：C/R89/R109 × low/64 held，
各两次换槽窗口，完整报告 daemon、caller、二者之和与 wall。这是重建基线的探索采样，
两窗口不足以判定约 1% 变化或等效性，不作最终接受结论。
FD 正确性要求增加了消费边界；R109 预读路径的性能优势不能沿用到修复版。
下一项候选仅研究借用入站派发，独立提交、独立门，不混入事件遍历或发送兴趣表优化。

C 的六个 lane/规模单元中，daemon CPU 两次均上升。尤其单监听者约 +14–15%，已远超先前追逐的约1%变化，当前版本仍未达到目标。
R89 这组事件工作负载的 daemon 和 total 两次均下降，但这不构成全部组件验收。
R109 对照的较大变化包含强制恢复 FD 消费边界的代价，以及 R110/R111/R112 的存储与服务循环差异，不能把整项差值归因给某一处代码。
两个窗口无法给出预设72比较族的有限秩置信区间；保留 null，不把交错顺序当作独立性证明，不选择有利的 caller/wall 结果替代 daemon 成本。
