# R94 HTTP 监听器内联快路径

2026-09-16。目标：让 httpd 在停放后（paced keep-alive）的每请求成本既优于 C 原版、也优于正式 R89。筛选在 Oracle Linux AArch64 私有 namespace loopback 上完成，终验在 AX3000T 实机（见「实机」节）。第一阶段候选 `d418b497`；第二阶段（紧密路径）第三轮 `55436dfd`、第四轮（最终）`16fa25d9`。均为 SDK musl 交叉编译、静态链接。

## 改动

1. **监听器内联快路径**（`components/httpd/src/fast.rs`，接入 `main.rs` 的 `accept_loop`）。一条已停放的 plain-HTTP keep-alive 连接，其就绪事件若携带一个完整的小 GET/HEAD 请求头、目标为普通可读文件（≤32 KiB，且不涉及 CGI/ubus/auth/alias/RFC1918/TLS-redirect 政策），就在监听器线程上直接完成：`MSG_PEEK` 探测 → 复用现有 `HeadBuffer` 解析 → 用同一个 `files::serve` 把完整响应生成到有界内存 → 精确消费已解析的头字节 → 非阻塞 `send`。socket 全程不离开 epoll 集合。

   这消除了停放请求原先每次都要付的：epoll DEL/ADD、线程移交（唤醒或新建）、50 ms 接收超时、8 KiB reader 重建。等价于 C uhttpd 在单个 uloop 上就地处理的稳定注册形态。

   所有其他请求整体回退到线程路径：在生成出完整响应之前不消费、不发送任何字节，因此回退路径服务的字节与快路径不存在前完全一致。短写时保留有界 `PendingReply`（每 listener ≤4），经 POLLOUT 排水，带网络超时。TLS、pipelined、请求体、错误页、所有解析失败都保持既有路径。

2. **请求头控制字符单遍 SWAR 扫描 + 按长度索引的头名表**（`http.rs`）。R92 的逐字节控制字符扫描在 R93 本地阶段剖析里占头解析 12–18%；改为每步 8 字节（对每个字节值、每个对齐位都与标量谓词逐一核对）。头名小写化先按长度分派，典型头至多比较两个候选。

3. **移除 R93 空闲 worker 缓存**。它在 keep-alive 连接安静后保留至多 4 个线程 1 秒，违反 R85/R93 内存合同（连接关闭后 Threads 必须回到基线）——这正是之前 worker/head 候选一直无法合入的原因。内联快路径已经以「零线程」服务了该缓存的目标场景（停放小静态），所以缓存对本目标是冗余的，只会拖累门禁。恢复为每活动连接一线程，停放的空闲连接仍只占一个描述符。

## 正确性门（Oracle，aarch64 原生）

8 个历史门全部 exit 0：`httpd-unit`、`httpd-clippy`、`httpd-resources`、`httpd-static`、`httpd-extended`、`httpd-r14`、`httpd-fuzz`、`httpd-cgi-stress`；另加 `shared-cap`、`http-r92` 均 exit 0。

- fuzz 133/133 通过，候选变更仅 `chunked-huge-size`、`header-ctrl` 两项 R92 既批准偏差——SWAR 重写未引入任何新偏差。
- `httpd-static` 含 64 连接空闲内存释放子测（曾令 worker/head 候选失败）现通过：fds 立即归零、Threads 在关闭后回到基线。
- extended 31/31、SSE 断开清理通过（Rust 保留 0 fd，C 保留 12）。
- 唯一的红是 `static-cold-memory`，因 `r93_httpd_worker_memory.py` 是仅存在于 Oracle 的私有工具、从未纳入仓库（FileNotFound），非候选缺陷；其覆盖的 64 连接释放已由 `httpd-static` 验证。

### 判定

停放（paced keep-alive）路径：优于 C 与 R89，完成。紧密（gap 0 连发）路径：优于 C、与 R89 持平，**未达「全面优于 R89」**，列为下一轮目标。httpd 整体暂不打勾。

## 第二阶段：紧密路径（gap 0，连接不停放）

实机紧密矩阵与 R89 持平的原因：R89→R94 的热路径几乎没变。Oracle 上 `strace -c` 显示候选与正式 R89 **每个静态响应都是同样的 10 个系统调用**，daemon CPU 约 80% 在内核态（user 4–5 / sys 18–19 µs，1 客户端）。要赢就得砍掉 R89 也在付的每请求内核工作，而不是找回退。

| 系统调用 | R89 | 去向 |
|---|---:|---|
| setsockopt ×2 | 2 | 头等待改用 `poll(2)`（`HeadDeadline::polling`）：装 SO_RCVTIMEO 与读完头后恢复各省 1 次，换 1 次 poll。TLS 保留原路径（rustls 可能持有 socket 无法示意的明文）。 |
| read ×2 | 2 | 只读 Content-Length 字节（`copy_from`），不再多读一次到 EOF。副作用是正确性改进：lookup 后变长的文件不再把超出声明长度的字节泄进下一条响应（uhttpd 有此 framing 缺陷；变短仍提前结束，同 uhttpd）。 |
| fcntl | 1 | musl 的 `open()` 在 O_CLOEXEC 后无条件补 `fcntl(F_SETFD)`（Rust std 走 `open64`）；直接调 `openat` 没有。 |
| openat + close | 2 | 每连接线程保留最近打开的文件：lookup 每次仍新鲜 `stat`，仅当 (dev, ino, ctime) 与打开时 `fstat` 记录完全一致才复用并 `pread`；替换、重写、截断、chmod、删除重建都会重开。随线程退出释放，停放/关闭的连接不持有文件（r85 fd 基线门通过）；监听器快路径不启用。 |
| recvfrom / newfstatat / sendto / (p)read | 4 | 保留 |

结果：**10 → 5**（ppoll、recvfrom、newfstatat、pread64、sendto，strace 逐项 1.00/请求）。同时 `lookup` 热路径 4 次堆分配 → 1 次（路径就地规范化、name 改为 phys 偏移、`Lookup::Found` 去 Box）。

Oracle（aarch64，1 客户端 40,000 请求，daemon utime+stime）：**R94 18–19 µs/请求 vs R89 22**（两次重复；ticks 74–76 vs 90–91）。四侧 pilot gap0 紧密档（4 客户端 20,000 请求）：**R94 27.0 vs R89 32.0 vs source05 32.5 µs**（−15.6%）；停放档 37.5/25.0 vs R89 275。

门禁（候选 `55436dfd`）：8 项历史门全部 exit 0，fuzz 133/133 仍只有两项 R92 既批准偏差，extended 31/31，`httpd-static` 的 64 连接 fd/线程回基线子测在 fd 复用下通过。

### 第三轮实机与 jsonrpc_c4 的回退

候选 `55436dfd`（poll 头等待 + fd 复用 + 单分配 lookup）实机紧密矩阵：12 条静态 CPU 低于 R89 8–21%、范围不重叠；但 **jsonrpc_c4 CPU 518.8 vs R89 471.2（+10.1%），范围不重叠**。该负载不走文件与 lookup，唯一新触及它的改动是 `poll(2)` 头等待：4 个连接线程加 rpcd、ubusd 争抢两个核时，`ppoll`+`recvfrom` 两次进内核的唤醒比一次阻塞 `recv` 贵，而 JSON-RPC 没有静态路径那些省下的 syscall 来抵消。停放间隔五档则全部低于 R89（gap0 173.5 vs 203，60/80 ms 205/210 vs 630/680）。

### 第四轮：固定 50 ms 接收超时，热路径零 poll

`http::Sock::new` 在 accept 时把 SO_RCVTIMEO 固定为 LINGER（50 ms），之后任何请求都不再改 socket 选项；读超时的含义由连接线程的 `ReadWait` 模式决定：头首字节 `Linger`（上报 WouldBlock → 停放）；后续头行与请求体 `Budget(剩余预算)`（超时后 `poll` 剩余预算再读——只有停顿超过 50 ms 的慢客户端才付这两个 syscall）；CGI 中继非阻塞段 `Passthrough`。TLS 的记录读经同一个 `Sock`。静态热路径：**recvfrom、newfstatat、pread64、sendto，共 4 个 syscall**（R89 为 10）。

Oracle（候选 `16fa25d9`）：1 客户端 40,000 请求 daemon CPU **17–18 vs R89 23 µs/请求**；pilot gap0 紧密档 **26.0 vs 32.0**，延迟 55.9 vs 60.7（第三轮 poll 带来的延迟抬升消失）；门禁 10/10 全绿（fuzz 133/133 仍只有两项既批准偏差）。

## 边界

- Oracle AArch64 GNU 主机的 SDK musl 诊断构建，非 canonical x86_64 CI 发布；C/R89 为精确镜像/正式产物。
- daemon CPU 用 /proc stat（含已退出 worker），100 Hz 量化，每 tick=12.5 µs（paced）；不替代整机冷启动或冻结的 74 项性能矩阵。
- 停放阈值 50 ms 未改；gap<50 ms 的真实浏览器点击间隔仍走线程路径。
- 原始逐轮数据、身份与门日志在 Oracle `/home/ubuntu/r94-httpd/`；实机原始样本与派生表在 ignored `private/r94/device-r94-01{,-derived}/`，恢复门 `private/r94/recovery-01/`。均未纳入 Git。
- 实机驱动在全 C 生产栈下需 `--stack stock`（`52be6f1`）；恢复门按当前 boot 用 read-only `private/r94/backup.py` 重生成。
