# v0.3.2 rpcd 静态项目复现与修复

五项原静态边界均得到 Oracle 运行证据并修复。没有物理设备操作，也没有读取或写入
`/proc/kmsg`。精确参考为 rpcd `28faf640`、匹配 libubox `7dd12784` 与镜像中的
LuCI `luci.uc`；身份来源沿用 release source manifest 和独立审查的 source-identities。

证据：Oracle `/home/ubuntu/v032-root-fixes-20261019/`；本地副本
`private/review-v032/rpcd-static/`。`rpcd-static-red-{1..4}.log` 是修复前单测，
`rpcd-static-daemon-red-v4/` 是四轮 C/Rust 实际 RPC；早期夹具失败与修订也保留。

本轮模型：问题来自把**已提供但非法的值当作缺省**、先窄化/乘法再校验，以及
cleanup 清除实际写入失败。预计用相同报文和文件故障即可得到确定性的退出码/返回值
差分，无需延时或性能代理。每类保留正常输入、真实文件内容及修复后继续服务控制；
只将 Linux namespace 内结果用于源码决定，不推断 HTTP 可达性或物理闪存故障率。

## Session thaw 与原始 SID

- 破损 freeze 的 SID=`31个a+é` 在 UTF-8 第 32 字节切片 panic；过大 expires 乘
  1000 在 debug 下 panic。两项各四轮红。现只接受 32 个 ASCII hex 的 SID，时间
  按匹配 C 的有符号解释先饱和乘法再 clamp。普通计时与负值 clamp 行为保留。
  C `rpc_session_from_blob()` 是固定 32 字节 memcpy，未承诺接受任意破损身份；
  C 时间 helper 的极大有符号乘法也可能溢出，不能拿未定义行为作为兼容保证。
- 非 UTF-8 的显式 SID 原先经 `as_str()->None` 被当作本地 root：真实 file
  read/stat/md5/exec、uci.get 四轮均 C=6、旧 Rust=0；session.list 则 C=4、旧
  Rust=0 并列出会话。现保留显式 SID 的存在，以不可匹配的空身份走原权限检查，
  缺省字段仍是本地 root。session 的各 SID 消费者使用相同解析规则。
- 证明范围是已连接本地 ubus 的原始字节请求；未声称 HTTP/匿名 LAN 可利用。

## Base64 padding 与 LuCI 空 name

- `QR==`、`Qf==`、`QUJ=`、含空白的等价串和后缀案例均曾被 Rust 接受。匹配
  `libubox/base64.c` 明确拒绝非零 padding bits；现检验解码后剩余位为 0。
  实读审查副本与 Oracle 的干净 libubox checkout
  `7dd127841e82eb1cfb61185da37dde7b9bd9ba6d` 中该文件的 SHA256 均为
  `3378f8210b5bd02d19e9c73caa658b5206e61efef8d2fdedf879b13f5f0ef966`；
  早先误写的 `6f78fa49` 属于 ubox/logd，不是 libubox。
  真实 file.write 对比同时检查拒绝状态与写入字节，合法 `QQ==/QUI=/QUJD` 正常。
  C 错误出口再次读 errno，本轮在前序 ACL 拒绝后返回 6；Rust 明确返回 9。
  因而报告“均拒绝且空文件”，不伪称所有错误码逐位一致。
- 匹配 LuCI 的 `!request.args.name || i == request.args.name` 将空串视为未过滤。
  Rust 现忽略空 name，真实 getInitList 的缺省/空串返回相同 synthetic init script。
  所有脚本仅位于复制的 rootfs，未执行设备 init 动作。

## UCI I/O 错误

用 delta 目标为目录制造真实 EISDIR，add/set/delete/rename/order 各四轮均旧
C/Rust 返回 0；只读 bind 的 commit 与带 rollback 的 apply 也四轮错报 0。
这是 C 共同缺陷，修复有意保留 mutation 的错误而不复刻 `uci_unload` 清错行为。

现在 mutation 在清理 package 后仍返回实际错误；commit/apply 失败不发送成功配置
通知。apply 停在首次失败，并保留已经准备的全部快照及 rollback 计时器；正常
rollback 恢复仍通过。回归逐项检查原配置保持、delta 保留、解除只读后 commit 重试、
apply 快照保留及解除故障后 rollback 恢复。无需模拟 ENOSPC 来重复证明同一错误传播。

`tools/rpcd_static_check.py` 使用提取镜像的 C ubusd/rpcd/plugin 和候选 Rust daemon，
每轮独立 mount/network/PID namespace。只借用既有工具的编码和 Bus client；没有
实例化其会触碰 kmsg 的旧 Fixture。C 的七项 UCI I/O 安全断言失败保留为基线事实，
不计作候选可接受行为。

最终候选：**36 项实际 RPC/文件状态断言 × 4 轮全部通过**；包含正常控制，
不把 144 计成互异漏洞。C 同输入每轮 29/36，七个失败仅为上述继承 UCI I/O 边界。
freeze 定向四轮绿；最终 `-Dwarnings`、串行 `cargo test --locked` **68 passed**，
同时构建现有 examples。`rpcd-static-daemon-final/identities.json` 保存最终 ELF 身份；
最终测试日志为 `rpcd-static-final-tests-v3.log`。之前一次失败为新增测试调用了不存在的
Payloads::is_empty，另一次是远端未同步已提交的 example Result 适配；均保留失败日志。

独立代理只做新增源码与调用方复核，未发现可从 diff 确认的新阻断；它确认显式坏 SID
无法对应可创建/可恢复的空会话，失败 apply 的 owner、快照与 timer 保持一致。
rollback=false 仍可能部分成功且没有自动回滚，这是调用方选择，并非本轮事务性保证。
本轮不提供 HTTP 原始无效 UTF-8 可达性、长期在线运行或物理掉电原子性结论。
