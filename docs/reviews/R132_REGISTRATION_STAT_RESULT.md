# R132 注册路径独立计数复核

12 个正式 Oracle `perf stat` 窗口通过证据完整性检查。R131 相比 R124 的用户态指令数增加很小，
但用户态周期数、分支误预测计数在两个镜像配对中均增加。这提供了后续按符号 profile 的调查线索，
**没有证明路由器注册 p95 回退的原因，也没有改变 R131 不提升为通用基线的结论。**

## 固定条件与复核

[冻结计划](r132-registration-stat-plan.json)使用同一独立 Rust caller，保持原注册 fixture；
caller 固定 CPU0、daemon 固定 CPU1，warmup 5000 后经 enable/ACK 计量 100000 个 ADD/REMOVE 周期，
结束后 disable/ACK。方法数为 1、16，各执行 C/R124/R131/R131/R124/C，合计两个镜像配对块。
caller 与历史 router ELF 的关系及差异见[调用者报告](R132_REGISTRATION_CALLER.md)。

独立工具直接解析原始 `perf.csv`、`client.json` 与进程快照，没有导入 collector 或采用其派生统计。
检查覆盖：

- 72 个计数均可用、整数、运行比例 100%；12 窗 CPU migration 全为 0。
- 1200000 个逐操作样本均完整、为正数，外层 CPU/wall 时钟与元数据一致；成功周期数完整，错误数为 0，
  完整 signature preflight、warmup 后与结束时空 registry 检查均通过。逐回复完整 wire 字节校验没有声称执行。
- daemon 前后 PID、启动 ticks、CPU1、ELF/动态库 SHA、映射文件 dev/inode 与命令行一致；
  caller 单次活体 PID、CPU0、静态 ELF SHA、映射与命令行相符。没有声称保留了两次 caller 活体快照。
- 原始 tar 的 259 个文件全部与本地副本逐字相同；每个文件的 SHA、每窗原始计数和全部配对差异均写入
  [派生 JSON](r132-registration-stat-results.json)。
- collector 以已冻结旧源码核对，SHA 为 `c32372bf8eb4c1cb6a9e755519ef92d3583fe3525a958220ca72f10e308a7be1`，
  对应 `c3be8e7`；随后 profile 采样频率修改不追溯改变本批 stat 工具身份。

原始 archive SHA 为 `8e62a918474eb39191bc7f9957780bfa95387e4e7eaea4acafe3abc4460f72e9`。
本地复核命令：


## 计数结果

表中为两个配对百分比的中位数，负数代表 R131 较少。两个窗口不能提供显著性、等价性或优化接受判定。
硬件事件均为 `:u`，不包含内核指令、周期和分支。

| 指标/周期 | 1 方法：R131/R124 | 16 方法：R131/R124 | 1 方法：R131/C | 16 方法：R131/C |
| --- | ---: | ---: | ---: | ---: |
| 用户态指令 | +0.2283% | +0.1043% | −13.0124% | −6.8280% |
| 用户态分支 | +0.0003% | +0.0004% | −41.8321% | −20.1633% |
| 用户态分支误预测次数 | +3.0039% | +6.3777% | −21.4722% | −3.5176% |
| 用户态周期 | +2.5985% | +3.9851% | −16.2657% | −5.8734% |

R131/R124 的每一对原始方向如下，未剔除任何窗口：

| 方法数 | 指令两个配对 | 周期两个配对 | 分支误预测次数两个配对 |
| --- | --- | --- | --- |
| 1 | +0.2313%、+0.2252% | +3.4460%、+1.7509% | +5.2293%、+0.7785% |
| 16 | +0.1050%、+0.1037% | +4.3557%、+3.6146% | +5.4069%、+7.3485% |

分支总数基本不变且两个配对混号。分支误预测**次数**与误预测**比例**不可混用：
R131 对 C 的误预测次数下降，但因为总分支下降更多，误预测比例相对增加约 35.00%/20.85%。
R124/C 的全部方向、绝对值、IPC 和 context-switch 计数也保留在 JSON，未只展示候选的有利方向。

## 时钟只作同一种计量方式内的描述

| stat 内指标 | 1 方法：R131/R124 | 16 方法：R131/R124 | 1 方法：R131/C | 16 方法：R131/C |
| --- | ---: | ---: | ---: | ---: |
| daemon CPU/周期 | +0.3681% | +0.7676% | −1.0037% | −0.6739% |
| 逐周期 mean | +0.5273% | +0.8597% | −0.5111% | −0.3780% |
| p95 | +0.3559% | +0.4262% | −1.0439% | −1.1900% |
| p99 | +2.6418% | −2.2108% | +0.0120% | −4.1221% |

表中中位数不是统一方向保证。R131/R124 的 1 方法 mean、p95、p99 均混号；
R131/C 的 16 方法 daemon CPU 和 mean 混号，1 方法 p99 也混号。完整配对在 JSON 中。

计量方式有明显扰动：本批首个 C/1 方法 `stat` 窗的 daemon CPU 为 **73.2554 µs/周期**，
已拒绝的 997 Hz `profile-01` 首个 C/1 方法窗为 **21.0343 µs/周期**（n=300000，检测到 THROTTLE）。
后者只作为扰动观察，不能恢复为有效 profile；差异原因没有单独隔离。
其原始 `client.json` SHA 为 `a3735181a88cc5f2189c684a6fae13ea5a003a231aac7f621663499acab9fdb1`。
本轮主要调查指标是同模式用户态 PMU 计数；不得混合 stat/profile/历史 router 的 CPU 或延迟数值，
也不得用这些时钟与 `:u` 周期的比值估计生产环境内核开销。

路由器已观察到的注册 p95 +15.2532%/+5.0085% 仍是原先独立仪器和窗口下的结果；
本次 Oracle 的小幅时钟变化不能覆盖它。下一步应结合有效的按符号 profile 判断哪些热点值得改动，
而不是从这些两窗差异直接指定算法、代码布局或编译器为根因。
