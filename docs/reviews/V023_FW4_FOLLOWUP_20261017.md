## 一次修改与功能边界

源码 `de7e5a691f79c106afeb9af89a58548f34a96cf0` 仅调整 `lib.rs` 的调用条件：
start/restart 正常写 state、失效旧缓存、下发并执行 includes，但不准备 reload
认证输入、不查询 generation、不采实时规则认证快照；reload 的安全逻辑及缓存
格式不变。Oracle 41 场景×原版/候选、19 单测、Clippy 通过；独立静态审阅无阻断。

首次后续 reload 正常下发并建立认证，之后相同有效规则可跳过。现网 software
flowtable 原本就需要首次 reload 热化，故没有额外下发；无 flowtable 的配置可能
比前一候选多一次首次 reload。变化 reload 的后置快照仍是下一次可靠 skip 的凭据。
丢弃它会把认证及一次额外 apply 移到下一次 WAN 事件，所以没有采用这种转移成本
的改法。与 stock firewall4 的计数器、flowtable、verbose 输出差异见
[功能报告](FW4_RELOAD_V023_20261017.md)。

Canonical core CI `39070644856` host/target 均通过，严格编译与未分类警告为 0；
target 另有 300 条已分类 SDK metadata 提示。新 fw4 SHA256：
`1f53b868cb3fc9c205257a41bd17918d93cc38ba7cb84138e57154d10840f3f8`。
其余八个 core ELF 不变；netifd 仍为已接受的 `cd02d474…10ef`，DNS 冻结输入不变。
