# OpenWrt 25.12.6 适配结果

2026-10-22：完成 11 个替换组件及共享库、保留执行面和发布入口的检查。
必要产品修复集中在 **rpcd 和 httpd**；netifd 增加合同测试，无需改产品逻辑。
源码已适配所覆盖的 .6 接口，**当前已资格的完整固件仍是 25.12.5 / v0.3.2**。
本轮没有发布镜像、修改路由器或执行刷写。

官方 25.12.6 于 2026-10-18 发布。完整来源、源码 revision、包级差异及全部组件矩阵见
[上游审查](OPENWRT_25126_UPSTREAM_20261022.md)。已下载并校验官方 stock 镜像和
ImageBuilder，新增[独立 intake](../../manifests/ax3000t-stock-openwrt-25.12.6/intake.json)。
13 个替换/恢复路径中，只有 C rpcd、uhttpd 的文件哈希变化；其余 11 个逐字节相同。
镜像 revision 与 release tag 的差异仅为 feeds 锁定和版本元数据，组件实现以匹配包的
源码 revision 为准。未改写 .5 历史证据和冻结 PGO 身份。

## 必要更新

| 范围 | 完成的变更及兼容边界 |
| --- | --- |
| rpcd 文件访问 | 原路径和解析目标分别授权；新文件解析父目录，悬空末端链接拒绝；递归删除逐项授权。`lstat/remove` 仍操作末端链接，但额外授权父目录链接，关闭 .6 上游遗漏的父链接绕过。成功 stat 返回实际解析路径。 |
| rpcd 文件结果 | 空文件成功返回空 data；创建模式屏蔽特殊位并遵守进程 umask，已有文件模式不变。 |
| rpcd 会话/UCI | 独立随机 dirname 用于暂存及冻结文件，SID 不出现在路径；lookup 不续期；熵失败不创建会话；未知 SID 不写暂存。apply/rollback/destroy 共用映射。旧冻结格式先迁移目录再恢复，失败不恢复会话，不保留上游继续暴露旧 SID 的行为。 |
| LuCI 调用方 | 包内新增同组 `luci-mod-system-flash` 的 `/proc/*/mounts` read ACL，兼容旧 .5 调用；新 .6 同组重复授权无害。验证内容、模式、归属及 `rust.sha256`，stock 恢复清单不变。 |
| httpd | 16 KiB/100 字段共享 header/trailer 预算、431、字段名 token 验证、严格 chunk grammar/CRLF、prefix Basic Auth、modern ubus 参数类型、一跳 symlink MIME。已有安全请求体排空、SSE 释放和 TCP_NODELAY 保留。详见 [HTTP 审查](OPENWRT_25126_HTTPD_20261022.md)。 |
| netifd | 验证 .6 DHCP/DHCPv6 `sendclientid` schema 及 9 种 UCI→JSON→脚本参数组合；动态 schema 已支持，模式选择仍由上游脚本执行。 |
| 镜像工具 | AN8855 FIT 输入改为 .5/.6 独立 hash pins；构建与验证共同使用，错误版本/哈希仍拒绝。dnsmasq 发布工具按版本或 `OWRT_NATIVE_SPEC` 选配方，禁止默用 .5；缺少新配方时明确拒绝。 |
| 微软规范 | [长期规则](../RUST_GUIDELINES.md)通过 AGENTS.md 对所有 Rust 开发/重构/审查/维护生效，记录官方文本身份、适用约束和渐进优先级。新增测试隔离进程 umask、临时文件与网络；顺手清理 6 处机械 Clippy 问题，无依赖或架构重构。 |

procd、ubus/ubusd、uci、fw4、odhcpd、dnsmasq、logd、reload_config 的相关上游实现未变，
无证据支持为版本号重构。内核、mt76、Wi-Fi scripts/hostapd、TLS、cgi-io、LuCI 的更新应随
新 stock 执行面一起进入新镜像，不能由 Rust 修复替代。Wi-Fi 的 SAE/GCMP 默认改变需要
未来真机客户端验证，本轮不声称其性能或连接体验已确认。

## 发行边界

本轮提交的是源码、安全合同、回归工具和新官方输入证据，未建立可发布的 .6 完整镜像。
`native-25.12.5.json`、默认发行版本和冻结 PGO 仍保持已验证身份；没有将旧 ELF 的 reference
哈希复制到新版本来绕过资格检查。要切换发行基线，仍需完成：

1. .6 官方 SDK 校验及 canonical x86_64 构建，取得本轮新 rpcd/httpd 的正式 ELF 身份。
2. 新 native 配方、包/LuCI inventory、dnsmasq 冻结源码/PGO 的明确资格，以及完整镜像的归属、
   迁移、C 恢复和可重现性检查。
3. 另行授权后的恢复门、部署与 Wi-Fi/客户端健康验证；本任务不包含物理路由器变更。

可选 httpd SNI `-Q`、FREEBIND 与 Lua/ucode 插件仍未覆盖，设备既有合同未启用这些功能。
路径授权未宣称解决全部可写目录 TOCTOU 竞态。微软规范也不意味着现存全仓已一次性完全合规；
后续按安全边界、测试可靠性、文档/API 的顺序渐进检查，避免无关重构。
