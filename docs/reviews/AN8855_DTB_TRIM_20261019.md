## 改动与身份

`ci_build_image.sh` 固定检查 OpenWrt 25.12.5 的原 FIT、DTB、ITS SHA256，
检查目标节点 compatible 和原本无 status，提取两个负载后仅增加
`/soc/ethernet@15100000/mdio-bus/switch@1f` 的 `status = "disabled";`。
反编译 DTS 必须只有这一行差异，重新提取的内核必须逐字节相同。
`SOURCE_DATE_EPOCH` 取自固定身份 FIT 的内嵌时间戳 `1782737960`，
安装后的 mtime 也显式设为该值。重复使用已经修改的 IB 会失败，须重新解包 IB。

最终流水线原本重新使用官方 sysupgrade 的 kernel 卷；经用户同意，最小接入扩展到
`ci_integrate_image.sh` 和 `native_image.py`。最终镜像使用新 FIT，并从最终 kernel 卷
重新核验原始身份、内核字节、唯一 DTB 修改和时间戳。官方 kernel 与原 IB FIT 的
SHA256 完全相同。最终 manifest 继承 `ax3000t_fit` 原/新身份，`kernel_sha256`
记录最终 kernel 卷。两个调用该构建脚本的 CI 补装设备树与 U-Boot 主机工具。
组件、冻结 dnsmasq 配方、上游 DTS 和 `-ubootmod` 均未修改。

## 首两轮 CI：发现 rootfs 构建日志不确定性

经用户授权推送 `an8855-dtb-trim`，提交 `2daaf76c` 的
[39313401534](https://github.com/WenliangCao/owrt-control-plane-rs/actions/runs/39313401534)
和 [39313406355](https://github.com/WenliangCao/owrt-control-plane-rs/actions/runs/39313406355)
均构建成功。5 个 APK、11 个 ELF 和 FIT 完全相同；全部 ELF 与 v0.3.1 相同，
冻结 dnsmasq 身份门通过。但完整镜像 SHA256 分别为
`1ab9a80031573b9134eba580748407c1980bad1eb694f011c96df9d3195c235c`、
`9a36053d1376ff5795d099f8a1bf424515485556b742431fe0ba59fd123aa488`，不接受为可复现结果。

Oracle 解包比较两份 rootfs 的 1,270 个路径：属性全部相同，唯一内容差异是
`/tmp/log/apk.log` 中安装时间 `19:51:22` / `19:58:53`。原 stock 镜像没有该文件。
固定 IB 的 apk-tools 3.0.5 支持 `--no-logfile`，因此仅在最终离线 APK 安装命令增加该
选项；诊断继续保存在镜像外的 `install.log`。没有修改组件、配置或执行平面。
此轮证据位于 Oracle `/home/ubuntu/an8855-repro-20261019/`。
修复的离线对照使用相同 5 个 CI APK 和两个全新的 stock rootfs，安装开始时间相隔
17.526 秒；完整 SquashFS 均为 `f7786d0bde5bf31b6a0b7976938fbcd04e736f9c1500904c12d4cfdd3fd8bb08`
（9,792,824 B），没有生成 `apk.log`。

首轮精确镜像已通过完整离线资格，且无失败或重跑：boot、image 11/11、APK 真实重装
2/2 与反例 8/8、守卫 23/23、PID1 交接 2/2、离线备份 46 成员和 13 个恢复文件。
kernel 卷的 DTB 仅增加 disabled 一行。该结果绑定旧镜像，修复后须对新镜像重新资格，
不能沿用。证据：Oracle `/home/ubuntu/an8855-image-20261019/runs/ci-39313401534/`。
