# R97 ubusd：方法存储实验节省内存，注册退步使候选暂缓合入

2026-09-20。**本轮存储候选暂不合入**：虽有明显请求堆和批量查询 CPU 收益，单方法注册 CPU 在八轮独立复查中全部上升，
触发冻结的暂缓门槛。保留完整补丁、正负数据和兼容性修复，继续研究 ubusd；没有证据可以把未达标归因于 Rust/C 的语言极限。
先独立修复 [方法名字与 ACL 的 C 字符串边界](R97_METHOD_COMPATIBILITY.md)，再以修复版为基线研究存储。
生产保持 C，所有路由器候选只运行在临时隔离命名空间。

## 实现依据与改动范围

镜像匹配 ubus revision `24864e7840b3a02a9ef76284a373f6b2f00b8a9b` 的
`ubusd_obj.c` 把方法描述和 blob 放在一次 calloc 中，方法名指向该 blob；类型使用链表。
[上游源码入口](https://lxr.openwrt.org/source/ubus/ubusd_obj.c)。
Rust 原来每个方法同时保存名字 Vec 和 blob Vec；方法列表本身也是 Vec，注册完成后不再增长。

本次实验候选保留连续方法列表，避免引入指针链表或 unsafe：

- 校验返回输入名字的借用切片，规范化后从唯一方法 blob 的名字长度和字节读取 ACL 名字。
- 方法 blob 和注册完成的方法列表转为 `Box<[T]>`，去掉保留容量和重复名字分配。
- 方法 payload、顺序、类型引用计数和所有者删除逻辑保持原合同；诊断例程适配新表示。

标准库依据：[Vec 的容量和 into_boxed_slice](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.into_boxed_slice)、
[Box 的所有权](https://doc.rust-lang.org/std/boxed/index.html)。这是存储布局改进，不改变遍历的渐进复杂度。
转换时收紧容量可能触发 realloc，不能凭减少分配空间就假设注册更快。
因此额外冻结注册—删除循环实验，覆盖 1/16/64 方法及长名字。

运行时 [补丁](r97-method-storage.patch)基于 `5a19517`，比较修复基线 `527f8683…` 与候选 `bdade5c6…`。
固定真实构建目录、SDK、Rust 1.98.1、cwd 和 release 链接参数。
查找矩阵使用 [冻结旧客户端源码加 CPU 时钟](r97-reference-client.json)，
注册实验在该客户端上只追加 [注册循环命令](r97-registration-client.patch)。每个实验的四侧客户端完全相同。
不跨 R95/R96/R97 轮次或客户端版本合并数据。

## 实机验证与结果

物理路由器 29 条单测通过；最终候选的 14 条方法签名/ACL 观测与精确 C 一致，旧版本错误对照仍可复现。
六个构建机历史门通过（root/ubus 用户功能差分、ACL、模糊测试、资源边界、恢复），它们只算预筛查。
诊断例程仍有共享 sys 模块的 unused-import 警告，clippy 指定门通过。两个运行时 release 均为 507,880 字节。

### 注册—删除循环

[独立冻结计划](r97-registration-plan.json)的 16 个窗口共 **128,000 个计时循环**，每循环 ADD_OBJECT + REMOVE_OBJECT，
共 256,000 条计时协议请求。计时包括相同客户端的编码；每个场景在计时外完整比对注册签名字节，结束后验证对象集为空。
C 与候选的工具冒烟及路由器三条计量工具单测通过，当前工具源码在构建机的三条单测及 clippy 也通过。
[完整注册结果](r97-registration-results.json)。下面是相对修复基线的配对中位变化。

| 方法数/名字字节 | mean | p50 | p95 | p99 | 主体 CPU/循环 | 客户端 CPU/循环 |
|---|---:|---:|---:|---:|---:|---:|
| 1 / 8 | **+1.59%** | **+0.77%** | **+2.59%** | **+5.00%** | **+1.56%** | **+0.27%** |
| 16 / 8 | -2.05% | -3.05% | **+0.52%** | **+3.56%** | -6.52% | -0.52% |
| 64 / 8 | -10.47% | -10.03% | -12.98% | -10.24% | -17.08% | **+0.16%** |
| 1 / 128 | -0.23% | -0.07% | -2.85% | **+0.99%** | -0.52% | **+0.28%** |

单方法 CPU 四对变化为 +1.93%、−1.34%、+1.20%、+2.04%；16 方法 p99 四对均为正（+2.61% 至 +5.09%）。
这是优化可能增加注册成本的实测信号，追加 [八 block 独立注册复查](r97-registration-recheck-plan.json)，不以更低的平均延迟遮盖尾部。

| 方法数/名字字节 | mean | p99 | 主体 CPU/循环 |

对 C，小签名 1/16 方法和长名字单方法的 mean/p50/p95/p99、主体和客户端 CPU 都未胜；64 方法场景这些指标均更低。

因此此前只测 lookup/invoke 的结论不能推广到对象注册生命周期，ubusd 的 C 目标明确仍未完成。

现有每轮 wall interval 还保存了 ops/s，补充为 [吞吐诊断](r97-throughput-diagnostics.json)。

### 独立复查与保留决定

两项复查均在看过各自初始矩阵后另行冻结，各八个配对 block；不合并样本、不覆盖原报告。
查询/调用复查每负载 20,000 次，16 窗共 1,280,000 个计时请求。
注册复查每场景 10,000 个 add/remove 循环，16 窗共 320,000 循环（640,000 条计时协议请求）。

| 独立复查负载 | mean | p50 | p95 | p99 | 主体 CPU/op或循环 | 客户端 CPU/op或循环 |
|---|---:|---:|---:|---:|---:|---:|
| lookup | **+0.70%** | 0.00% | **+3.57%** | **+2.75%** | **+0.06%** | **+0.52%** |
| lookup_c4 | -2.71% | -14.04% | **+4.38%** | **+1.24%** | **+0.83%** | -0.20% |
| lookup_all_64 | -0.92% | -1.37% | **+1.20%** | **+0.25%** | -7.12% | -0.09% |
| invoke | -0.41% | **+0.23%** | -0.08% | -2.20% | **+0.79%** | -0.16% |
| register_1_8 | **+1.58%** | **+0.84%** | **+2.46%** | **+3.97%** | **+1.62%** | **+1.00%** |
| register_16_8 | -3.47% | -3.22% | -4.94% | -5.78% | -8.06% | -0.73% |

并发精确查询原先 +14.43% 的 p99 幅度没有稳定复现，复查正负各四轮，但不能据此宣布等价或无退步。
并发精确查询 p99 各对范围仍为 −9.64% 至 +29.25%，不能把中位数当作最坏情况。
普通精确查询 p99 七轮为正，中位数 +2.75%；它仍是反向信号。
16 方法注册的初始 p99 反向没有在复查持续出现，八轮均下降；原来的四个反向窗口仍保留。

**单方法注册主体 CPU 八轮全部上升，中位数 +1.62%，触发采样前冻结的暂缓合入门槛。**
其 p99 六轮上升、中位数 +3.97%，逐对范围为 −1.02% 至 +41.23%；mean 为 +1.58%。门槛是保守研究决策，不冒充正式显著性检验。
[查询复查全量结果](r97-method-recheck-results.json)、[注册复查全量结果](r97-registration-recheck-results.json)、
[门槛逐项计算](r97-retention-gates.json)。

**决定：暂不合入本轮方法存储运行时改动，撤回这四个未提交实现/例程文件到已通过实机验证的修复基线。**
[运行时补丁](r97-method-storage.patch)和 [诊断例程适配补丁](r97-method-storage-fixtures.patch)作为实验记录保留，
不能将文中这些候选收益说成当前运行时代码已获得的收益。方法名/ACL 兼容性修复 `5a19517` 保留。
复现候选可在实验工具提交 `6797042` 上应用这两个补丁；使用文中固定 SDK/源码根/工具链构建，不能以任意目录编译冒充相同 ELF。

本轮最终身份的 71 个物理窗口均通过清理、生产 C、配置、boot、宿主挂载与客户端健康检查。
其中 64 个性能窗口、4 个堆诊断窗口、3 个正确性/工具窗口。
完成后再次检查零测试目录、零测试进程引用、零测试宿主挂载；配置与当前 boot 的离线备份一致。
从未安装或启用候选。[验证清单与二进制身份](r97-method-storage-validation.json)。



## 仍未完成

四个独立 block 仅用于探索，不能据此宣布统计优于、等价或非劣。
内存计数器只记录 Rust 请求的 layout 字节，不能代替分配器物理占用、进程峰值、PSS 或内核资源。
原版 libubus 调用者及完整九组件组合仍须单独在路由器验证。

注册成本现在也是后续优先问题：先验证签名并确定方法数，再一次分配最终列表，可能避免增长后收紧容量的 realloc；
这是待测假设，不计为已实现收益，也不能跳过 malformed/空签名边界。
同时核对了精确 C 的 `ubusd_id.c` 和 Rust `sys.rs`：二者均使用 `getrandom(..., GRND_INSECURE)` 取得对象 ID，
不能在没有 profile 的情况下把注册差距归因于随机数接口不同。

另外，精确 C 的 `ubusd_send_event` 通过 fill 回调，直到找到实际接收对象才创建事件消息；
Rust 的 `send_obj_event` 则在匹配前就编码并复制消息，零接收者也执行这些工作。
`ADD_OBJECT`/`REMOVE_OBJECT` 的 DATA 回复也仍使用新 BlobBuf 再复制，C 复用静态缓冲。
这些是源码已确认的额外工作，尚不能仅凭阅读认定它们解释了全部 CPU 差距；下一步应测量并逐项消除，
保持事件序号、去重、监视器、删除通知与背压语义。没有证据支持“已达到 Rust/C 语言极限”。

每客户端首次读取后保留的 4 KiB 接收缓冲也仍待研究。匹配 C 使用固定前缀缓冲后按消息体分配；
Rust 的预读减少系统调用，却可能增加连接规模下的常驻内存。下一步须同时测小消息、大消息、批量帧、
部分读取和 SCM_RIGHTS 边界，不能只把常量调小后检查吞吐。本轮未修改接收状态机。

原始记录保存在 `private/r97/method-storage/`；恢复备份为当前 boot 的 `private/r96/recovery-full/`，均不入 Git。
