## 恢复方案与已遇到的问题

用户最新选择：**不安装自动回滚守卫，出问题时手动刷回 v0.1.1；不追加 Oracle 模拟或新验证。** 已准备的守卫、helper 和真实交接测试仅保存为历史工具证据，不会加入本次配置备份。恢复材料是电脑上已核验的 v0.1.1 原镜像和当次配置备份；管理可达时使用标准保留配置 sysupgrade，管理不可达时按[救援手册](../RUNBOOK_AX3000T_RECOVERY.md)使用 failsafe/TFTP。镜像内的十程序加 dnsmasq init/ACL 完整 C 恢复是另一路径，**不等于 v0.1.1 回滚完成**。sysupgrade 请求返回或超时也不能证明尚未写闪存，不能盲目重复刷写或强制重启。

首个正式 CI run `38625158559` 在读取 stock `/etc/config/dhcp` 时因权限不足失败，未成为候选发布。`21e14a95` 修正装配工具的显式读取权限并重新走完整正式 CI；未修改 dnsmasq 产品代码。失败日志与中间产物原样保留。另有上面的正式 ELF 与性能参考 ELF 差异，已独立记录，尚无已证实根因；不能用旧性能数据抹去身份变化。

host-tests run `38626687422` 的原失败保留；`5c1a2f48` 修测试连接关闭生命周期，修复后 ubus suite 70/70；`ded73bae` 修测试 namespace/串行执行条件。`ded73bae` 对应完整 host CI [38636080350](https://github.com/WenliangCao/owrt-control-plane-rs/actions/runs/38636080350)现已成功，原 namespace 环境问题与产品失败分开保留，不为此扩大测试。最终 `38636115402` 镜像身份已核验，用户要求只处理刷机必需项。

## 上线后继续观察

自然 DHCP 续租、新设备首次入网、IPv4/IPv6 和公网 DNS TCP、长期 RSS/FD/CPU 趋势，以及进程重启/日志异常仍需日常观察。原性能参考 ELF 有两处未解释尾部：UDP 未命中单轮出现 4 次发生器漏发和 174.267 ms 最大答复；6 客户端首次 DORA 的 Rust 最大 19.795 ms（C 最大 2.496 ms）。没有确认原因，也没有证明它们会或不会在新 CI ELF 的生产流量中出现。
