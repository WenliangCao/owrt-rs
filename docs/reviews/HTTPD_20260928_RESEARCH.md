# httpd H12 工程结案（2026-09-28）

**保留 H12，必要功能门、正式构建门与三侧实机确认全部完成；未部署。** 在本轮代表性明文 HTTP→ubus 负载中，四条 RPC 主体 CPU 中位数相对精确 C 降低 **23.28%–42.94%**，相对正式 R89 降低 **13.86%–51.11%**；静态路径已有收益保住。H12 是本轮已测试候选中最有依据的工程选择，不宣称所有负载最优或统计显著。

保留的代价包括：CGI 相对 R89 主体 CPU **+9.30 µs/请求（+1.31%）**、mean **+56.14 µs（+2.60%）**；实机关闭后 RSS 比 C/R89 多 **72/80 KiB（6.67%/7.46%）**；密集转义的编码器微基准相对 H2 **+20.32 µs（+14.36%）**。逐项尾延迟、资源差异与未归因异常均在下文及[候选/拒绝索引](httpd-20260928-candidates.json)，没有用平均收益抵消它们。

用户明确解除原来的两小时/45分钟限制，要求深入 C 源码和算法变体；同时保留允许披露退步、按工程边界结案的要求。它取代 R95 等旧材料冲突的性能收尾条件，正确性、身份与生产隔离要求继续有效。生产九组件始终为精确 C；ubusd R136、netifd H10 没有重开性能研究。

## 从证据到代码

以[HTTP 合同](../contracts/httpd.md)、[R94](R94_HTTP_FASTPATH.md)、精确镜像及其匹配 C 源码为起点。R94 的 c4 RPC 主体 CPU 470.2 vs C 462.8 µs 范围重叠，不能先认定当前版本存在稳定退步。初始证据与三个可检验方向如下；后续变体均归于这些方向。

| 证据 | 假设 | 验证办法 |
|---|---|---|
| 完整小 RPC 49 次分配；目标 lookup 触发约一对 4096B mmap/munmap | 中间 Message、签名和 JSON 树产生可去掉的分配/复制 | 分段分配 profile、syscall 归因、独立未插桩 HTTP 对照 |
| 大回复编码和搬运成本随字符串/长度变化；C 批量复制普通字符段 | 字符扫描、整数/转义与缓冲所有权是主要可改善机制 | 固定形状、固定容量、整数和四字节去头变体，再筛 HTTP |
| c4 有 futex 等待；C 输出先尝试借用写入 | 池锁边界或输出缓冲可能影响并发/大回复 | 地址归因，分别比较 H11 池锁与 H12 输出；保留拒绝结果 |

精确源码修订：uhttpd `7b1bec45826bd78c8afc993435bdc0f1df2fe399`，ubus `24864e7840b3a02a9ef76284a373f6b2f00b8a9b`，libubox `7dd127841e82eb1cfb61185da37dde7b9bd9ba6d`。读取了 uhttpd `ubus.c`、libubus 的 lookup/request/io 实现、libubox `blobmsg_json.c`、`ustream.c`/`ustream-fd.c`。后两个来自 Oracle 上核过 HEAD 的匹配源码目录；本机提取目录不当作独立 Git checkout。各文件 SHA256 在索引 `final.exact_c_sources`。

C 保留每次目标 lookup → session lookup → access invoke → 目标 invoke 四次总线事务；lookup 回调只借用 DATA 提取 ID；JSON 编码按 Blob 长度估算容量、扫描普通字符连续段再复制；ustream 先尝试直接输出、再保存余下内容。Rust 采用这些线索，但没有缓存会话权限或远端 ID。C 完整输出链也不能称零复制。

|---|---|---|

H7b 的关键证据来自精确 SDK `libc.a` 的反汇编：源/目标相差四字节时，musl memmove 落入逐字节循环。选择的安全四字节循环保持 Vec 指针/容量，但仍发生一次原地搬运，**不是零复制**。H12 遇短写、WouldBlock 或 EINTR 时退回缓冲逻辑，不能重新起计超时。TLS、deferred CGI、静态 `copy_from` 与 R94 内联路径保持原有选择。没有引入新依赖、unsafe、权限缓存或事件循环重写。

代码在 `components/ubus/src/{json,conn}.rs` 与 `components/httpd/src/{bridge,http,main}.rs`。公共 Reply 表示、FD/Lease寿命、乱序队列、状态优先级、断连重连和deadline合同保留。JSON扫描覆盖所有字节/位置/尾部及100000个确定性随机字，整数有边界/100000值差分，输出有7个短写/错误/deadline/路径选择/实际TCP测试。batch写失败单测确认：开头写失败执行0个RPC，首结果写失败后只执行1个，不启动后续RPC。

## Oracle profile 的能力与局限

先在 Oracle/aarch64 上做单机制研究：release profiler 每段100次预热、1000次计时，分配计数另取一次调用；HTTP筛选每侧两个独立窗口、通常4000次请求，使用精确镜像 C ubusd/rpcd。微基准是阶段墙钟，插桩 trace 只用于归因，不混入正式 HTTP CPU/延迟。初始 profile 曾与构建并发，时间只作线索；不能把所有阶段数字直接相加。

最终 JSON 编码器与 H10 相同。统一初始容量128字节的形状 profile：普通120字节字符串回复 **116.652→51.075 µs**，UTF-8形状 **224.710→106.120 µs**，32×1000普通字符 **115.886→64.929 µs**；密集转义 **141.533→161.855 µs，+20.322 µs/+14.3587%**。H4d早期的+8.01%只属于该历史阶段，不能代表最终编码器。完整小RPC在H10 profile为22次分配/1880 requested bytes；这不是最终进程RSS或所有请求的分配上界。没有设备密集转义矩阵，也不把控制字符专项当作真实LuCI分布。

H5有效筛选的c4 p99 745.686 µs异常保留。一次H5构建因复制源文件mtime复用了旧Cargo产物，强制重建后才使用正确hash；另一次准备目录错误使标为H4d的控制实际为H4b，17/18两窗排除，H5只使用正确的21–24窗。没有把错误身份样本改名混入有效配对。原始日志和失败构建留存。

## 冻结确认与异常处理

设备 AX3000T / MT7981B，OpenWrt 25.12.5 r33051-f5dae5ece4，Linux 6.12.94。Wi-Fi `en0`管理；全部试验沿用隔离mount/PID/network namespace、设备guard、身份/配置/boot/清理和客户端健康门，生产九组件精确C。每窗 ubusd/rpcd 固定为镜像C并核ELF，未测九组件组合。

确认设置先冻结：三block，seed20260928，顺序 **H12/R89/C；C/H12/R89；R89/C/H12**。每普通负载10000次，c4各2500；CGI500次；每客户端预热20，CGI预热5。代表负载为授权 `uci.configs`小回复、UCI list 256×120字节字符串大回复，各c1/c4；16KiB静态c1/c4；CGI c1。配置/ACL/独立预期JSON在计时外生成并核hash。实际影响门槛为CPU同时5%且10 µs/请求、mean同时5%且20 µs，尾延迟恶化同时10%且100 µs需重点解释；更小差异同样披露。

正式九窗 **2026-09-28 10:04:13–10:25:53 UTC，1300.012秒（21分40秒）**，完成63个负载观测、**544500次正式成功请求，0错误**。最终阶段pilot+诊断+确认共约22.98分钟；先前H2阶段约22.97分钟，总设备实验约45.95分钟。原45分钟限制已被用户解除；没有隐去准备或失败尝试成本。设置文件最初的09:42时间是设置冻结时间，构建/门/异常状态随后补入；正式CI实际09:51完成，不声称更早已通过。

全部性能请求为**明文loopback持久连接**。HTTP回复收完结束单请求延迟计时，后续JSON校验不计该延迟，但计调用方CPU并影响吞吐。c4主体/依赖CPU取同一个外窗，分母含80次预热；调用方CPU/延迟为正式请求。c4吞吐外窗含启动/预热且按 `/proc/uptime` 精度。测试工具与服务共享设备CPU，因此CPU分层列出；没有TLS握手/HTTPS速度或真实LuCI全链收益声明。
