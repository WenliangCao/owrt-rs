# 用户追加的一次 fw4 定向小修与复测

前轮 [A/B](V023_DEVICE_AB_20261017.md) 已如实停止。用户接受 netifd，允许一次
fw4 小修：首次 start 不读/比较实时规则；变化 reload 能安全省读取则修，不能则
接受并记录。只重测 start、changed reload，沿用噪声规则，然后恢复资格与部署。

选择最小改动：start/restart 正常写 state、清理旧缓存、下发及执行 includes，
但不生成有效规则认证、查询 generation 或读取下发后的实时快照。首次后续 reload
正常下发并按既有完整逻辑认证，之后相等时才跳过。reload 的安全证明和缓存格式
保持。变化 reload 的后置读取是建立下一次 skip 证明所需；删除会把认证及一次
额外下发移到后续 WAN 事件，不属于省掉多余工作，因此保留并采用用户明确允许的
代价例外。不能把未经认证的候选与之后随意读取的内核快照配对。

成本模型：前轮 start CPU 增约 14 ms，与新增后置 snapshot 路径方向一致；预测
这次 start 回到旧版噪声范围。变化 reload 路径保留，预测仍有约 14 ms CPU 代价。
本轮不拆分 profile，不增加变体，不重测已经接受的 netifd 或其他三个 fw4 场景。

真机之前只做与改动相关的 Oracle 功能检查及正式 SDK 构建；同一新 ELF 用于
性能与最终镜像。九个其他组件身份保持，随后仅更新 fw4 打包参考 SHA。

唯一追加批次复用原沙箱、输入、计时器、隔离与清理工具。新输出目录和新封包
SHA 单独记录，旧原件不改。先六次 true 地板，再依次 **start、changed**；各场景
校准 `ABBAAB`、正式 `ABBABAAB`，总计 28 次 fw4 调用，不补样。仍每次恢复初态、
计时前安静 1 s；计时外验证 nft handles/新规则端口。A=原 v0.2.2 精确 ELF，
B=这一次小修的 canonical SDK ELF，上传前冻结 SHA；不使用 Oracle 性能挑选。

分别计算墙钟与 CPU 的 `N = max(A 校准极差, B 校准极差, 2×量化)`，报告全部
正式配对差。**start 任一配对 B−A > N 就停止**，没有第二次修复/复测。changed
沿用同一噪声计算并明确标出超限，必要快照造成的保留代价按用户上述例外接受，
不能把“接受该差异”写成“性能没有退化”。两场景功能检查、隔离及样本完整性
必须通过，任何仪器错误或 600 s 超时停止，不补跑。

上机前核对离线备份和 v0.2.2 恢复材料、生产身份、客户端健康；结束后再次核对
配置、进程身份和客户端 TCP DNS/双栈 HTTPS，删除自有临时沙箱。首轮已证明当前
客户端 UDP DNS 有单独限制，不能冒称本轮通过 UDP。通过以上门后才重建最终镜像，
执行恢复资格、当次备份/自动回滚、刷机和持续客户端健康验收。
