# R131 补齐范围与验收边界

继续使用已测 R131 release ELF `c5bcf6e7c6f2ed565140e183ba3aa97c1ef60274bbde8398771ac13680da839a`，
R124 和精确镜像 C 同轮作对照。新增测试不与新优化混合，不借测试补齐之名更换运行时代码。
生产一直为 C；物理路由器一次只运行一个受恢复门保护的临时命名空间，窗口后验证清理与健康。

1. 短写：强制直接写在第二、第三帧内停止，恢复逐帧队列、覆盖调用者缓冲后验证最终完整字节。
   对 R124 helper 作反向核查，两版都通过；这是新覆盖，并未证明 R124 存在短写缺陷。
2. 原协议：目标 musl 全部单测、原有功能/ACL/恢复与 FD 差分门。构建机门只作前置条件，路由器另行验证。
3. 尾延迟：独立 exact-libubus latency caller 保存逐操作数组；每次从发送前计到所有回调完成，
   它是端到端耗时而非 daemon 自身延迟。时钟开销不扣除，三主体使用同一个 caller，不与旧 CPU-only 数据混算。
4. 事件边界：分组 owner、交错 owner、monitor、慢读者；逐 payload、目标、顺序、序号、删除和 FD 回收检查。
   发送队列达到镜像匹配的 1 MiB 上限后允许按原策略丢弃；幸存帧数受实际 socket 短写/调度影响，不要求完全相同。
5. 内存：0/1/8/32/64 空闲连接；单处理器 32/256/768 KiB；八处理器 1/8/32 KiB，
   后者覆盖批量、16 KiB 批量边界和大帧回退。采样空闲、连接、投递后、关闭后，事件保留 1/5 秒原始快照。
6. 共用发送函数回归：ADD/REMOVE、exact/all/prefix lookup、invoke，防止事件优化损害其他路径。

R131 旧报告的约 20% 改善只证明八处理器同连接的平均 wall/CPU 有益；原计划 p95/p99 未采集，
完整验收应为 pending，不能把事后删除未测门当作通过。本轮单独冻结补测计划，不修改旧原始采样或旧门。
所有不利结果保留；候选是否可采用，等这些门完成后再判定。

本轮完成范围是 ubusd/R131 的候选验收；九个 Rust 组件共同运行的整体性能和实际部署仍是独立项目阶段，
不能用单组件 namespace 测试替代，也不在这里声称已完成。
