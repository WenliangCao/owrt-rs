# R123 SEND ACL 凭据借用

R121 profile 与源码复核定位到 `event_send` 调用 `cred_of`，克隆附加组列表、用户名和组名。
SEND ACL 只使用 uid/gid/附加组；C 直接查看客户端凭据。R122 的固定 C 对照仍未达到事件性能目标。

候选基于 R122 `6f38c06`，只在 `event_send` 的 SEND 检查内借用这三个字段。
不改其他 `cred_of` 调用、ACL 算法、接收/FD 规则、派发或事件编码。缺失客户端仍传 None，
root 仍直接通过，主组和附加组匹配保持不变。补一个服务器层组授权表驱动回归，
覆盖附加组允许/缺失附加组拒绝、主组允许、root 和缺失客户端，检查状态及是否进入派发。

独立 commit 后在同规范路径和参数构建 R122 控制与候选，要求控制 ELF 逐字节复现；
先运行单元测试与已有功能/恢复门。构建和 Oracle 诊断不是路由器性能结论。

先使用已验证的 v3 原版 libubus ACK 调用者与 `r110_perf_event_diagnostic.py`，
对 R122/候选做低连接及 64-held 的同步 instructions/branches/branch-misses/cycles 筛查；
两块比较反转顺序，另做同 ELF A/A 控制。每窗 n=50000、warmup=5000；启动名字完全相同，CPU1/CPU0 钉核。
硬件计数不接受 multiplex、不丢失败记录。精确二进制和 JSON 计划在运行前冻结。

为限制无收益的长实机系列，暂用两规模 instructions/op 中位均下降至少 3% 作为进入路由器性能测试的研究筛选条件。
这不是 CPU/耗时收益的必要条件，更不是语言极限判据；未达到就先核对符号归因，不换控制流继续碰运气。
任何功能门失败立即停止。若达到筛选条件，再冻结路由器协议/FD 前置门与固定 C 对照系列，禁止引用 Oracle 值代替实机收益。
不从 R122/C 历史比值外推新候选/C，也不把两次代码简化自动接受为最终运行版本。
