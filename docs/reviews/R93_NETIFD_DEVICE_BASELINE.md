## 仍未赢 R89 的部分

- `wireless_status` CPU 25.0→26.5 µs（+6.0%），平均延迟 97.33→99.18 µs（+1.90%）；并发 CPU 21.33→22.32 µs。
- `device_status_c4` 平均延迟 2406.47→2481.37 µs（+3.11%），CPU 608.13→614.09 µs（+0.98%）。
- 两项 CPU 的四轮范围没有重叠：`wireless_status` R89 24–25、source05 26–27 µs；
  `device_status_c4` R89 602.18–609.13、source05 612.10–619.05 µs，值得继续定位。
- `interface_dump_32` CPU 532.0→533.5 µs；并发 CPU 509.92→512.90 µs。
- 这些小差值须结合逐轮范围；本组不能单独把成本归因于某一处代码，也不构成全场景无回退证明。

## 验证与范围

- 12 个样本的 COMPLETE、原始文件集合与 SHA 校验通过，共 1080 个文件；boot、配置、生产身份和客户端健康门通过。生产保持 R92。
- 2/32 接口回调齐全且无重复，子进程通过 `/proc` PPid 检查已回收；初始化前后子 CPU 稳定，所有计时查询无子进程启动 CPU。
- 所有客户端均完成既定请求、通过原始输出校验；串行 CPU 不含预热，c4 使用唯一外层 CPU 区间并计入每客户端 20 次预热。
- 客户端校验和原版依赖也占同一路由器 CPU，吞吐不等于独立服务器极限。
- 夹具是静态接口与空无线配置；没有非空 delegated-prefix/assignment、真实无线驱动管理或大规模 watch。IPv6 prefix 关联扫描问题仍未测量。
- C 为精确镜像原版，R89 为正式历史产物；source05 为同 SDK recipe 的 Oracle 诊断构建，非 canonical CI 发布。
