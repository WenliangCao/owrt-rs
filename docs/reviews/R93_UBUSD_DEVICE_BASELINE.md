## 结论与边界

- lookup_all_64/128 平均延迟仍未赢 C，source05 为 786.27/1548.64 µs，C 为 774.87/1510.22 µs；其自身 CPU 更低。
- 多项查询延迟比 R89 高约 0.9–2.5%；四客户端 invoke 则更低。小差值需结合逐轮范围，不能只按正负号判定稳定退化。
- 矩阵 lookup_all 实际发送 `*`，普通签名，没有覆盖已发现的 64 个大签名对象漏 DATA 故障。该故障已在单独严格工具中复现，不能用此矩阵通过替代。
- 运行第 3 样本期间本地 collector 曾停止，namespace 独立正常完成；取回时逐文件 hash/COMPLETE/boot/配置及生产身份核验通过。host-after 采样延后，明确保留于恢复记录。原始负载数据未改。
- 候选为同 SDK recipe 诊断构建，与 canonical R89 的构建 host 不同；候选未部署生产。
