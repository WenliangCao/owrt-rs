# R93 ubusd lookup Oracle 短四轮初筛

2026-09-15。**新版 smoke 48/48、短四轮 192/192 通过，0 错误。**
累计严格验证 **15,232 次 lookup、2,228,224 条 DATA、2,827,265,536 个 wire bytes**。
这是 Oracle AArch64 Linux namespace 初筛；不是 AX3000T 实机性能验收。borrow 候选未合入。

## 结论：尚未证明借用遍历有稳定 CPU 收益

512 对象大签名慢读，borrow 相对 starfix 的同轮 CPU 变化为
**−2.99%、−5.03%、−6.61%、−1.53%**，配对中位 **−4.01%**。
这是值得复核的方向；该 cell 每样本仅 **15.98–18.14 ms** daemon CPU，尚不足以确认稳定小幅收益。
其余 11 个 cell 的 borrow/starfix 配对变化均包含正负两个方向。
512 慢读相对 C/R89 的四轮方向仍有混合，不能称为胜双基线。

**168/192** 个样本 CPU 少于 25 ms；全部样本范围 **3.98–44.20 ms**。
没有自动启动长轮；本轮不足以支持合入 borrow 性能候选。

## 测量与资源边界

- 每个 cell 四侧输入、查询数相同；四轮顺序按 Williams 顺序平衡各位置与有向相邻组合。每样本启动全新 daemon，先做一次不计时 warmup。
- CPU 主指标是单线程 daemon `/proc/PID/schedstat` runtime ns；100 Hz stat ticks 同时保留。pathless 仅 0–2 ticks，star 为 0–5 ticks，不能用 ticks 判断小差值。
- 慢读 wall 包含每查询 20 ms 停读、每 32 KiB 1 ms 睡眠；pathless 另加 2 ms 平台检查。其 wall 只描述这套协议，不能当一般查询延迟。
- RSS/HWM 包含 fixture 注册对象和签名。borrow 与 starfix 各 cell 测后 RSS 中位差为 −4…+4 KiB，没有稳定省内存证据；单次分配探针不能替代 RSS 或 CPU 结果。
- 所有 lookup 原始字节、path、运行 ID/type ID、signature、seq、peer、顺序和最终成功 STATUS 精确检查；末尾额外输出/EOF 在计时外检查。失败样本不得计胜，本轮没有失败。
- Oracle 仍有正常后台服务；无其他 owned 压测/构建并行。四轮平衡不能消除所有调度噪音。
- C/R89 为精确镜像/历史正式产物；starfix/borrow 为同 SDK 诊断构建，不是 canonical CI 发布。所有历史及新 smoke 计时均排除。

## 工具与证据

独立工具修正原四轮顺序偏置，支持固定对象数对应 queries，并强制已知 ELF/helper/ns-exec hash。
汇总拒绝缺侧、缺轮、重复、失败、smoke、身份漂移、fixture 差异和缺失 DATA/字节；所有 cell 均显式 `winner_claim=false`。
25 ms 仅低采样标记，不以它选择性删除样本。

下载归档 SHA 和 **997 个文件**的集合/大小/SHA 全部一致（另有 file manifest 本身）；逐样本 raw 与 aggregate 逐字段一致，两组 summary 已本机重算一致。
结束后四侧源 ELF hash 不变，owned namespace/daemon/driver 进程为空，Oracle 窗口已释放；没有物理设备访问、runtime 修改或自动长轮。
