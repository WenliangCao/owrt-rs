# v0.3.0 odhcpd 路由器 A/B：停止推进

**空闲 CPU 四对、Renew 一对超过冻结噪声，停止 v0.3.0 后续构建和刷机。**
Rust/C 的空闲 CPU 中位数为 **64.370/14.846 µs/s**；Renew 第三对 Rust 多
**1.009789 ms**，超过该项 **0.805586 ms** 噪声。接口更新 CPU 和内存改善
不能抵消失败。只运行本轮，不优化、不补样、不重新测量。

当前版本配方已改为 **v0.3.0 / 0.3.0-r1**。路由器仍为 v0.2.3＋精确 C
odhcpd，生产 PID、boot、配置、挂载和客户端健康均保持正常。没有刷机、发布
或合并主线；旧 v0.2.4 候选证据继续保留原身份。

## 运行、范围和证据

设备唯一批次 UTC **10:16:57.190775–10:20:35.961624**，**218.770849 秒**。
十四个独立实例、固定请求和通知全部完成，无超时、替换样本或第二批。
进程 CPU 时钟包含 Rust worker，不含 provider、ubusd、观测器和 leasetrigger
子进程。更新窗到匹配新 RDNSS 的 RA 再加 1 ms，等待中的后台 CPU 不扣除。
所有十四个空闲窗均无周期 RA，保留实际观察值，没有因此筛选窗口。

声明的单调/进程 CPU 时钟分辨率均为 1 ns，页大小 4096 B；实际连续时钟
读取差为 0–154 ns、中位数 77 ns。UDP echo 地板最小/中位/最大为
45.396/46.396/150.653 µs。地板未扣除，全部门值均由校准波动或页量化决定。

这是空网桥上的本机服务端路径比较，不代表 Wi-Fi 往返时延、整机启动或首条
主动 RA。接口事件只改变私有 provider 的有效 DNS，并经过真实 ubus 订阅和
dump；没有测前缀切换性能。保留随机 bridge MAC、固定客户端 DUID 和 IPv6
地址，两侧设置相同。三 NA 内存场景在设备采样前因本地 PD 网关无效而确定；

## 当前模型与下一步

测量支持“Rust 更新和分配路径、内存更省”，但不能推广到全部事件：空闲后台
开销稳定更高，Renew 的正式第三对也超过已经较宽的噪声。双循环每秒唤醒是
空闲差异的候选解释；本轮没有做归因实验，不能把相关性写成已证明的原因。

本轮不再裁决实现细节。按用户停止条件保留 v0.3.0 候选，停止优化、重测、镜像
构建和刷机，等待后续指示；不以其它指标改善或绝对 CPU 占比小来绕过发布门。
