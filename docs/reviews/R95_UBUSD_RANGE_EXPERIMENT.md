# R95 ubusd：消除查询快照和背压恢复的重复收集

2026-09-20。保留借用有序树的运行时改动，性能目标仍未验收关闭。
依据包括实机分配诊断、背压扩展性实验、完整矩阵及独立复查；没有以少量点估计宣布全面胜出。

## C、原 Rust 与本次算法

检查精确 C revision `24864e7840b3a02a9ef76284a373f6b2f00b8a9b` 的
`ubusd_proto.c`，其 SHA-256 为 `815c1ddd6c4c1c0009f899b78d5e143e2b50a7f8e0d389031d717865f5d2aa66`。
`__ubusd_handle_lookup` 直接遍历 AVL 路径索引，`ubusd_send_obj` 逐对象编码和过滤方法。
C 的排队对象指针、原始前缀背压行为不能照搬；Rust 已修复的删除/重建对象续传与完整帧保证必须保留。
接口、调用者、权限与错误边界见 [ubusd 合同](../contracts/ubusd.md)。

改动前 Rust 每次查询/续传先收集整个剩余范围到 `Vec<u32>`，前缀下界也复制成 `Vec<u8>`。
若 N 个大对象每发送一个就停下，剩余 ID 收集量是 N+(N−1)+…+1。
本次直接借用 `BTreeMap::range`，只在暂停时拥有恢复路径；原始字节序、删除后的包含式下界、
空列表/未匹配/删除尾部状态、ACL、监视器和 16 KiB 批量发送策略均保留。
通过拆分字段借用，编码与发送可以进行，而索引在一次派发中保持只读；没有新增 unsafe 或依赖。

在上述每对象暂停夹具中，移除 O(N²) 的剩余 ID 收集，留下 O(N log N) 的路径重新定位及
O(N) 对象遍历；报文复制、socket 和客户端读取成本另计。普通批量查询仍有两次有界树遍历，
并非删除了所有重复工作。树遍历可能比连续数组访问更贵，因此必须实测。
使用借用键和克隆范围游标的 API 依据是 [Rust BTreeMap 文档](https://doc.rust-lang.org/std/collections/struct.BTreeMap.html#method.range)
与 [Range 文档](https://doc.rust-lang.org/std/collections/btree_map/struct.Range.html)。

没有采用持久化完整回复缓存：它会增加常驻存储，并引入 ACL、注册/删除与重载时的失效要求。
没有继续调整发送块大小；上一轮 [4 KiB 方案](R95_UBUSD_BATCH_EXPERIMENT.md) 的不利结果仍然有效。
本次也不声称已经证明这是一切负载下的最优算法。

## 实验身份与功能验证

- 改动前 `0eea3291…`，候选 `46940829…`，精确 C `cfb83044…`，正式 R89 `9b7169b3…`。
- 原实际构建路径 `/tmp/owrt-core-release/ubusd`、SDK、Rust 1.98.1、cwd、release flags 均固定。
  两个 Rust release 文件都为 507,880 字节。[候选补丁](r95-ubusd-range.patch)以 `abb3816` 为基线。
- 构建机 28 条单测和 clippy 门通过。六个历史门通过：root/ubus 用户功能差分、ACL/字节差分、
  模糊测试、资源边界、恢复；这些是构建机证据，不代替实机结论。
- SDK 测试程序的 28 条单测在物理路由器通过；ACL/原始字节排序夹具扩展到有、无监视器两条路径。
  包括部分写入、连续查询 FIFO、覆盖缓冲后的队列字节，以及删除/重建后的恢复。
- 16 个四方矩阵窗口、16 个独立复查窗口，共 **1,280,000 个计时请求成功**。
  另有 8 个物理分配/背压诊断窗口及一次单测+基本调用窗口。
- 每个窗口前后生产 C、配置、boot、宿主挂载、客户端健康和清理均通过。最终扫描无 R95 测试目录和
  进程引用。候选没有安装或启用。[验证身份与范围](r95-ubusd-range-validation.json)。

新背压 profile 第一次交叉构建因辅助源码复制时保留了错误文件名而失败；改为目标 `mod.rs` 后通过。
保留该构建日志，没有将失败计为通过，也未改变运行时来绕过它。诊断例程还修复了原先无限积累
`touched` 的夹具问题：现在像真实事件循环一样消费通知，两个 Rust 版本使用同一夹具。

## 分配与大对象背压：机制确实成立

先冻结 [普通诊断计划](r95-ubusd-range-profile-plan.json) 和
[背压计划](r95-ubusd-range-backpressure-plan.json)，各按 before/candidate/candidate/before 运行。
计数器在独立的一次操作统计分配；计时期间不累计原子分配计数。它们测量的是 Rust 派发+
请求副本+socket-pair 读取，没有独立守护进程事件循环，不是对 C 的性能验收。

普通 128 对象查询每次的 `allocations / reallocations / requested bytes`：

| 查询 | 改动前 | 候选 |
|---|---:|---:|
| 完整列表 | 2 / 5 / 1,012 | 1 / 0 / 4 |
| 前缀列表 | 3 / 5 / 1,044 | 1 / 0 / 24 |

剩下的一次分配是夹具复制输入报文。两次实机复现的分配计数一致。
[全部普通诊断值](r95-ubusd-range-profile-results.json)。

背压夹具每对象一个 16 KiB 方法负载，将发送缓冲设为 4,096，验证每次至少 N−1 次恢复，
并在计时外核对每个 DATA 的路径、ID、完整方法内容、序号以及最后的 STATUS。
下表耗时变化是两个窗口各侧中位数之比，**不是四方矩阵的配对统计量**。

| 查询/对象数 | 耗时变化 | 改动前扩容次数 | 候选扩容次数 |
|---|---:|---:|---:|
| 完整列表 / 16 | -12.88% | 20 | 0 |
| 完整列表 / 64 | -10.90% | 196 | 0 |
| 完整列表 / 256 | -11.65% | 1,284 | 0 |
| 前缀列表 / 16 | -10.92% | 20 | 0 |
| 前缀列表 / 64 | -7.20% | 196 | 0 |
| 前缀列表 / 256 | -26.29% | 1,284 | 0 |

256 对象完整列表累计请求分配量从 4,565,376 降到 4,219,904 字节，减少 345,472 字节，
约 **337 KiB**。这个量包含每次 realloc 请求的新容量，不能当作同时存活内存、实际复制字节或峰值下降。
报文排队所有权和恢复路径仍有分配。[完整背压结果](r95-ubusd-range-backpressure-results.json)。

| lookup_all_128_c4 | -7.13% | -8.08% |

六个多对象列表负载的 mean/p50/p95/p99 和主体 CPU 对改动前的配对中位变化均为负，
但还有以下未胜出项，不能宣称全面优于 C/R89：

- 对 C：128 对象串行 p50 **+0.55%**；invoke p95/p99 **+3.51%/+3.99%**。

+7.14%/+8.33%；lookup_prefix_64_c4 对 R89 +0.77%。不能用主体 CPU 改善代替这些成本。

## 不利结果的独立复查

发现并发反例后，另行冻结 [复查计划](r95-ubusd-range-recheck-plan.json)：
原候选字节不变，八个独立配对 block，每负载 20,000 次；只复查精确 lookup、lookup_c4、invoke_c4。
这是根据第一轮结果选择的诊断，不能代替四方矩阵，也不与原样本混合。

| 负载 | 平均延迟 | p50 | p95 | p99 | 主体 CPU/op |
|---|---:|---:|---:|---:|---:|
| lookup | -1.01% | 0.00% | -5.36% | -12.16% | 0.00% |
| lookup_c4 | -1.41% | +0.16% | -5.46% | -4.01% | 0.00% |
| invoke_c4 | -2.37% | -3.48% | -5.52% | -7.18% | -2.17% |

初次观察的平均退步没有持续复现，但 lookup_c4 每轮 mean 仍从 -14.95% 到 +7.64%，
p50 从 -22.58% 到 +27.83%；invoke_c4 mean 也有 +5.76% 的窗口。
CPU 量化单位降至约 0.5 µs/op，主体精确查询仍打平。
这既不能证明等价，也不能把原反例删除或归因于某一种未测量噪声。
[八轮全部正负值](r95-ubusd-range-recheck-results.json)。

## 内存和验收边界

四方矩阵结束时 proc 的 VmRSS/RssAnon 中位数（KiB）分别为：
C 972/144，R89 616/160，改动前 628/172，候选 626/170。
候选比改动前低 2 KiB，但匿名页仍高于 C 和 R89；这些异步计数不能证明精确驻留或峰值胜出。
实机无 smaps/PSS，分配诊断也不覆盖共享库、页缓存、内核 socket 存储和整个调用树。

保留此改动的依据是删除可解释的平方级收集工作、可重复的实机分配减少和背压收益、功能门通过，
以及对并发反例的独立复查；不是“所有性能指标已经更优”。仍需精确内存测量、廉价操作更细 CPU 计量、
尾延迟机制调查和预注册的独立确认实验。九组件组合验证与其他八组件的性能目标继续开放。

复算工具：[矩阵/复查](../../tools/r95_ubusd_pilot_report.py)、
[分配/背压](../../tools/r95_ubusd_profile_report.py)。原始数据在 `private/r95/ubusd-range/`，不入 Git。
