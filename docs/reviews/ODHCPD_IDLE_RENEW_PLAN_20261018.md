# v0.3.0：一次定向修复与两项复测

用户在首轮 A/B 后授权一次修复：空闲仅由事件或实际期限唤醒，并检查 Renew
回复前可后移的工作；只重测空闲 CPU 和 Renew，规则同前。两项通过后继续
v0.3.0 构建、恢复资格、刷机和发布；否则停止汇报，不自行增加优化轮。
旧[全项结果](ODHCPD_DEVICE_AB_RESULT_20261018.md)及其原件不修改。

## 模型、修复与边界

首轮空闲 C/Rust 为 14.846/64.370 µs/s。源码确认 Rust 已连接的 ubus worker
每秒 poll 返回一次；网络事件背压时另有 10 ms 重试；协议循环每秒做完整租约
协调并把 poll 上限固定为 1000 ms。精确 C 的 ubus 使用 fd 事件；其 DHCPv6
仍有每秒轻量到期扫描，不能声称 C 本身完全没有周期唤醒。

本次只消除无任务的周期轮询：worker 等 fd/命令/可用队列槽或断线重连期限；
协议循环等租约/offer/Decline、有效源前缀、RA、内核快照及失败重试等实际
期限。信号通过非阻塞唤醒通道到达主循环，SIGCHLD 触发回收，不能依赖原来
的一秒兜底。无事件且无到期任务时不设置轮询期限。墙钟只参与文件导出，不
代替单调时钟调度。

Renew 的已知顺序是内存绑定/PD 路由 ACK→回复→文件导出；不能把必要的 PD
ACK 后移。问题候选是前一个 Request 回复后的同步文件操作挡住后续 Renew。
采用首次 dirty 起 **1 ms 的一次性导出期限**：后续包不延后期限，到期写当前
完整状态，失败按一秒期限重试，普通退出前处理待写状态。hosts 原子写完后
才触发回调；纯续期不多发 leasetrigger。1 ms 是具备执行条件的期限，已有
同步 I/O 仍可能使实际写入更晚，不承诺硬实时上限。不加写入线程或文件缓存。

预测：无事件空闲窗中 Rust 的两次每秒工作消失，CPU 降至本轮可分辨地板；
Renew 由首轮约 1.05 ms 向无文件阻塞的约 0.2–0.5 ms 路径靠近。前者依据
明确的轮询点，后者只是由首轮 Solicit 0.248 ms 提出的可推翻估计。若仍超过
噪声，停止；不借用其它指标的改善抵消失败，也不追加归因和优化实验。

## 功能和仪器资格

Rust 构建/测试只在 Oracle 或 CI。针对期限、SIGCHLD/HUP/TERM、文件合并和
失败重试、ubus 队列满/断线重连检查新代码，并用最终 SDK ELF 运行既有实包
功能夹具。Oracle 不用于候选性能筛选；仪器仅做一次新 ELF 功能 smoke。
独立审查只覆盖本次改动的期限、唤醒和持久化边界。

沿用已验证的空网桥隔离和守卫：每样本独立 net/mount/PID/IPC/UTS namespace，
只读根、私有配置/ubus、无物理端口，不改现网或加载模块。生产仍运行精确 C。
设备前重新核验备份、v0.2.3 回滚材料和客户端健康，结束后逐哈希归档、清理
自有目录并核对生产身份、配置及客户端健康。整批仍有 600 秒守卫。

## 唯一复测批次

使用工具的显式 `--profile idle-renew --candidate-sha NEW_SHA`。新 SDK SHA
在设备运行前写入包、身份回执和冻结分析器参数；C 仍为
`53e534a12d412b1f138ab95d15431bc109bbb356dbfadfb8625397d585d2be82`。

- 地板：16 次时钟读取、16 次 UDP echo，保留原件，不扣除。
- 校准 `ABBAAB`、正式 `ABBABAAB`，十四个全新实例；每次安静 2 秒后测
  零租约的 3 秒空闲进程 CPU，包含 Rust 工作线程，折算为实际墙钟 µs/s。
- 沿用三 NA 客户端轮换的 16 组 Solicit→Request→Renew。前两者是建立相同
  状态所需动作，保留原包但不进入性能门。Renew 使用全部 16 次延迟中位数。
- 不发 RS、不做接口更新，不重测内存或首 RA，也不比较其它性能指标。

每项重新校准 `N=max(C 校准极差, Rust 校准极差, 2×实际时钟量化)`；空闲
量化随实际窗长折算。四个相邻正式 AB/BA 对分别算 Rust−C；**任一对 > N
即停止**，总体中位数只展示。仪器错误、超时或缺样同样停止，保留原件，不补样。
不设置固定微秒门槛、不做 PGO。冻结序列完成后分析一次。

本次只裁决这两项；通过后重新绑定 v0.3.0 新镜像、统一 APK、manifest 与新
回滚配置包，再按项目守卫和真实客户端健康验收执行部署和发布。
