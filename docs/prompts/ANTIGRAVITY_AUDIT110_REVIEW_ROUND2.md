## 3. 真机性能测量（我已授权）

我授权你在路由器（`ssh openwrt`，AX3000T，当前跑 v0.3.3）上**按组件依次**测量性能。
CPU 敏感的结论以真机为准，oracle 上的数据只用来筛选。

### 比哪几方

每个组件都比较以下几方：
- 真机上实际运行的 v0.3.3 二进制，作为基线；
- C 原版；
- audit-110 端点；
- **候选分支 `1e8c3bd5`**。这是我们真正打算合入的东西，必须证明它在真机上不退步。
- 如果第 1 节有值得单独测的 perf 组，再加上「候选分支 + 该组」这一方。

上一轮已经查明，重建出来的基线和发布 ELF 并不逐字节相同。所以要先在真机上做一次
「发布 ELF 对重建基线」的 A/A 对比，确认构建配方本身不带来差异，再拿重建的候选去比。

### 测量方法

- 尽量不碰正在运行的服务：
  - 一次性 CLI（uci、fw4 print/check、reload_config）：从 `/tmp` 直接运行候选，读写都只用 scratch 副本。
  - httpd：在另一个端口起候选实例。
  - rpcd：用 `OWRT_RPCD_LUCI_RPC_NAME` 这类对象名覆盖，与正在运行的实例并行跑。
  - dnsmasq 的 DNS 部分：在另一个端口、用独立配置跑，不开 DHCP。
  - ubusd：在私有 socket 上跑。
- 只有 DHCP、RA、netifd 这类必须接管真实接口才能测的项，才用替换窗口。每个窗口约 3 分钟，一次只测一个组件。
- procd 是 PID 1，ubusd 的热替换已经明确禁止。这两项只测并行实例能测到的部分；
  其余部分不测，在报告里写明。
- 每项指标要做到：
  - A/B 交替至少 5 轮，并做同二进制 A/A 噪声校准；
  - 报告中位数和区间，只有区间不重叠才算赢；
  - 内存读 `/proc/<pid>/status` 里的 VmRSS 和 RssAnon，不要看 `ps` 的 VSZ；
  - 同时记录空闲 CPU、上下文切换和二进制大小。
- 测量期间不在路由器上做其他工作；`/tmp` 是 tmpfs，内存只有约 256 MiB，用完立即清理。
- 路由器没有 sftp，用 `ssh openwrt 'tar xf - -C /tmp/…' < x.tar` 传文件。

### 替换窗口的安全要求

每个窗口都必须满足：
1. **开工前**：确认离线备份、v0.3.3 固件 SHA256 和回滚镜像都在（见 `docs/reviews/V033_DEPLOY_20261023.md`
   和 `private/backup`、`private/v033-deploy-20261023`）；记下真机上全部被替换程序的 SHA256，
   以及当前的客户端健康状态。
2. **运行方式**：驱动脚本在路由器上脱离会话运行（`setsid`），自带不超过 180 秒的自动还原。
   我的 Mac 连的是这台路由器的 Wi-Fi，会话随时可能断，所以不能依赖聊天会话来确认或还原。
   Mac 侧的驱动用 `launchctl submit` 或 `setsid` 脱离，用完删掉 job。可参考
   `tools/p6_window.sh`、`tools/p6_client_probe.py`、`tools/*_guard.sh` 的做法。
3. **判定健康**：只看客户端侧，即本次启动内的租约、经路由器的 DNS、经路由器的 HTTPS 出网。
   不看路由器的自检。
4. **每个窗口结束后**：确认运行中的二进制 SHA256 与开工前记录的完全一致，
   客户端健康恢复后才开始下一个窗口。不一致就立刻停止所有测量，报告给我。
5. 不刷机、不重启路由器、不改 `/etc/config` 或 overlay 上的持久文件。候选只放在 `/tmp`，
   只在窗口内用 bind mount 或临时替换。
