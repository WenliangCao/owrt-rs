## 现役隔离边界阻断

只读核验发现，生产 K 实际由原厂 ujail 启动，具有独立 mount/PID namespace，
namespace PID 为 1、uid 为 453。`procfs=false`，mountinfo 无 proc 挂载，
服务根中的 `/proc` 和 `/proc/self` 都不存在；daemon/ujail 的 Seccomp 与 filter 数均为 0。
因而 b861 的 `/proc/self/exe` 自执行不能在该边界成立。此前 18 项 smoke 在没有这个
限制的环境中通过，不能据此推断生产兼容。没有更改生产 jail、挂载、配置或服务。

已停止 b861 PGO：原 11 场景、50 个 raw profile 完成了一次训练，停止时位于 use-build；
没有运行最终资格、上传 profile 或启动 canonical PGO。保留输出为被阻断源码的证据。
修复方向是在普通启动时从内核记录的执行路径取得并保留映像 FD，再由固定平台边界
通过该 FD exec，不依赖 `/proc`，也不根据可伪造的 argv[0] 猜可执行文件。
修复后须先过等效无 proc jail 门，再重新冻结源码、训练和验收。

现场证据：`private/device-v022-preparation/production-boundary/summary.json`；
其 raw SHA256 为 `ef77759026a52495da12a994f1c648c9b73f1ec0d5e9fca3c2c869d9966863e9`。

## 无 proc 修复与新增证据

`8adcdeaf` 在普通 main 的配置解析、chdir 和降权前，从内核 `AT_EXECFN` 打开
`O_PATH|CLOEXEC` 映像句柄；平台层通过固定 fexecve hook 执行该句柄。内部子入口先分派，
不会重新解析 exec 后可能已经关闭的 `/dev/fd/N` 路径。CString argv/env 表在父进程完整
构造并由 hook 持有；原有标准流之外仍只有明确的 IPC 通道跨 exec。
首次打开执行路径是启动信任边界，保证其后的替换/删除不换映像，不声称能追回打开之前
已经被替换的文件。主进程因此多 1 个常驻映像 FD。

另一次实际 ELF 探针发现，b861 即使在 pre_exec 设置 SIGPIPE 默认，进入 Rust 运行时后
仍为 `SigIgn=0x1000`；普通 C sleep 对照为 0。修复在 lookup 内部入口恢复固定终止信号。
Oracle 新窄门 **49/49、0 警告**：platform 9、helper 28、lookup 8、原 main 失败项 4；
包含保留句柄在路径替换/删除后执行旧映像、坏映像返回原 exec errno、闭管道 SIGPIPE
终止。新输入 **193 项**，digest
`a6f9f1e7a7aca739842c6695e9c94945b80339cdbce11c88e8c4b950cfa987ae`。

真实 parent-spawned helper 的 native 探针中，K 与新版本的 owner/helper comm 都是
`dnsmasq-rs`，helper `SigIgn` 都为 `0x7002`，没有新增名称恢复逻辑。
现役内核为 6.12.94；核对其[准确版本源码](https://github.com/gregkh/linux/blob/v6.12.94/fs/exec.c)
已含 AT_EMPTY_PATH 按 file dentry 命名的修复，不能拿最初 6.12 的旧实现推断该路由器。
这仍不替代实际 musl 与真机观察。

后台 daemonize 保留原安全检查，仍需 `/proc`；现役 `-k` 前台路径不调用它。
不得将无 proc 前台支持扩大表述为任意后台调用也等价。

准备实际成本对照时还发现 K 的既有限制：helper 无 proc 时会采用按 RLIMIT 逐 FD
关闭的 fallback，而 K 的运行期 hostname lookup 直接依赖 `/proc/self/fd`。
因此 40 次启动对照分为 helper 两侧各 10 次无 proc、resolver 两侧各 10 次同一
proc-visible 环境。K 的无 proc lookup 失败须实际保留一次负控，不进行失败耗时排名；
新版本无 proc lookup 单独验收。FD 压力在 Oracle 用最终实际 PGO ELF 验证，
不冒称 A53 结果。A53 主矩阵为 148 窗，详见[设备批次](SAFE_V022_DEVICE_BATCH.md)。

## 改动与边界

两个业务根 `components/dnsmasq/src/{lib,main}.rs` 均启用
`#![forbid(unsafe_code)]`。唯一新增第三方直接依赖是精确版本 `rustix = 1.1.5`；
残余底层边界放在不发布的内部 crate `components/dnsmasq/platform`，逐处说明安全条件。
普通描述符所有权、系统调用及错误转换迁至 rustix/std；不增加每查询 payload 复制。

以下是 b861 的迁移统计，尚未把后续 fexecve 修复计入。按 `unsafe {`、`unsafe fn`、
`unsafe extern` 文本形状分别统计，v0.2.1 的业务目录为
234/2/15，新业务目录为 0/0/0，内部 crate 为 60/1/14。该数字包含各 cfg 和测试，
用于描述迁移范围，不代表独立漏洞数或形式化安全证明。目标编译实际验证业务根的禁令。
必要边界及审阅限制见 [安全审阅](SAFE_V022_20261017_REVIEW.md)。

helper 和运行期 resolver 改用自执行，当前通过保留的映像 FD 进入新的 Rust
运行时，代价是多一次 exec 和 IPC 请求编码；helper child 额外保留 2 个 CLOEXEC 管道
描述符，resolver child 多 3 个管道 FD，parent 在发送请求期间多 1 个。resolver 的标准流
是否由新运行时重新打开须实际计数，不将管道增量当作全部 FD 增量。不能将这一部分称为
零成本包装。普通 daemon 分离只保留专用启动 fork，安全条件限于已检查的固定调用图。

## 当前成本模型与下一轮裁决

K 的单族公开规则约 73 µs/query，同名 A+AAAA 为 83.1 µs/query。本轮普通路径的
syscall 数、payload 复制和分配应保持不变，预测差异小于 5 µs；以同轮 K/K 校准
测量噪声，并用 K/候选配对测量推翻或支持该预测。

生命周期成本另算：总成本包含 owner、helper/resolver 子进程的 CPU、就绪时间、
FD 与驻留资源。自执行可能把成本转移到子进程，不能只看 owner CPU。
当前没有 self-exec 的真机数字，因此不能预先接受性能等价。
最终 PGO 使用独立训练，完整正确性通过后才进入隔离真机筛选与完整矩阵；
任何可分辨退化都阻止接受。生产健康是停止隔离测试的依据。
