## 实现与残余边界

唯一新增第三方直接依赖为固定版本 `rustix = 1.1.5`；仓库内
`components/dnsmasq/platform` 不发布。一般 FD 所有权和系统调用使用 rustix/std，
必要 libc/ABI 操作集中在小 crate，每处说明安全条件，不增加每查询 payload 复制。
CI 使用 `-Dwarnings` 和编译日志门；Rust、Cargo、linker 及未知 warning 都失败，
固定 SDK 配置/元数据提示独立保留。没有用 allow 掩盖本轮编译诊断。

恢复 fork 的提交新增 326 行、删除 1156 行，删除 self-exec 映像句柄、内部命令行入口、
请求编码和额外请求管道。helper 恢复命令/事件两管道，resolver 恢复单结果管道、
每步最多 4096 B 读取及 WNOHANG。固定信号先屏蔽，child 在关闭 FD 前禁用继承的
signal wake；子入口只接收纯 owned 快照，结束后 `_exit`，不回到父 ownership graph。
没有新增 unshare/maps 检查、seccomp 测试启动器或其他单线程证明工具。

业务 unsafe 为 0；platform 保留 **63 个 unsafe block、1 个非 extern unsafe fn、
13 个 extern C block、0 个 unsafe impl**。这是含测试/cfg 的语法计数，不是漏洞数。
输入类型、实际入口和必要例外见[安全审阅](SAFE_V022_20261017_REVIEW.md)。
单线程、没有共享可写映射或外部回调是固定应用的前提，与 K 的生产场景相同；
不把泛型约束或非捕获 fn 当作任意上下文下的 fork 安全证明。

父进程不再多持有映像 FD，helper 恢复两个非标准 IPC 端点。resolver child 保留
0/1/2，避免关闭后复用 Rust 隐藏标准流 owner 的 FD；比 K 多三个短暂标准 FD，
不能宣称所有资源完全相同。前台 helper/resolver 不依赖 proc；后台 daemonize 的
既有 proc 检查仍保留，不把前台支持扩大表述为所有后台调用均无 proc 可用。

## 已拒绝候选

- `b8617f57` 的 self-exec 使用 `/proc/self/exe`，与现场 UID453、无 proc 的 ujail
  不兼容。旧 smoke 没有覆盖这个真实边界，不能作为生产资格。
- `8adcdeaf` 改为启动时保留映像 FD，解决无 proc 启动，但实际 PGO ELF 在 resolver
  4 个空槽时返回 EMFILE；K 同条件成功，8 槽两者成功，2 槽两者失败后恢复。
  新请求/结果管道、exec-error pipe 及常驻映像 FD 是真实代价，因此拒绝。
  profile 未上传、未触发 canonical PGO、未上设备。旧矩阵停止新派发，已完成
  8 组/19 项安全收尾且保留结果，不把失败改签为通过。

旧压力证据为 `private/oracle-v022/proc-free-8adcdeaf/final-runtime/pressure-compact.json`，
其 PGO 处置见同根 `pgo/disposition.json`。旧 Oracle 启动预演的 resolver CPU 增加
仅用于定位 self-exec 成本，不当作 A53 性能裁决。历次工具错误、strict 回调断言失败
及修正前结果仍保留，最终结论使用明确归属的新输入。

## 当前成本模型与下一轮裁决

K 的公开规则单族约 73 µs/query，同名 A+AAAA 约 83.1 µs/query。本轮普通查询 syscall、
复制和分配预计不变，预测差异小于 5 µs；用同轮 K/K 噪声及 K/候选配对验证。
恢复 fork 去掉额外装载、初始化和请求编码；FD 压力已经支持这一判断，启动 CPU
仍需实际 A53 对照。owner 与 helper/resolver 的 CPU 分开保留，不能遗漏子进程成本。

新源单独训练 PGO，不复用被拒绝版本的 profile，不屏蔽 missing/mismatch 诊断。
完整正确性后执行[既定设备批次](SAFE_V022_DEVICE_BATCH.md)：40 次启动，再 148 窗。
任何可分辨退化阻止接受，生产健康决定停测；无可分辨差异不称严格等价。
