# v0.2.2 安全边界审阅

**业务代码 unsafe 为 0；受限 fork 回迁未发现新增源码阻断，可进入编译和运行验收。**
本轮冻结产品提交为 `a97edbc1382fc92b83110ed0822284aafeee7461`。对照已发布 K 的
真实 helper/resolver 实现，审阅 platform 封装、两个子入口及生产调用点；不把源码审阅当作最终正确性或性能通过。结论限于固定 OpenWrt AArch64 musl
程序及其当前调用图，不是通用 Rust fork API 的安全证明。

## 范围与计数

`src/lib.rs`、`src/main.rs` 两个业务根均设置 `#![forbid(unsafe_code)]`。
唯一新增第三方直接依赖是固定版本 `rustix = 1.1.5`；`dnsmasq-platform` 是仓库内
`publish = false` 的小 crate，没有再引入 libc crate。

源码语法计数包含测试和各 cfg 分支，因而不等于某次发行构建的实际调用数量：

| 范围 | unsafe block | unsafe fn（非 extern） | extern C block | unsafe impl |
| --- | ---: | ---: | ---: | ---: |
| v0.2.1 业务 src | 234 | 2 | 41 | 0 |
| 当前业务 src | 0 | 0 | 0 | 0 |
| 当前 platform/src | 63 | 1 | 13 | 0 |

其中 `process_fork.rs` 有 7 个 unsafe block、1 个 extern C block；只承担 libc fork、
固定信号屏蔽/恢复、固定 dispositions、close_range 和 `_exit`。这些操作没有挪回业务层。
逐文件数量可用 `unsafe\s*\{`、`unsafe\s+fn`、`(?:unsafe\s+)?extern\s+"C"\s*\{`
及 `unsafe\s+impl` 的语法位置复核。RELRO 另有 1 个 unsafe extern C 回调定义
和 1 个同型回调参数，K 也已有这两项。旧报告的“15 个 unsafe extern”包含 13 个显式
unsafe extern block 和这 2 项，不能与上表全部 extern C block 的口径混用。计数本身
不是安全性指标。

## fork 回迁的实际边界

两个生产入口恢复 K 的结构：helper 使用命令/事件两条管道，resolver 只使用结果管道。
已删除 self-exec 映像 pin、额外请求管道、启动编码和内部命令行入口。该版本不需要
为 helper/resolver 打开 `/proc`，也没有新增 unshare 或 seccomp 运行门。

- **输入与调用图。** helper 的 `HelperStartup` 仅含 `Config` 的 PathBuf、
  Option<Vec<u8>>、bool，以及容量、uid/gid、初始化模式；resolver 的
  `(Vec<ServerRule>, bool)` 嵌套字段仅含 Vec、IP 与标量。没有借用、FD owner、锁或
  用户回调。helper 子入口只访问快照、两条 IPC、标准流以及既有脚本/身份接口；
  resolver 只调用已有 libc 名称扩展并编码结果。它们不会访问父 logger、listener、
  RefCell 或运行时 owner。实际调用点没有跨 fork 持有供子入口重取的 stdio/全局锁。
- **信号与 FD。** 固定服务信号先屏蔽；子进程在关闭任何 FD 前将
  `SIGNAL_WAKE_WRITE` 设为 -1，再恢复 K 的 helper/resolver dispositions。
  遗留 HUP/USR/ALRM handler 至多操作复制的原子量，不能向已关闭并复用的 wake FD
  写字节。父子各自恢复原 mask，启动失败路径也恢复。子进程先 drop 本边界持有的
  父侧管道 owner，再通过固定 close_range 区间关闭其余 FD；没有按软 RLIMIT 扫描
  而漏掉高位 FD 的 fallback。失败直接 `_exit(5)`，不带着未隔离的 FD 进入业务。
- **终止与析构。** 子入口只拥有纯数据快照和保留的管道；正常返回或 unwind 后均
  `_exit`，不会返回到复制的父栈。panic payload 被 forget，避免其额外析构；
  panic=abort/OOM 本身终止进程。父进程独自返回原 owner graph。父侧新管道所有权
  在失败、正常返回和子进程分支均有明确去向，没有重复构造 OwnedFd。
- **stdio、TLS 和 libc。** 继续用 libc fork 保留 libc 自身的 fork bookkeeping；
  当前生产程序没有自定义 panic hook、allocator、外部 atfork 回调、生产线程创建
  或共享可写 mmap。0/1/2 保留，允许 stdio、panic 路径继续访问它们，避免关闭后
  复用隐藏 stdio owner 指向的 FD。helper 与 K 相同；resolver 因此比 K 保留
  **3 个临时标准 FD**。父进程没有 self-exec 映像常驻 FD。后者的实际计数仍交运行
  验收，不能据源码宣称所有 FD 与 K 完全相同。

单线程及无外部共享状态是当前固定应用的前提，与 K 的使用场景相同。
`Send + 'static` 和非捕获 `fn` 只是接口形状，不能证明任意 T、global、TLS 或第三方
回调都适合 fork；本审阅没有用它们作通用证明。新增调用者、FD/锁字段、线程、共享映射、
panic hook 或依赖回调时，必须重新检查这两条真实调用链。未把多线程 libtest 的运行
成功当成生产单线程前提的证明，也不要求为该假设另造测试启动机制。

## 其余保留的 platform 边界

此前 `b8617f57` 已审阅的其余边界没有因 fork 回迁扩大职责：

| 边界 | 保留原因与约束 |
| --- | --- |
| datagram / socket options | rustix 1.1.5 未覆盖所需 pktinfo ancillary 和少数选项。单 iovec、32/40 字节 align-8 存储及固定选项；长度有界，FD 借用，不复制 payload。LP64 MsgHdr 与目标 musl ABI 一致。 |
| interfaces | getifaddrs、特定 ifreq/ARP ioctl、任意字节接口名保留窄封装。RAII 释放列表，借用名字不逃逸；固定布局、长度和 FD 生命周期在边界内。 |
| credentials / close | NSS 的 reentrant 查询后复制结果；libc credential 操作保留进程级语义。close_file 唯一接管关闭责任，Linux EINTR 不重试。 |
| daemon startup | 保留既有专用后台启动 fork；该路径仍检查 proc 的单线程/共享可写映射。前台 procd/ujail 不调用它。父/中间进程报告后 `_exit`，不回到服务 owner。 |
| signals / poll | 固定 handler 仅用目标锁自由原子、非阻塞单字节 write 或 `_exit`；保存 errno。poll 接受可能已关闭的整数 FD 快照，不伪造 BorrowedFd。 |
| text / resolver / limits / RELRO | 保留镜像 libc 的文本、名称解析和 sysconf 语义；结果在存活期复制。静态 PIE RELRO 仅保护已检查的主镜像完整页，不暴露任意地址 mprotect。 |

每处 unsafe 的安全说明留在源码实际操作附近；剩余 unsafe 不等于还可机械删除的业务
代码。使用 libc 的少数边界和当前 rustix 未覆盖的 ABI 仍需审阅维护。

## 已拒绝结果与验收边界

`8adcdeaf` 的 self-exec 候选已拒绝：resolver 只有 4 个 FD 空槽时 K 成功、候选出现
EMFILE；新增请求管道、exec-error pipe 和映像 FD 不是纯包装等价。Oracle 启动预演还
显示 resolver CPU 增加，但它不是 A53 最终性能结论。旧失败和原始证据保留，不能被
本次源码审阅改签通过。

新 fork 产品源码仍须完成目标 SDK/CI 的零编译警告、完整正确性、no-proc/FD 压力及
K 对照真机验收。此前 self-exec 构建的零警告、native 或 PGO 产物不能替代新源码结果。
研究分支保持独立，不据本审阅发布、刷机或合入 main。
