# dnsmasq：警告清零与安全边界

独立分支 `research/dnsmasq-safe-v022-20261017`，以精确 K 的 v0.2.1 产品输入为基线。
本轮不部署、不改正在验收的 v0.2.1，不把安全性改动继承为已经通过 K 的资格。

## 顺序与边界

1. 先消除路由器目标 aarch64-unknown-linux-musl 的 22 条现有 Rust 警告：8 条无用项与
   14 条重复 extern 声明冲突。依实际 SDK 头文件统一 ABI，不加 allow 或过滤日志。
   对 dnsmasq 和内部封装包启用 warnings-as-errors，使用一次临时 warning 负控验证门。
   固定 SDK/Kconfig 提示、其他组件旧警告不属于本轮；不改驱动、内核或原厂包依赖。
2. 仅新增 rustix 这一个第三方直接依赖，固定版本和锁文件。底层例外放在嵌套的小 crate
   `components/dnsmasq/platform`；dnsmasq 的 lib.rs/main.rs 根均加
   `#![forbid(unsafe_code)]`。内部 crate 不发布，给主 crate 的最终 API 均为安全封装，
   不允许调用点靠一条“保证正确”的注释绕过类型或生命周期要求。
3. rustix 已覆盖的 syscall 直接迁移；保留相同非阻塞、CLOEXEC、EINTR、错误和批次语义。
   只有不能表达的 pktinfo 控制消息、按原 libc 语义的查询/格式、特定 ioctl、启动边界等
   可以留 residual unsafe，每处说明对象大小/对齐、有效期、所有权与调用时机。
   不把全部旧 unsafe 原封不动搬入新 crate，不引入额外线程或每请求分配。

## 当前成本与风险模型

K 同名 A+AAAA 命中 CPU 83.12 µs/query，单族公开规则路径约 73 µs/query；原 mixed
相对 J 仍有 +4.21 µs 趋势。此次目标是保持行为和成本，不追逐新性能收益。预计 syscall
次数、包复制、分配和 owner 调度均不变；若增加每请求分配/额外 syscall，或真机差异超过
本轮 K/K 噪声与 5 µs 关注量级，就推翻“包装可被消去”的预测，先解释或修复再接受。

已识别的边界：rustix raw backend 不写 libc errno，必须由返回 Errno 构造错误；
PEEK|TRUNC 返回完整报文长度，不能误用已复制长度；非 UTF-8 接口名不能强制转字符串；
rustix 1.1.5 ancillary API 没有 IP_PKTINFO/IPV6_PKTINFO；kernel_fork 不运行 libc atfork
且有线程运行时限制，不能机械替换 libc fork。不得将这些兼容差异隐藏成警告清理。

## 验收

- 第一阶段一次真实 SDK 编译确认 0 Rust 警告，保留实际日志及负控结果。
- 最终代码完成后，目标平台全测试、原 44 组/67 项正确性、发货边界及 source corpora
  全部通过；新增用例只覆盖此次边界变化，原失败/允许差异保留，不降低现有门槛。
- 新源码独立重训 PGO，禁止用旧 K profile 的 missing/mismatch 警告强行发货。
  程序/组件包仍须不超过 2,500,000/1,400,000 B。K 精确 ELF
  `f6710d37912bd414e01b32be97fd73b2ed4cf2ddf637eaa1254fa660603eba08` 为对照。
- 路由器完成 v0.2.1 观察与收尾后才安排隔离实例；先 K/K 校准和固定 K/新候选配对筛选，
  再完成原 118 窗全场景及同名双栈确认。不得以热大核结果代替 A53 裁决，不可分辨不称
  完全等价；任何可分辨性能退化都阻止接受。具体批次和噪声界限在开跑前冻结。
- 本轮完成标志是警告门、业务根 forbid、例外安全审阅、完整正确性及真机无可分辨回退
  都有数据。新版仍只留独立分支，未获本轮部署授权。
