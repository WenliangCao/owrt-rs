## 问题与修复

| 问题 | 修复及验证 |
| --- | --- |
| 无条件 DHCP 广播仍要求、保留 NET_ADMIN | 根据 C 的首条广播规则判定能力需求；无条件广播且关闭 ping 时无需该能力，条件规则仍需它。正常与缺能力对照通过。 |
| 缺能力时先改写 PID 再失败 | 能力检查移到 PID 操作之前；失败保留原 sentinel。 |
| 设置组失败时删掉新 PID | PID 清理改为正常终止后的显式操作；降权失败退出 5，保留自身 PID，与 C 一致。 |
| SIGINT 被当作 SIGTERM | 普通前台模式继续服务；debug 模式退出 5，保留 PID。结论限服务 ready 后的信号。 |
| TFTP 用降权前 UID 判断文件 | 文件策略和打开器使用实际运行身份；UID 453 自有的 0600/0644 文件可读，内核权限拒绝对照保持。 |
| UDP 转发答复丢失原目的地址 | 每个接收者保留目标地址和入口接口，发送时设置正确源地址；连接式 UDP 客户端也能收到答复。 |
| 缓存 CNAME 的本地终点丢失网段 | 把同一查询的 `local_network` 传到终点回答，正确执行 `localise-queries`。 |
| 接口与显式监听地址未取并集 | 普通模式使用通配 socket 并按 C 规则准入；显式目的地址、TCP 与 UDP 一致；拒绝 TCP 先 shutdown，保留 C 的 EOF 行为。 |
| 静态绑定不存在接口仍启动 | 静态模式按 C 的初始化顺序报错退出 2；动态模式保留等待接口出现的行为。 |
| ethers 先于 DHCP host 文件合并 | 先重载 host 文件再合并 ethers，保留名字、租期、来源、推导地址处理和存活规则的 DECLINE 状态。 |
| 通配 TCP 不读取真实入口接口 | 通过 C 使用的 pktoptions ABI 获取 IPv4/IPv6 入口，执行 TCP 专用准入；保留绑定模式、回环例外和无元数据时的 fallback。 |

前十项的失败均用相同输入复跑确认后修复。最后一项由独立源码审查定位，
以精确 C 建立允许/拒绝基线，再验证修复后的防御行为；没有运行旧 Rust 的
跨接口放行复现。每项都有已提交的回归测试或可重复差分工具，权限和准入
同时包含拒绝对照，比较器包含缺行/错误观察的负向校准。

审查未在该范围确认其他具体 netlink ABI/边界问题。此结论不是任意配置、
任意启动信号竞争或完整 TFTP 权限矩阵的证明。
