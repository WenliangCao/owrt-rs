# TCP cache snapshot timing screen — no candidate accepted

The frozen 48-run schedule completed with **24,000/24,000 successful
snapshot/lookups and zero errors**. Every run and the earlier allocation and
correctness evidence is retained. All three candidates fail at least one
unchanged gate in `TCP_SNAPSHOT_SCREEN_V1.md`; none is adopted into product
code. This is a Rust-representation primitive screen, not a C/Rust service
comparison or router performance result.

The coordinated build-host window ran on CPU 2 from 14:16:27 to 14:16:45 UTC
on 2026-10-01. Other continuation agents held remote builds/tests for that
window. The compiler, source `e77d966`, binary hashes, order, 5 warm groups,
25 measured groups of 20 snapshots, capacities and thresholds were unchanged.
No round was added, retried or selected after examining results. Existing
exact-C 22,571-operation gates were reused; they were not regenerated by Rust.

## Frozen decisions

| Candidate | Combined CPU reduction at 1,000 / 10,000 | Snapshot requested-heap reduction | Rejection |
| --- | ---: | ---: | --- |
| compact | 0.25% / 0.53% | 4.78% / 5.08% | Memory reductions below 20%; CPU gain below threshold/noise; small-profile guards also fail. |
| shared | 48.67% / 29.84% | 49.20% / 52.34% | Population CPU exceeds the 5% ceiling: worst pairs +10.63% at 150 full, +13.71% at 1,000 full. |
| top | 0.48% / 0.10% | -0.05% / -0.01% | First mutable lookup copies the whole cache; memory and combined CPU targets fail; small-profile tail guard fails. |

Shared entries do reduce snapshot work: the paired CPU ratio spread is only
0.64 / 0.56 percentage points at 1,000 / 10,000, below their gains. But each
new entry adds an allocation and the frozen population guard uses the worst
paired ratio, so the population regressions cannot be waived using a better
median or a new timing window. The 150/1,000 population samples vary across
rounds; the screen does not establish a stable magnitude for that regression.
It establishes that this candidate failed the predeclared guard. Parent heap
increases of 2.23%/2.36% and extra per-entry allocation remain visible.
