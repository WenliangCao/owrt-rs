# DHCP message counters at state-machine events

The ordinary DHCP/BOOTP producer now matches the actual C `dhcp_reply` counter
trace in **16 scenarios / 88 ordered observations**, on both the host probe
and a frozen native Linux probe. A negative calibration changes one observed
Rust counter: the same 88 observations yield 87 matches, one mismatch and exit
1. No expected value is generated by the Rust implementation.

`LocalProvider` owns `MessageCounters` and exposes a read-only copy through
`message_counters()`. `StateProvider` borrows that owner while executing state
transitions; direct primitive callers can omit the sink. The 11 u32 slots are
BOOTP through NOANSWER in C's public order. The PXE slot has no runtime producer
yet and is explicitly outside this unit. Lease allocation/prune counters remain
owned by the existing `LeaseStore`; this change does not duplicate them.

The writes occur at their source-defined logical branches:

| Event | Counted boundary |
| --- | --- |
| BOOTP | Valid hardware/non-proxy branch completion, including allocation/configuration errors that produce no reply |
| DISCOVER | After selection/identity handling, including no-address and ordinary ignored-client outcomes |
| OFFER | Successful DISCOVER after the rapid-commit diversion |
| REQUEST | After mode/server-ID early-return rules; rapid commit skips it |
| ACK | Ordinary committed request or valid INFORM, before wire delivery |
| NAK / NOANSWER | Ordinary request failure / rapid-commit failure respectively |
| DECLINE | Valid server ID and requested address, including unknown leases |
| RELEASE | Valid narrowed context and server ID, including unknown leases |
| INFORM | Before ignored-client or zero-ciaddr return; valid replies also count ACK |

`quiet-dhcp` is now parsed once into `DhcpConfig` and forwarded to the producer.
In C it suppresses the ignored-DISCOVER increment through an early return; it
does not suppress the INFORM counter. The change preserves the existing packet
behavior for ignored clients. Other log-related runtime capabilities retain
their existing acceptance boundary.

The full C caller also showed that a missing initial serving context returns
before ordinary message handling, including INFORM. The provider now retains
packet-triggered lease pruning but returns no reply and no message count in
that case. An INFORM with an initial context whose client address later fails
narrowing still succeeds, matching the distinct C branch. A proxy-only initial
context similarly stops before ordinary DHCP message counters.

Counters wrap at u32 and remain cumulative across hosts/cache reload, lease
file writes, DNS publication and failed socket sends. The runtime regression
uses the actual counted state provider and a failing sender: ACK and REQUEST
counts persist even though no datagram was sent. They are not packet-receive or
successful-send counters. Storage adds 44 bytes of counter payload per provider,
without per-lease fields, heap allocation, sockets or threads for counting. No
CPU or memory improvement is claimed.

The oracle includes unchanged hash-pinned `lease.c` to observe its live list,
links the exact `rfc2131.c` and other reference objects, and executes actual
`dhcp_reply`. It uses the six image COPTS and recorded ubus/libubox dependencies.
The fixture requires `no-ping`, read-only empty lease initialization and an
isolated loopback-only namespace. It opens no DHCP listener. The comparison
includes actual response classification, active lease count and every message
counter after each command; full C wire replies remain in private stderr logs.

Coverage includes successful and rejected requests, unknown release/decline,
ignored clients with/without quiet mode, INFORM without ciaddr, allocation
capacity, BOOTP refusal and conflicting static ownership, rapid ACK/NOANSWER,
malformed/pre-message inputs, counter wrap and reload preservation. PXE,
leasequery, main/ubus publication and modes still rejected by the daemon require
separate gates. These primitive results alone do not establish service
equivalence. The later ordinary BOOTP service slice is independently verified
in [BOOTP_SERVICE_PHASE.md](BOOTP_SERVICE_PHASE.md); rapid-commit runtime wiring
retains its explicit unsupported boundary.
