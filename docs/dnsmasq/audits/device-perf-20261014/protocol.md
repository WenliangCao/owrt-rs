# AX3000T 真机性能协议：device-safe v1

本协议在第一组正式 C/Rust 成对结果之前冻结，作为
[`PERFORMANCE_PROTOCOL.md`](../../PERFORMANCE_PROTOCOL.md) 的本次安全缩减版。
用户已授权低用网时段的临时独立实例测试。本轮只测不改产品；不把旧协议的主收益
目标或容量门槛当作本轮已经满足的结论。预试记录、失败和取消窗口全部保留。

## 版本与隔离

- 对照为精确 OpenWrt 25.12.5 镜像的 C dnsmasq 2.93，ELF SHA256
  `097a9e21a2ca479cf5add1725e672d48179e7973eea836d030eafbea588cab87`。
- 候选为 main 对应的最终 SDK ELF，SHA256
  `50e591a9d9dc1e6578888b14690b5b38415a9db886a492a2960a0c75b3eeb57c`。
  另存 main commit、构建输入对应证明及工具哈希；不把文件名当作身份。
- 同一台双核 AX3000T、同一内核；两版都复制到 `/tmp`，各自使用相同的独立配置。
  使用 `--keep-in-foreground`，保留 C 正常的 TCP fork 行为，不用 debug/no-daemon
  模式替代。禁用查询日志；保留私有 leasefile 的读写。
- 测试进程必须处于新建且只有 loopback 的 network namespace。
  `unshare` 或接口核对失败就退出，不得退回生产 network namespace。
  不创建通向 LAN/WAN 的接口；发生器与受控上游均在该隔离环境内。
- network namespace 不隔离文件和 Unix socket。测试实例必须使用自己的配置、
  hosts、pid、日志和 lease 文件；不得启用生产 ubus 名称、真实 DHCP helper，
  不得读取配置后执行真实 lease hook。上述集成成本不在这次 DHCP 数字中。
- 生产 dnsmasq 不停止、不替换、不发信号、不改配置；不写闪存、不安装包。
  临时文件只放本次 `/tmp` 目录。独立期限/健康守卫只终止本次测试进程组。

## 安全门与预试选档

正式计时前保存生产 PID/starttime/ELF、配置文件哈希、服务状态和健康基线。
测试期间低频检查生产 DNS、LuCI、WAN 状态、主机 CPU 和 MemAvailable：

- 生产 DNS 或 LuCI 出现基线以外失败、生产进程变化、WAN 掉线，立即停止测试。
- MemAvailable 低于 80 MiB，或主机两核合计 busy 比例连续 3 点超过 35%，停止测试。
  busy 以 `/proc/stat` 区间差计算，分母为主机两核总时间，不能混用单核百分比。
- 守卫失联/退出或期限到达，停止本次测试进程组。实验结束核对生产进程、哈希、
  配置、服务、socket/子进程及 `/tmp` 清理。不能仅以 SSH 可连作为恢复证明。

DNS 预试只在 C 上按 200、1000、2000 请求/秒顺序逐档进行，预热 5 秒、正式 20 秒。
每个场景在这些固定档中选择最高安全且无错误的档；到任何安全门即停止递增。
选档还要求发生器发出全部计划请求，没有 skipped/transport/wrong/timeout，
发包延迟 p95 不超过 1 ms。没有档符合则该场景标记受限，不自行扩大负载。
正式 C/Rust 使用同档，不为一方降低速率。单轮服务 CPU 不足 10 ticks 时，可以
保留延迟/资源结果，但 CPU 快慢受计量精度限制；不得在看到正式结果后加压补出收益。
预试不进入正式五轮统计。Rust 若在已选档触发安全门，保留失败并停止该场景；
若需重新设计，先形成有原因的新协议版本，不覆盖本版结果。

## 场景与时间边界

所有名字为合成 `.test`，地址为文档地址段，固定随机种子 `0x293001`。
配置/hosts/租约规模根据现场只读清点派生，禁止将真实名字、地址、MAC 提交到 Git。
每个场景的最终参数、配置和数据文件哈希在其正式第一轮之前写入运行清单。

| 场景 | 固定输入与边界 |
|---|---|
| UDP 缓存命中 | 800 名字，A/AAAA 70/30；cache 1000；预热后核对受控上游计数 |
| UDP 未命中 | 每次唯一名字，A/AAAA 70/30；受控上游固定 1 ms 延迟、TTL 120 秒 |
| UDP 混合 | 80% 缓存名字、20% 唯一名字，A/AAAA 70/30；上游计数验证真实比例 |
| TCP 命中与未命中 | 两种场景分列；固定连接数、每连接 100 次后重建；包括连接/关闭计数；不与UDP吞吐混合 |
| DHCP DORA | 隔离 loopback 的替代服务/客户端端口；合成客户端；完整 DISCOVER/OFFER/REQUEST/ACK，leasefile保持真实写入 |
| DHCP 续租 | 先完成合成客户端建租，再计 REQUEST/ACK；建租与正式续租计数分列，不能把DORA+续租混称纯续租 |
| hosts/HUP | 私有 hosts 两个完整版本交替；测信号发出至新 marker 正确可见；20次/轮、至少1秒周期，含daemon读文件I/O，不含信号前准备/rename写入 |
| 配置变更/启动 | 单独测测试实例停启、配置读取与DNS可用；HUP不重读所有启动配置，不能把HUP结果称为任意配置reload |

DNS 每轮预热 5 秒、正式 20 秒。正式共五轮，固定顺序：C/R、R/C、C/R、R/C、C/R。
DHCP、重载与启动沿用五轮交错；每轮至少 10 秒，具体节流/操作数必须在预试前记录。
一轮只运行一个被测服务；依赖、观察器和发生器输入完全相同。禁止计时窗口抓包、
编译、fuzz、压满CPU或运行其它审计负载。用户的日常自然流量仍可能存在，必须报告波动。

不压测最大容量。固定交付速率下的正确完成数/秒只说明该负载能被承接，不代表
最大吞吐相同。安全无法在真机覆盖的场景直接列为未覆盖；oracle补测须另表标明。

## 计量与统计

每轮保留计划、发出、完成、正确、错误、超时、跳过、迟到、重连、上游请求数量，
原始逐请求延迟、配置/ELF/工具哈希、开始结束时间、所有资源采样和退出状态。
发生器以固定时间表发包，不能在回复变慢后自动降低交付率。

- 延迟分别报告实际发包至正确回复、计划发包至正确回复，以及计划至实际发包延迟。
  p50/p95按轮算；只有每轮至少10,000个有效样本时列该轮p99。
  超时和错误单独计数，不能通过排除它们制造低延迟。不存在回复的请求不伪造延迟。
- CPU 用服务完整进程树的 user+system，包含 C 的 TCP 子进程。端点关闭所有测试
  TCP 连接、等子进程被 parent 回收，再核对稳定的 parent
  `utime+stime+cutime+cstime`；不得对有回收竞态的非原子 tree 采样直接作差。
  无法取得稳定端点则 CPU 结果受限。读取目标内核的 `_SC_CLK_TCK`，不能假定100。
- DNS CPU 若覆盖预热与正式窗口，则除以两段全部正确操作数，标题注明包含预热；
  正式延迟仍只取正式窗口。DHCP建租若进入CPU窗口必须单列或明确为组合成本，
  不能除以纯续租数。发生器、上游和观察器CPU分列，不加到服务CPU中。
- CPU报告ticks、秒、单核等效占用和每正确操作成本。单轮CPU不足10 ticks不排行；
  对四个截断字段作保守比较，C/R CPU差异还需超过8 ticks对应的计量精度下限。
- 无 `/proc/smaps`/`smaps_rollup` 时，PSS/USS为不可测；不以RSS或RssAnon代替私有内存。
  分别报告RSS、RssAnon、RssFile、RssShmem、FD、线程、子进程以及主机MemAvailable。
  子进程RSS相加可能重复共享页；峰值只是采样峰值，不能称瞬时最大值。

每指标列五轮原数与 median [min,max]。相对差为 `Rust median / C median - 1`。
令 `W=max((Cmax-Cmin)/Cmedian, (Rmax-Rmin)/Rmedian)`；只有至少4/5对同方向且
相对差绝对值大于W，才描述为测得更快/更慢，此外CPU须满足上述精度要求。
否则写“差异未超过本轮波动”，仍列数值。零中位数、缺轮、发生器受限或功能失败
不作快慢判定。此规则是保守工程判断，不把五轮称为统计显著或总体置信区间。

不能把本轮低负载实验推断为长期稳定性、全屋断网风险、最大容量或正式安装包
集成验收。结果报告必须区分服务处理成本、固定上游延迟和自然系统噪声，并说明
可测退步对实际家庭请求速率/延迟的影响。
