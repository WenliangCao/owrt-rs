# Device-safe v2：预试安全门后的降载

在任何正式 Rust/C 配对结果产生前冻结。保留 v1 及其所有预试记录。

C 的 UDP hit 预试 200、1000 qps 完成且答案/计数正确；2000 qps 时主机两核
busy 连续三个样本超过 35%，独立守卫按预定规则停止该测试进程组。
停止前 DNS/LuCI 健康无失败，停止后确认生产 C PID/starttime/ELF 不变、
WAN/WAN6 up，测试进程无残留。此记录是安全中止，不是服务吞吐上限，
也不用于 C/Rust 速度比较；同机发生器、上游和家庭活动都占用主机 CPU。

为降低家庭网络风险，正式 DNS 五场景统一固定 **200 qps**，取消其它场景的
1000/2000 档递增，不再寻找上限。先仅作每场 C 200 qps 校准，再以同样速率
执行五轮交错 C/R、R/C、C/R、R/C、C/R。每轮预热 5 秒、正式 20 秒；其它
输入、正确性/波动/CPU量化规则及 35%/80MiB 安全门全部沿用 v1，不放宽。

该变化由正式对照前的安全中止触发，不依据 Rust 快慢选择负载。1000 qps C
预试仅作附录观察，缺少匹配 Rust 测量，不能据此计算加速比。正式数据只能
说明固定家庭负载下的延迟、完成速率和资源成本，不给峰值吞吐结论。

原 STOP 与守卫日志完整回拷并核验后，另启低负载测量窗口；每次窗口仍有
独立最长一小时守卫。若 200 qps 再触发同一安全门，不继续降低档位寻找通过，
保留未完成的场景并结束真机负载测试。
