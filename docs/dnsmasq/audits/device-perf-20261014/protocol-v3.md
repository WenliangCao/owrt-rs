# Device-safe v3：按生产服务健康继续真机测量

本版在真机正式 C/Rust 成对结果产生前冻结。用户在 v2 停测后明确要求继续真机
对比：降低测量工具开销或将发生器外置，以正在服务的 DNS、管理页面和双栈外网
是否正常决定停测，Oracle 结果只能作参考。此后续授权取代 v2 的“不再进行真机
负载”处置；不删除、不改判 v1/v2 的两次 CPU 守卫中止或其它失败记录。

本版更改健康停测依据和观察器实现，不修改产品、不提高请求速率。旧窗口保留为
旧方法的 C 校准，不能与新窗口拼成正式配对；最终报告分别标明协议版本及工具哈希。

## 不变的边界和负载

- 使用 main 对应的同一最终 SDK Rust ELF
  `50e591a9d9dc1e6578888b14690b5b38415a9db886a492a2960a0c75b3eeb57c`
  和精确镜像 C ELF
  `097a9e21a2ca479cf5add1725e672d48179e7973eea836d030eafbea588cab87`。
  上机前再次核对文件、运行映像和配置输入身份。
- 生产 dnsmasq 始终运行，不停止、不替换、不重载、不改配置。测试实例仅在新建的
  loopback-only network namespace 内运行，不能接触 LAN/WAN；文件只写本次 `/tmp`
  目录，不安装包、不写闪存。各实例配置、leasefile、日志、PID 和 Unix 接口均隔离。
- DNS 五场景仍为 UDP hit/miss/mixed、TCP hit/miss，全部固定 **200 qps**。
  800 缓存名字、A/AAAA 70/30、cache 1000、EDNS 1232、1 ms 受控上游延迟及 TTL 120
  不变。mixed 为 80% 热名字/20% 唯一名字；实际上游计数必须随结果报告。
- UDP 32 clients、TCP 8 clients，每 TCP 连接 100 个答复后重建。hit/mixed 先通过
  相同的 UDP 查询预热父进程缓存，不能只预热 C 的 TCP 子进程。
- DNS 每轮预热 5 秒、正式 **20 秒**，五轮交错 C/R、R/C、C/R、R/C、C/R。
  不压测最大容量，不把固定交付率的完成数称为吞吐上限。
- DHCP 和 lifecycle 沿用测前冻结的
  [具体场景清单](scenarios-lifecycle.json)：DHCP 150 个合成客户端、100 次操作/秒、
  5 秒建租/预热加 20 秒正式续租；启动、配置停启、8-host HUP、1000-host HUP
  每轮各 20 次、至少 1 秒周期，同样五轮交错。正式续租不能混入 DORA；建租延迟
  单列，CPU 若跨建租和续租则必须标为组合成本。

## 观察器与依赖开销

旧观察器在缺少 `/proc/PID/task/PID/children` 时会对每个子进程分别扫描 `/proc`。
新观察器每次采样最多构建一次 PID/PPID 表，再从该表寻找被测服务树；不重复扫描
整张进程表。采样周期为 1 秒，不把观察器开销计入服务 CPU。

发生器、受控上游和观察器分别保存已知 PID/starttime、user/system 计数及可得的
退出 CPU 用量；短命的 C TCP 子进程仍通过服务父进程的 waited-child 累计计入。
已知依赖 PID 不能靠扫描命令行猜测，不允许 PID 重用后的计数混入同一窗口。
旧中止窗口缺少完整依赖计数的局限保持不变，不能以新数据反向证明旧事件的根因。

优先使用上述低开销、同机 loopback 方法，两版使用同一套工具和拓扑。若确需
外置发生器，在任何受影响场景的正式第一轮之前另存拓扑、传输路径、时钟与
工具哈希的补充清单，重新成对执行该场景；不能将跨 Wi-Fi 延迟与 loopback
延迟拼表。外置不是把测试监听口直接暴露给家庭客户端的授权。

计时期间不并发其它 benchmark、Oracle 补测、编译、抓包或追踪。记录整机 CPU
作为上下文，但它包含工具、网络栈和家庭活动，不能代替被测服务 CPU。

## 测前生产健康基线与停测门

在开始正式负载前，复用同一个健康守卫，连续采集**至少 120 秒**的轻量生产基线：
对已有本地 DNS A 记录以 loopback UDP 约每 2 秒探测一次，并保存全部 RTT；
预计约 60 条，以实际日志条数 N 为准，不把未发出的探测算作样本。同时每 5 秒
检查 LuCI。基线没有测试进程组；到期 STOP 仅结束基线，不算生产健康失败。
探测只查询已有名字，不改服务配置，不依赖公网 DNS。每次 timeout 为 **700 ms**。
核对事务 ID、NOERROR、非截断且存在 answer；任一基线查询错误、超时或这些
答案检查失败，则不开始负载，保留结果并先调查。

基线 p95 使用最近秩 `ceil(0.95 × N)`，冻结持续延迟门：

`T_dns = max(200 ms, 10 × baseline_p95_ms)`

计算后的基线、T_dns、探测目标身份及代码哈希写入私有运行清单，再开始正式
窗口；同一组五轮 C/R 使用相同阈值。不得看过正式快慢后调阈值。700 ms timeout
始终独立生效；如果计算出的 T_dns 超过 700 ms，则先调查异常基线，不开始负载，
也不截断计算结果以伪装健康基线。原基线日志和到期 STOP 独立归档后才开启正式守卫。

| 项目 | 运行中检查及动作 |
|---|---|
| 生产进程 | PID/starttime 或预期 ELF 身份变化，立即停测 |
| 生产 DNS | 每 2 秒查询同一已有本地记录；错误、超时、答案异常立即停测；连续 3 次正确答复 RTT 超过 T_dns 也停测 |
| LuCI | 每 5 秒请求同一无认证管理入口，700 ms 总期限；超时、连接错误或不符合已确认基线的 HTTP 错误立即停测；当前 403 是已核对的登录入口响应，不算故障 |
| 双栈外网 | Mac 每 30 秒分别以 IPv4、IPv6 HTTPS 检查已有测试目标；失败立即通知控制器停止本次测试进程组，不继续下一窗口 |
| WAN | 已有默认路由丢失或接口明确变为 down，停测；正常地址/前缀寿命倒计时不算故障 |
| 可用内存 | MemAvailable 低于 **64 MiB（65536 KiB）**立即停测；这是避免内存耗尽的底线，不是性能达标线 |
| 守卫/期限 | 守卫退出、失联或窗口最长一小时期限到达，停止自己的测试进程组；每个新窗口都须先核对健康和守卫身份 |

**取消整机 busy 35% 的自动停测门。** 整机 CPU 继续记录，不作为单独的硬停止条件；
生产服务健康、延迟和内存底线决定停测。这是用户明确纠正测量目标后的测前变更，
不是根据 Rust 对照结果放宽标准，也不把此前两次中止改称“通过”。

200 ms、700 ms、连续 3 次和 64 MiB 均是本次运行的健康保护界限，不能用于声称
DNS 正常延迟应为 200 ms、CPU 效率合格、Rust 占用合理或容量足够。性能结论仍由
相同交付条件下的服务数据和波动决定。低频健康探测不能保证捕获所有短暂异常。

发生真实生产健康失败后，立即停负载并收集原因；不自动重启生产服务，也不为
凑齐五轮自动重试。守卫只操作经过 PID/starttime/PGID 与任务目录核验的测试组，
组 leader 必须存活到子进程全部退出。正常结束先清空测试组，再停止守卫。

## 数据资格与判定

沿用 v1 的数据与统计口径：逐轮保存完整输入/产物哈希、计划/发出/正确/错误/
超时/跳过/迟到计数及二进制请求记录；预热和正式窗口均须核对错误和计数守恒。
上游队列丢弃、错误、未解释的请求/答复差额必须保留，不能用低成功率换速度。

服务 CPU 前后端点须为同 PID/starttime，TCP 子进程关闭并回收，稳定计数无回退。
计数包含预热时，分母也包含预热正确操作；百分比使用实际端点时间差。依赖 CPU
单列。RSS、RssAnon、RssFile、RssShmem、FD、线程和子进程分别记录；无 smaps 时
PSS/USS 不可测，不以 RSS 或 RssAnon 代替私有内存。

每指标列五轮值和 median [min,max]。定义
`W = max((Cmax-Cmin)/Cmedian, (Rmax-Rmin)/Rmedian)`；相对中位差绝对值须大于 W，
且至少 4/5 对同方向，才判有可辨别差异。CPU 还须每轮至少 10 ticks、两版中位
差超过 8 ticks 的精度下限。否则保留具体数字，写“未超过波动/计量精度”，不排名。
每轮不足 10000 个有效样本不列 p99。出现未完成窗口时，保留失败而不拼接旧协议
窗口补足样本；Oracle 参考表始终与本机结果分开。

结束后完整回拷原始材料至本机 `private/`、逐文件核哈希，清理全部自有 `/tmp`
文件、进程、socket/namespace 与挂载，再核对生产 C 身份、配置、LuCI、DNS 和
WAN/WAN6 状态。报告记录实际完成范围与最终状态；不改产品代码、不推送 GitHub。
