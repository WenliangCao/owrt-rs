# 真机 v3 补充：家庭规模 DHCP（测量前冻结）

本补充只增加 `dhcp-home6` 场景，不替换或重判原 150 客户端 DHCP 场景。
现场只读清点为 6 条租约；150 客户端的处理成本和内存结果不能直接外推到家庭规模。
新增场景是补齐用户要求的实际使用规模。协议在该场景第一组 C/Rust 结果之前冻结；
即使结果不利于 Rust，所有轮次和失败仍须保留。

沿用 [v3 协议](protocol-v3.md) 的精确 ELF、隔离、健康守卫和统计规则。
待原 100 个主窗口和 2 个预定补充窗口全部结束，再更新并记录测试 runner 的新哈希，
执行本场景。不得在正在运行的管线中替换脚本，也不修改产品代码或生产服务配置。

## 固定输入

| 参数 | 冻结值 |
|---|---|
| 场景标签 | `dhcp-home6` |
| C / Rust | 与原 v3 相同的精确 C / main 最终 SDK ELF |
| 重复与顺序 | 五轮成对交错：C/R、R/C、C/R、R/C、C/R，共十个窗口 |
| 合成客户端 | 6 个固定 MAC，与原场景前 6 个一致 |
| 地址池 | 私有 network namespace 内 `127.0.0.10`—`127.0.0.15` |
| 租约上限 / 时长 | 6 / 12 小时 |
| 预热 | 5 秒，100 个操作/秒；预计 6 次 DORA + 494 次续租 |
| 正式窗口 | 20 秒，100 次 REQUEST/ACK 续租/秒；预计 2000 次纯续租 |
| 完成后 | 私有 leasefile 恰好 6 条；没有 RELEASE，不接触生产网络 |
| 其它条件 | 同一 loopback 接口、端口、无冲突 ping、私有 leasefile；不调用生产 DHCP helper、不注册生产 ubus 名称 |

负载工具和资源采样工具不变。所有 6 个客户端必须在正式窗口开始前完成 DORA；
否则判为建租失败，不能把后续 DORA 混入纯续租。保留 scheduled/sent/correct、
错误、超时、skipped、send lag、配置与脚本哈希及完整原始资源采样。

100 次/秒是固定测量负载，远高于 6 台家庭设备日常续租频率。它验证在相同交付
负载下的小租约表处理成本，不代表真实家庭 DHCP 流量，也不代表最大吞吐。

## 计量与解释

- 正式续租延迟每轮预计 2000 个样本，按 v3 列 p50/p95 和五轮波动；不列 p99。
- 每轮仅 6 个 DORA 样本，单独保留全部原始延迟及 min/median/max。若总表需要
  p95，须标记为接近样本最大值；不据此对 DORA 尾延迟作强快慢结论。
- 当前 before/after CPU 端点覆盖预热和正式窗口，预期组合为 **6 次 DORA +
  2494 次续租，共 2500 次完成操作**。按实际成功计数验证后报告组合 CPU，
  不将该 CPU 除以 2000 并称作纯续租成本；DORA CPU 未单独隔离。
- RSS、RssAnon、RssFile、RssShmem、FD、线程及 CPU 都保留原始值和五轮范围。
  没有 PSS/USS，不能把 RSS 或 RssAnon 当作私有内存。
- 原 `dhcp` 的 150 客户端与新 `dhcp-home6` 分表。不得合池计算中位数、删除
  不利轮次，或用新结果否定原 150 档真实存在的成本。跨规模比较须注明采集时段不同。

静态分配、`no-ping`、无真实 helper/ubus 和 loopback 的限制与原 DHCP 场景一致。
本场景只贴近现场租约数量，不模拟 Wi-Fi 客户端时序、动态地址搜索、冲突检测或
完整系统事件开销。生产 dnsmasq 全程不停止、不替换、不改配置；结束清理仅限本次
拥有的临时测试进程和 `/tmp` 文件。
