# v3：一次 UDP miss 成对补充（执行前登记）

原五轮 UDP miss 中，r5 Rust 计划 4000、实际发出并正确完成 3996，skipped=4，
最坏响应 174.267237 ms。21 次已发查询的延迟超过 100 ms，发送时刻集中于正式
窗口约第 10 秒。同段观察器一次采样耗时约 129 ms 但自身仅增加 1 tick；生产
DNS 仍正确，LuCI 仍返回基线 403。存在共同等待/调度干扰迹象，但原因未确定，
不能用它为产品免责，也不能把未发出的请求写成服务丢包。

为补足有效稳态对照，仅追加 **r6 一对，顺序 Rust→C**，在原 DNS 五组尝试结束、
无负载阶段健康核对和守卫续期开启后执行。仍使用相同 ELF、配置、工具、200 qps、
5 秒预热＋20 秒正式、32 客户端、唯一名字、70/30 A/AAAA、1 ms 上游和相同安全门。
不改变 CPU、波动、计数正确性等判定规则，不修改产品。原始标签明确为 r6，
不覆盖或改名 r5；任一 r6 窗口数据质量失败都不再追加。

报告必须同时给出六对所有尝试的计划/发出/正确/错误/跳过及最坏尾部。原 r5
仍无效，原 v3 五轮资格不因此改为通过。若 r6 全部有效，条件性稳态比较只用
**r1–r4+r6，排除 r5 的 C/R 整对**，不能仅替换较差的 Rust 窗口。此 subset 的
CPU/常态延迟结论必须明确条件，并同时突出 r5 的 4 skipped 和 174 ms 异常。
若 r6 无效，只保留受限结果，不放宽门槛、不进行随机重复直到通过。
