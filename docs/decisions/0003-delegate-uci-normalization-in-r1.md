# 决策 0003：R1 委托目标系统 UCI 规范化并保持共享基线

> 日期：2026-08-31
> 状态：已定
> 阶段：R1

## 背景

C1-01 要求替换实现的规范化输出与固定 revision 的 `uci show` 逐字节相同。这不仅包含常规
package，还包含含点 tuple 成功/失败、畸形输入和 `/var/run/uci` override。现在重写一份 UCI
parser 会扩大 R05 职责，并产生第二套尚未证明等价的语义。

原实现的基线又是 BusyBox `md5sum` 的文本格式。保持该格式是无事件切换和立即回退的条件。

## 决策

R1 候选保持窄进程边界：

1. 扫描集合、优先级、旧基线比较和事件顺序由 Rust 显式实现；
2. 每个条目的规范化仍调用目标系统 `uci -c … -C … show <name>`；
3. digest 仍调用目标系统 `md5sum`；
4. 事件仍调用 `ubus call service event`；
5. Rust 负责进程 timeout/cancellation、单实例锁、资源上限、JSONL trace 和退出码。

crate 不引入第三方依赖。仅为 `flock(2)` 和 `signal(2)` 保留两个窄、带安全说明的 FFI
调用；V1 再用匹配 OpenWrt SDK 验证最终 ABI 与 package 集成。

## 与原实现的有意差异

合同内的事件语义不变。C1 §8 明确未定义的故障路径采用 fail-closed：

- `ubus` 返回非零：继续剩余事件并保持原实现“基线推进”，但记录逐条结果且进程退出 2；
- `uci` 无法启动或超时：不重写基线，返回依赖/临时失败；
- `ubus` 超时或进程被取消：不重写基线，使下一次可重试；
- 并发候选运行：第二个进程立即返回临时失败，不进入共享 `config.check` 竞态。

这些差异不被写回 C1 兼容要求，也不声称改变了现有系统行为；它们是候选在未定义故障边界
上的可观测、安全默认值。

## 后果

- R1 可以证明 event set 与基线字节等价，而无需发明 UCI 语义；
- 候选仍依赖镜像中已经保留的 `uci`、BusyBox 和 `ubus`，符合保留成熟执行面的项目原则；
- 未来若要移除这些进程依赖，必须单独建立合同并做新的逐字节差分；
- V1 只需处理 package、默认禁用的切换和 release-matched 构建，不得顺带扩大检测职责。
