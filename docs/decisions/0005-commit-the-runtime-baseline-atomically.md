# 决策 0005：候选基线通过同目录临时文件原子提交

> 日期：2026-08-31
> 状态：已定
> 阶段：V1 故障注入

## 背景

R1 正常与已知故障用例全部通过，但 V1 首次磁盘满注入发现：候选用 `File::create` 直接截断
`/var/run/config.md5`。当新基线超过剩余空间时，进程虽然退出 70 并输出 fatal trace，旧基线
已经变成 4,096 字节的半截文件。该路径属于 C1 §8 的未定义故障区，但不符合 R1 已选择的
fail-closed 原则。

## 决策

候选先在同一 `/var/run` 目录写 `config.md5.reload-config-rs.tmp`，完整写入后执行
`sync_all`，最后用同文件系统 `rename` 原子替换正式基线。写入或同步失败时删除临时文件，
正式基线保持原字节。

单实例锁保证两个候选不会争用临时文件。原实现与候选并发仍是 C1 未定义边界，本决策不把
它扩展成新的跨实现锁协议。

## 后果

- 正常路径生成的 `config.md5` 字节和事件语义不变；
- 只读 I/O 与磁盘满现在都退出 70、产生 dependency fatal trace，并保留旧基线；
- 新增单元测试固定“临时文件无法创建时旧基线不变”；
- V1 重新执行 11/11 差分、6/6 既有故障和 package 构建，全部通过；
- 这一改动只收紧未定义故障边界，不修改 C1 兼容合同。
