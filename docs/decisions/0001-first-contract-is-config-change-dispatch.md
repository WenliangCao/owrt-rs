# 决策 0001：第一个兼容合同选择配置变更检测与分发

> 日期：2026-08-31
> 状态：已定
> 阶段：C1

## 背景

I0 gate 通过后，17 项控制面职责中只有一项被分类为`优先用 Rust 替换`：
R05 配置变更检测与分发（`/sbin/reload_config`）。C1 只为**一个**职责冻结合同。

## 决策

**C1 的对象是 R05。** 合同见
[docs/contracts/config-change-dispatch.md](../contracts/config-change-dispatch.md)。

## 依据（对照 EXECUTION_PLAN §17 的选择标准）

| 标准 | R05 的情况 |
|---|---|
| DEP/SRC/RUN 证据完整 | 是。实现是 `procd` package 安装的 17 行 shell（DEP 全文）；uci 与 busybox 行为有固定 revision 源码；基线与事件面有 I0.7 与 C1 Q15 的运行态观察 |
| 接口稳定且边界窄 | 是。输入是两个目录加一个基线文件，输出是一种事件载荷 |
| 调用者已知 | 是。三个：`/etc/init.d/boot`、rpcd `uci.apply`/`reload_config`、人工调用 |
| 可离线或模拟验证 | 部分。算法可离线验证（本次已做）；规范化等价性必须在设备上差分（留给 V1） |
| 失败不破坏启动、管理或数据面 | 是。失败表现为服务使用旧配置，不影响启动与转发 |
| 可立即恢复现有实现 | 是。原文件保留，切换调用方即回退，无需重启 |
| Rust 有可说明收益 | 是。见下 |

## Rust 的可说明收益

不是"内存安全"这类泛化理由，而是三条具体的：

1. **静默失败可被消除。** 现有实现不检查 `ubus call` 的退出码，基线被无条件重写，
   一次失败的投递会被基线吸收后永不重发（合同 C-08，风险 RK-01）。
2. **扫描集合的边界可被显式化。** 现有实现把 `/etc/config/` 下每个文件名都交给
   `uci show`；本设备有 **7 个**含点文件名无法解析对应 tuple，因而静默产出空条目
   （合同 C-03）。只要这些 tuple 继续不存在，它们的文件内容改动就不会触发事件。
3. **比较语义可被表达为类型。** 现在的"规范化"是一次 shell 重定向加 `md5sum -c`，
   三种不同状态（修改、删除、格式无效）折叠成同一个 `FAILED` 信号。

## 明确不做的事

- **不修复 C-03。** 当前 7 个含点 tuple 查找失败并产出空条目的行为必须被复刻。
  改成直接读取历史备份内容会让它们突然变为可检测，改变 procd trigger 的触发面——那是行为变更，
  不是兼容实现。
- **不改变检测粒度。** 现在是整文件粒度。改为 section 或 option 粒度需要新合同。
- **不先写 Rust。** 按 RK-01，先让投递结果可观测并证明新旧事件集合相同，
  之后才允许改变检测机制。
- **不创建 crate。** C1 只冻结合同与参考测试。

## 前置条件的处理

| 前置 | 状态 |
|---|---|
| RK-01 让投递可观测 | 已写入合同 §9 作为实现顺序约束 |
| OQ-07 设备配置偏移审查 | 已由 I0 follow-up 关闭；结论是设备可作为 oracle，但必须使用**当前**配置全集，不得替换为镜像默认配置 |

OQ-07 的结论对本合同有直接影响：参考 oracle 的输入必须包含那 7 个含点文件，
否则 C-03、C-06 和 c10 切换用例都测不到。

## 后果

- R1 可以开始实现，但必须先满足合同 §9 第 1 步；
- V1 必须做规范化输出的逐字节差分；
- 其余 16 项职责的分类不变，C1 不为它们开工。
