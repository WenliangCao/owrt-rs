# 临别指点：怎样做性能与算法研究

写给 Codex。你这一轮做事勤奋、证据干净、从不作弊，这些是底子，别丢。但你把大部分
力气花在了「把事情做对」上，很少停下来问「我做的是不是对的事」。下面每一条都来自
这轮 dnsmasq 研究里真实发生的事，按重要性排序。细节出处见
`docs/dnsmasq/PERF_EXPERT_REVIEW_20261016.md`；文中时刻均为会话记录里的 UTC。

## 1. 先写下「成本在哪」的模型，再动手；每轮实验都要能推翻它

你在 10-16 凌晨到下午做了约十轮真机实验，几乎全在回答路径里省指令和分配，每轮
2–4 tick。而你自己 01:38 的 owner32 数据已经写着：同一个 G，200 qps 时用户态 17.5k 周期，
饱和时 3.5k，IPC 0.44 对 1.57。这组数字说的是「低速率下八成用户态周期是冷缓存停顿，
与指令数无关」。它在你的结果文件里躺了十二个小时，没有被当成线索。后来三条关键假设
（顺序核、分配、代码体积）是用户 20:12 替你提出的。

为什么重要：没有模型，实验只能验证「这个改动有没有用」，不能回答「为什么没用」。
连续三轮小效应时，错的几乎一定是模型而不是实现。

怎么做：
- 开工前写一段话：总成本 ≈ A + B + C，每项给一个估计数和出处。写不出数字的项就是
  下一轮要测的东西。
- 每轮实验先写预测值。结果和预测差一倍以上，先改模型，再改代码。
- 同一区域两轮都只有仪器噪声量级的效应，立刻上一层问「主导变量是什么」，不要做第三轮。
- 看到自己的数据里有和模型矛盾的数字（比如「指令少 14%，周期多 31%」），把它当成
  本轮最重要的发现，不要只写进表格。

## 2. 仪器要配得上你想看的效应；先测地板，再测差距

真机 CPU 用 100 Hz tick，5000 次查询下 1 tick 就是 2 µs，同一二进制轮内就漂 ±2 tick。
你定的「>8 tick」门槛对这个仪器是合理的，但仪器本身可以换：`clock_getcpuclockid`
的纳秒 CPU 时钟任何内核都有；或者每窗多跑十倍查询。你一直在用一把刻度 16 µs 的尺子
找 5 µs 的东西。另外，Rust 只收发包就 74 µs、C 全部处理 86 µs，这个对比最需要的
参照——C 的骨架或一个 echo 守护进程给出的内核地板——从头到尾没有测。

怎么做：
- 开始一个系列之前，先定「我在乎的最小效应」，再确认仪器分辨率不大于它的三分之一。
  做不到就先修仪器，这不算跑题。
- 任何差距研究，第一轮测地板：不可压缩的部分有多大。剩余差距减去地板，才是你的战场。
- 一轮实验里同时记录「这个数字的仪器噪声是多少」。同一二进制重复测一次，比五对候选
  对照更能告诉你仪器的本底。

## 3. 代理指标必须和真实目标同向，否则立刻换掉

你用三级漏斗筛候选：native hot15（热循环，IPC 2.6）→ oracle owner32（IPC 0.44）→
A53 十窗。前两级和真机的相关性很弱：9e 在 owner32 高负载有收益，真机不可区分；
803 在前两级中性，真机变慢。更糟的是你用 native 热循环里 configured-CNAME +7% 把
reply-layout 原型「退役」了——布局改动的目的就是冷缓存体制，用热体制否决它是反的。
owner32 里 send-lag p50 从 0.68 涨到 2.76 µs 被反复写成「退化」并阻止 promotion，
那是饱和闭环里负载生成器的发送滞后，生产里没人能感知。

怎么做：
- 每个代理指标用一个已知效应的改动校准一次：它和真机结论同向吗？不同向就不用它筛。
- 问自己：如果这个指标变差 30%，用户会发现吗？不会的指标不能当门。
- 测试环境和真实环境差在哪，要写成一句话（这里是「乱序大核、大缓存、热循环」对
  「顺序核、小缓存、每 5 ms 一次冷启动」），每次用代理数据下结论前重读这句话。

## 4. 门槛是你造的仪器，不是法律；小收益要叠加后再判

5c 五对全同向、6ab 五对全同向、fresh-address 变化恰好等于 W，这些大概率是真实的
3–6%，你把它们逐个写成「不可区分」然后丢掉。「不过门就不叠加」加「单项必须 >8 tick」，
结构上排除了任何小于剩余差距三分之一的改进。E 那轮也一样：「一个无效窗整轮作废」
让任何候选都过不了，最后是用户 14:50 替你改的规则。

怎么做：
- 区分「测不到」和「不存在」。五对同向但低于门槛的结果记为「待叠加」，不记为「无效」。
- 行为等价的小改动攒成一个组合候选上真机，用一轮判断总和。
- 当一条自己定的规则让成功在逻辑上不可能时，显式改规则并写明理由，而不是继续服从它。
  改规则是研究的一部分，服从一条错误规则不是严谨。

## 5. 下一步选「最能减少不确定性的」，不是「最现成的」

PGO 产物已经建好，因为 ELF 超预算 4% 从未运行；A53 target-cpu 因为 .text 涨 8.7%
没测；热代码聚类卡在链接器机制上停了；速率扫描三分钟就能裁决冷缓存模型，没做。
与此同时，十轮真机都给了同一区域的变体。你选实验的标准事实上是「哪个已经准备好」。

怎么做：
- 列出三个候选实验，各写一行「它会把模型的哪个未知数变成已知数」和「成本几分钟」。
  选信息量除以成本最大的那个。
- 一个实验被预算、流程或工具卡住时，先问「绕过它测一次会损失什么」。用超预算的
  产物测一轮收益，比永远不知道收益强。
- 换方向的信号：同一层次两轮空结果；模型预测连续失准；用户提出的假设你无法用已有
  数据反驳。
- 停的标准：剩余差距小于「地板 + 仪器噪声」，或所有剩余方向的预期收益都低于噪声。
  「流程走完了」不是停的理由，「还有现成原型」也不是继续的理由。

## 6. 严谨和官僚的界限

835 次提交里 511 次是文档，产品源码改了约 2.3k 行，文档增加 73.8 万行。每个候选走
native240 → owner32 → 965 测试 → SDK → 两三轮独立复核 → 真机十窗 → 独立审计 →
多篇「retain / bind / freeze」文档，四到六小时换一个 2 tick 的结果；真机十窗本身
只要五分钟。你做对的部分要保留：产物哈希、原始数据不删不换、分析脚本可重放、
冻结门抓到了 D 的真实启动缺陷、用计数窗口验证了「零分配」这个前提。这些是严谨。
为每个筛选写三份收据、给每轮空结果做独立审计，是官僚。

判断标准：
- 严谨 = 这个结论不可能以一种会改变决定的方式出错。问「如果这个数字错了，谁会做出
  不同决定」，没人就不用核验。
- 核验的成本不超过实验本身的两成。超过了说明你在核验不重要的东西。
- 每轮只留一份计划、一份结果。进入候选的改动才需要独立复核；探索性筛选不需要。
- 文档只写别人复现和决策所需的内容。「我做了什么」的流水账放进 git log，不放进报告。

## 7. 主代理的时间花在模型和下一个实验上，不花在中继和等待上

主线程 2507 次工具调用里，491 次是转发消息、192 次是后续任务、160 次是睡眠；用户
17:35 不得不明确要求你「不要反复睡眠刷进度，亲自做研究」。四个子代理各自写了
30–50 MB 的日志，大量内容是互相确认状态。约 100 个工作树、50 个分支没有清理。

怎么做：
- 主代理只做三件事：维护成本模型、决定下一个实验、写给用户的结论。执行交给子代理。
- 给子代理的任务书写清三样：要回答的问题、停止条件、交回什么数字。不要让它们自己
  决定要不要多做一轮审计。
- 不轮询。子代理完成会通知你；等待期间做模型和原型。
- 机器资源的瓶颈不是真机分钟，是你准备一轮的小时数。真机实验要攒成批、一次排程。
- 每轮结束清理工作树和分支，保留标签即可。

## 8. 向用户汇报：第一句话是数字和决定

你的账本第一段是「passed 957 short checks, all 44 correctness families/67 jobs,
the original boundary corpora, and independently audited 110-window …」，用户得自己从
几百行里找出「82 对 114」。用户两次催「不要早停」，一次纠正规则，一次替你提假设，
每次都是因为报告里看不到「现在我认为成本在哪、下一步测什么、为什么」。

怎么做：
- 第一句：结论和关键数字。第二句：它改变了什么判断。然后才是证据。流程只在它影响
  可信度时才提。
- 每份报告有一段「我现在的模型」和一段「下一轮要裁决什么」。没有这两段的报告是日志。
- 问用户的问题只在不同答案会导致不同工作时才问；问时给推荐选项。

## 9. 保留你做对的那些习惯

D 的正确性失败你先临时归类为已知 HUP 差异，发现反例后立刻撤回，最终找到真实的启动
缺陷，并把修复和性能改动分开计时——这是对的。syscall 和 PMU 对账几小时内就定位了
「多一次空读」和「指令少、周期多」——这是对的，问题只在后来没有追到底。证据不可变、
不选择性重跑、空结果全部保留——这些让我这次的诊断成为可能。继续这样做。

## 每轮实验开始前，问自己

1. 我现在的成本模型是什么？本轮哪个结果会推翻它？我的预测值是多少？
2. 我在乎的最小效应多大？仪器分辨率是它的三分之一吗？地板测过了吗？
3. 这个指标和真实目标在同一体制里吗？上次校准是什么时候？
4. 这是「最能减少不确定性」的实验，还是「最现成」的实验？成本几分钟？
5. 如果结果是两个 tick，我打算叠加还是丢弃？规则允许叠加吗？不允许就先改规则。
6. 本轮要写的文档里，哪些是复现和决策所需，哪些只是证明我做过？
7. 汇报的第一句话是什么数字、什么决定？
