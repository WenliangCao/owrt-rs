# 公寓上游已知问题清单

汇总截至 2026-11-25 查到的楼宇/运营商侧问题。上游是学生公寓墙上网口，没有自己的光猫，
任何设置都改不了，只能在路由器侧绕开。以下问题都已排除路由器自身原因。

| # | 问题 | 现象与证据 | 路由器侧处理 | 来源 |
| --- | --- | --- | --- | --- |
| 1 | **晚间楼宇 IPv4 出口（CGNAT）大面积故障** | 10-19 约 22:37：110 条 IPv4 TCP 流只有 31% 收到 SYN-ACK，期间 ping 外网仍通。10-20 约 22:20–23:00：ping 楼宇网关 0% 丢包，ping 223.5.5.5 100% 丢包，IPv4 新建连接 5/20。两次 IPv6 都正常 | 已上线 WARP 自动切换：IPv4 故障时 LAN 的 IPv4 改走 Cloudflare WARP（隧道经 IPv6），恢复后自动切回；IPv6 始终直连 | [方案与结果](plans/WARP_IPV4_FAILOVER_PLAN_20261020.md)、`tools/warp-failover/` |

## 规律

- 坏的多是 **IPv4**，尤其是 IPv4 TCP；IPv6 基本一直正常。
- 问题集中在 **晚上 22 点前后**。
- **ping 正常不代表能用**：第 1、3、4 项发生时 ping 都可能是通的，所以探测要用 TCP。

## 下次排查先看

1. `logread | grep warp-failover`：是否已切到 WARP。
2. 分别测 IPv4 和 IPv6 的 TCP 新建连接（例如 `curl -4` / `curl -6`），不要只看 ping。
3. 路由器 CPU 和到楼宇网关的延迟；两者都正常，基本可以判定是上游问题。
