# I0：部署身份接收与源码导向验证

## 首选输入

按优先级提供现有路由器实际使用过的原始文件：

1. 最终安装使用的 OpenWrt `sysupgrade` 镜像；
2. 初次迁移使用的 initramfs/factory 镜像；
3. 同次构建的 manifest、checksums、profiles、buildinfo 和 feeds 信息；
4. 镜像下载地址、下载日期，以及操作者记得的设备型号和版本。

如果原始安装文件已经丢失，先从设备的只读身份信息确定精确版本，再取得相同的官方
镜像。不要为了本阶段读取或写入 NAND。

## 私有材料边界

不要把下列内容放入本仓库：

- 原始镜像及其解包结果；
- NAND/MTD/UBI dump；
- `sysupgrade` 配置备份；
- Wi-Fi、PPPoE、SSH 或管理凭据；
- MAC、序列号、校准数据和设备专属密钥。

这些文件应存放在仓库之外的本机私有目录。仓库只记录脱敏后的文件名、来源、长度、
SHA-256、工具版本和分析结论。

## I0 分析顺序

1. 不修改输入文件，计算长度和加密哈希。
2. 识别设备、profile、版本、镜像 hash 和 stock/`ubootmod` 等布局变体。
3. 锁定匹配的 OpenWrt tag/commit、feeds、DTS、镜像 recipe、组件 revision、patch 和构建配置。
4. 从匹配源码导出预期镜像结构、软件物料、接口、调用者和失败路径。
5. 按源码检查表只读验证实际镜像，并登记 package、配置、生成物和二进制差异。
6. 还原 init、procd、ubus、rpcd、UCI、netifd、firewall、无线和 DHCP/DNS 的关系。
7. 对每个候选重写点记录现有接口、调用者、失败影响和兼容约束。
8. 形成“保留/接入/重写/延后/禁止”的替换边界报告。
9. 只有源码和部署验证无法回答的问题，才进入经批准的脱敏只读运行态采集。

## I0 退出条件

- 镜像身份和来源可以复核；
- 软件物料、启动链、服务链和配置链已经成图；
- 每项 Rust 重写候选都有实体证据和明确兼容边界；
- 没有因源码存在某条路径或镜像包含某个文件，就推断尚未观察到的运行行为；
- 没有接触物理机持久状态。
