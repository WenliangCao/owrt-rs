# v0.2.3：优化 fw4 与 netifd · OpenWrt 25.12.5

本版优化 fw4 和 netifd，继续提供 10 个 Rust 组件。

- fw4：reload 时，只有新生成的有效规则和当前已加载规则能够确认一致，才跳过下发；规则变化、有用户 include 脚本或不能确认等价时正常重载。跳过下发会保留计数器与 flowtable，原版 firewall4 每次 reload 都重新下发。首次 start/restart 不读取实时规则做比较，首个后续 reload 建立比较记录。
- netifd：续租时按 C 的 keep 条件跳过未变化地址和路由的内核写入；地址寿命、设备或属性改变及失败重试仍正常处理。DHCP 脚本未改。

v0.2.2→本版的相同续租 CPU 中位数为 **571.692→415.154 µs（降低 27.4%）**，五对均改善并超过校准噪声。最终 fw4 的 start 墙钟为 **25.509→26.119 ms**，未超过本轮噪声；变化 reload CPU 为 **24.013→38.588 ms**，增加约 14.58 ms，保留为可靠规则比较所需快照的代价，已明确接受。前一候选“不变 reload”变快的数据不冒充最终版实测。详见[首轮比较](https://github.com/WenliangCao/owrt-control-plane-rs/blob/main/docs/reviews/V023_DEVICE_AB_20261017.md)、[最终限定复测](https://github.com/WenliangCao/owrt-control-plane-rs/blob/main/docs/reviews/V023_FW4_FOLLOWUP_20261017.md)和[fw4 行为差异](https://github.com/WenliangCao/owrt-control-plane-rs/blob/main/docs/reviews/FW4_RELOAD_V023_20261017.md)。

已完成保配置刷写与客户端健康验收。随后 300 秒观察中 WAN6 出现 4 种地址集合，60 个采样点的防火墙规则和 flowtable handles 均保持同一组，未观察到重建；实际规则变化的生效由隔离测试验证。客户端 TCP DNS 和双栈 HTTPS 通过，既有 UDP DNS 诊断限制仍保留。详见[部署记录](https://github.com/WenliangCao/owrt-control-plane-rs/blob/main/docs/reviews/DEPLOYMENT_V0_2_3_20261017.md)。
