# v0.3.3：Rust 安全与可靠性整理 · OpenWrt 25.12.6

**正式版（Latest），仅适用于原厂 bootloader、AN8855 交换芯片版本的小米 AX3000T；不适用于 MT7531 或 ubootmod。**

本版将固件基础从 OpenWrt **25.12.5 更新至 25.12.6**，并依据微软官方
[Pragmatic Rust Guidelines](https://microsoft.github.io/rust-guidelines/agents/all.txt)
完成 Rust 代码审查和必要修复，将其纳入后续开发与维护规范。

- **OpenWrt 兼容**：跟进 rpcd、uhttpd 的接口与安全修复，补齐 DHCP 客户端脚本合同验证，更新版本化构建输入及 AN8855 FIT 校验。
- **权限与会话**：加强 rpcd 文件和符号链接的权限检查；会话暂存目录使用独立随机标识，避免将会话凭证暴露在路径中。
- **HTTP 与 TLS**：收紧请求头、分块传输和鉴权解析，更新 rustls/webpki 安全补丁，完善分片请求及 HTTPS 回归测试。
- **输入与错误处理**：修复 DNS 压缩名称、协议长度、整数边界、无线 JSON 转义及 Unicode 诊断中的问题；补全错误来源，脱敏敏感调试输出。
- **平台安全边界**：dnsmasq、fw4、procd、reload-config、rpcd、ubusd 的业务代码保持 `forbid(unsafe_code)`；信号、进程创建、环境变量和 watchdog 交接由平台层封装，并检查操作前提。
- **测试与构建**：修复未真正验证目标行为的测试，增加进程隔离、故障恢复和差分回归；构建门禁覆盖 Clippy、feature 组合、examples、fuzz 与打包入口。

两轮同提交构建的固件、5 个 APK、11 个内嵌 ELF 和最终 manifest 逐字节一致；组件回归、DNS 的44类／67项资格，以及完整镜像的离线启动、包归属、升级交接和恢复门禁均已通过。附属构建诊断的差异保留在复现报告中。

同一公开镜像已保留配置刷入真机。首次 20 分钟观察为 **60/61**，出现一次原因未明的
客户端 DNS 查询超时；继续观察后，取得跨越 **1200.256 秒的连续 61/61** 健康采样通过。
全部 82 次采样为 81 次通过、1 次失败，原始失败记录保留。检查覆盖 DHCP、双频无线状态、
客户端 TCP DNS A/AAAA 与双栈 HTTPS、LuCI、服务及 watchdog，临时回退守卫已清理。
本轮未追加物理断电复验或长期稳定性测试，详见
[部署记录](https://github.com/WenliangCao/owrt-rs/blob/main/docs/reviews/V033_DEPLOY_20261023.md)。
极低文件描述符条件下 helper 的既有失败保留，离线对照未发现该项新增退化。
